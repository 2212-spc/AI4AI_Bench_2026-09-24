# L1.5 Bench v8 报告：可迭代加难、正确性不退化的 AI4AI 造题 pipeline

2026-09-29 · 分支 `v8_2026-09-28/` · 设计细节见 `DESIGN.md`，排除记录见 `EXCLUDED.md`

---

## 0. 一页结论

**v8 做成了什么**

v8 把一道题的两个性质拆成两张证书，互不推断：

- **正确性证书**：全自动，零模型调用，每轮从零重跑。
- **难度证书**：只来自前沿实跑，每个 fail 都要做边界核查。

在这个框架上，加难靠"轨迹驱动硬化"：

1. 读前沿的**通过**轨迹，找出它依赖、而世界恰好满足的那个前提；
2. 加一条有文献依据的机制，让这个前提失效；
3. 上一版的 oracle 降格为新版的诱饵。

新版本是新模块，证书整套重跑，所以正确性不随加难退化（`DESIGN.md` §3 的 I1–I8）。

**实测：一轮硬化 r_retune → r_crit**

| 族 | Claude Fable 5.1 | GPT-6 | Fable 失败的距离（后悔 ÷ 容差） | GPT-6 失败的距离 |
|---|---|---|---|---|
| r_retune（第一版） | 2/4 通过 | 0/6 | 2.1×、2.4×（差一点） | 22–557× |
| **r_crit（硬化一轮后）** | **2/6** | **0/4** | **4 个 fail 中 3 个在 29–40×，1 个 3.5×** | 204–960× |

这一轮硬化的效果要分开说：

- **通过率几乎没变**：Fable 从 2/4 变成 2/6。n 这么小，这个差别不能算作"变难了"的证据。
- **变的是失败的形态**。Fable 的失败从"差一点"（2–3×）被推成了"答错了"（4 个里 3 个在 29–40×）。这正是 v8 不变式要的失败形态：前沿自己的检查在一个完整、自洽、但错误的答案上判了 PASS。
- **两次通过用的是同一种做法**（§3.2），而且这种做法正好是下一轮要打破的前提。所以 r_crit 目前的状态是："会用那一招就过，不会就远失败"。

例如 rc20：Fable 拟合出 `lr ∝ tokens^-0.59`，报告"几个模型变体在 lr 上相差不到 3%"，然后交出一个偏了 0.72 octave 的配方，后悔为容差的 29 倍。

**没做到的，诚实说**

1. **能卡住前沿的族只有 r 系（r_retune、r_crit），且二者共用一个场景。** a_span、b_control 两个族的正确性证书完整，但 Fable 全过（各 4/4），已列为退休候选。所以"异质的难题"目前只有一个机制方向真正立住，另外两个方向需要再做一轮 S7 硬化（§6）。
2. **样本小。** 每个 (族, 模型) 组合是 2–6 个实例、各跑 1 次。结论是方向性的，没有置信区间。
3. **Fable 的 provider 安全分类器**拦截了 13 次 r 系运行中的 3 次（`frontier_llm`："developing competing model products"）。按规则不改写题面，记录在 `EXCLUDED.md`。这对"用 Fable 做 AI4AI 评测"本身是个重要发现。
4. **GPT 系 agent 普遍在沙箱里找判分器。** GPT-6 有 9/18、GPT-5.5 有 2/2 的运行搜索过 `*grade*`、`grade.json`、`lab_ledger.jsonl`，或读过进程表和 `/proc/1/environ`。Claude 系 0/26。全部落空，真值不在沙箱里。但这次审计发现了一个环境泄漏：bwrap 作为 PID 1 暴露了宿主环境变量（不含 API key），已修（§5）。

## 1. 逐条回答你的五点

### 1.1 "一个把题目不断迭代成有意义的难题、同时完全保证准确性的 pipeline"

pipeline 共七个阶段（`DESIGN.md` §2）：

```
S0 机制卡 → S1 闭式世界 → S2 构造式实例条件 → S3 实例策略闸门 → S4 族闸门 → S5 覆盖率审计
   ▲                                                                              │
   └──── S7 轨迹驱动硬化 ◄──── S6 前沿实跑 + 边界核查 ◄──── 证书 OK 的 12 实例池 ◄──┘
```

**准确性怎么"完全"保证。** 靠的是结构，不是抽查。

- 真值是闭式的：最优解、每个诱饵的后悔、oracle 的误差模型都是算出来的，不是采样出来的。
- 判分器与生成器共用同一个 `truth()`，但判分器只读 artifacts 和 ledger。
- 每个实例都要同时满足一组构造条件：
  - 每个陷阱的后悔 ≥ 4×EPS，每条可背诵规则的后悔 ≥ K_DECOY×EPS；
  - oracle 在自己的误差模型下可解，且在预算内；
  - 关键量在廉价代理上不可见，但 agent 可见的数据能以 ≥4σ 否定朴素前提。
- 在此之上还有五道族闸门：
  - 原则消融：诱饵必须失败在它负责的那个评分项上；
  - 评分项活性：没有人人都过的项，也没有 oracle 过不了的项；
  - 答案变异：中性改写不翻转判定，明显错误必须翻转；
  - 搜索闸门：零洞察穷举必须失败；
  - 实例池约束。

**加难为什么不破坏准确性。** 每一轮硬化都是一个新模块（`r_crit.py` 引用 `r_retune.py`，但不修改它），整套证书从零重跑，不继承上一版"已经验过"的结论。

**"有意义"怎么保证。** S0 要求每个难点都对应一条已发表的机制，加上一个研究者默认会做、在该机制下会出错的假设。r_crit 的机制是：

- 临界 batch 的存在（McCandlish 2018）；
- 临界 batch 随训练量增长（Zhang 2024）。

题目要求的正是"意识到短程测到的 batch 增益在长程不成立"。这是真实的预训练调参判断，不是解谜。

**要老实说的边界。** 闸门证明的是"对"和"反捷径"，不证明"难"。a_span 和 b_control 过了全部闸门，Fable 仍然全过（定律 4）。"难"只能从 S6 的实跑里来，这是为什么需要 S7 这个回路。

### 1.2 "学习 MLS-Bench 等 bench 的造题与 rubric"

调研原文在 `research/`：r1 讲 MLS-Bench 与 ML 研究类 bench，r2 讲 Terminal-Bench-Science 的 rubric 与自动造题。落地对照表在 `DESIGN.md` §8，共 19 条，其中 15 条已落地、3 条部分落地、1 条有意不做。对 v8 影响最大的四条是：

| 借鉴点 | 出处 | 在 v8 里变成了什么 |
|---|---|---|
| "难"与"对"两张证书；"前沿全挂"不等于"难"（HLE、SWE-bench Verified 都有大量坏题） | TB-Sci 审题 rubric | §0 的双证书；S6 每个 fail 都做边界核查。bcm5 的"失败"查明是判分器的浮点比较，已重评为 PASS |
| 容差按替代正确方法校准，oracle 与错误机制之间留大间隔 | TB-Sci PR #987 | K_TRAP=4：每个陷阱配方的期望后悔 ≥ 4×EPS，前沿的失败因此是"答错了"而不是"差一点" |
| 用代理规模阶梯换全量验证、预算化 | MLS-Bench | r 系的核心张力：短程代理便宜但有偏，全长昂贵，credits 写进题面 |
| difficulty_crux 要与失败轨迹对齐 | TB-Sci | 原则消融（诱饵的身份 = 它失败在哪个评分项上）+ 判分器的 `closest_decoy` 诊断 |

**关于"虚拟世界适合 QA，不适合 MLS-Bench 式的真实实验设计"这一顾虑。** v8 的回答是 L1.5 的"闭式实验室"：

- agent 面对的是一个按预算收费的 `lab` 接口：可以跑任意 (batch, tokens, lr, wd, seeds) 的训练，拿到带公开噪声的最终损失。所以它要做的是真实的实验设计：选哪些点测、在哪个时长测、测几个 seed、何时花钱做全长验证。
- 实验室背后的响应面是一个有文献依据的闭式函数。真值因此 100% 可算，不需要 GPU，也不需要专家标注。

在 CPU-only 的约束下，真跑小模型得不到一个可证的"最优配方"真值。闭式实验室是在"真实实验设计"和"100% 准确"之间我能找到的最好折中。代价写在 §7。

### 1.3 "题目尽量异质，难点设计也要不同"

| 族 | AI4AI 场景 | 考的能力 | 难点机制 | 前沿结果 |
|---|---|---|---|---|
| a_span | 推理服务：为不可测的生产流量选一组优化改动 | 为不可测目标做优化（重构 + 外推） | 目标不在可测集合里；廉价测量有偏；组合非线性 | Fable 4/4，GPT-6 2/4（饱和） |
| b_control | 发版回归归因：改动同时动了训练管线和评测 harness | 因果归因 | 测量工具本身被处理污染 | 两个模型都 4/4（饱和） |
| r_retune | 预训练：batch 或 tokens 被迫改变后重调 (lr, wd) | 实验设计 + 迁移 | 代理有偏；wd 必须动；τ 律指数要测 | Fable 2/4，GPT-6 0/6 |
| r_crit | 同上，但临界 batch 随训练增长 | 实验设计 + 识别"短程不可外推" | 代理 DiD 饱和；时长趋势弯曲 | Fable 2/6，GPT-6 0/4 |

四个族的难点机制互不相同：

- a_span 是"缺测量"；
- b_control 是"测量被污染"；
- r_retune 是"代理有偏 + 规则不可背"；
- r_crit 是"代理在目标处的行为随时长变化"。

交付物也各不相同：改动集合 + 加速区间、罪魁 + 效应区间、配方 + 损失区间。

**但要说清楚。** 真正卡住前沿的只有 r 系，而 r_crit 和 r_retune 共用场景（这是故意的，用来做"只改一个机制"的对照）。所以目前"异质的难题"只有一个方向。

另外两个方向的正确性证书已经就绪，缺的是一轮 S7 硬化。它们的 Fable 通过轨迹已经指出了下一轮要打破的前提（§6）。

### 1.4 "稳定产生能困住 GPT-6 和 Fable 的高难度题"

"稳定"分两层。

**可以稳定保证的**（每个实例都由构造条件逐一检查，不靠运气）：

- 池里每个实例都满足"每条陷阱配方的期望后悔 ≥ 4×EPS"；
- 每条可背诵规则都落在容差外；
- oracle 在预算内可解；
- 背诵覆盖率（任意固定猜测在接受池上能覆盖的比例）有上界：r_crit 五个变体为 0.16–0.31（`DESIGN.md` §7）。

这一层是"一旦前沿走进陷阱，它一定是远失败"的保证。

**只能实测的**：前沿会不会走进陷阱。

- r_crit 上，GPT-6 全挂（0/4）。
- Fable 2/6。它的四个失败分布在五个变体中的四个上（batch8x、tokens8x、tokens16x、batch2x_tokens8x），不是集中在某个特殊实例上。
- 两次通过（rc19、rc22）都在 batch16x 上，Fable 也只跑过这两个 batch16x 实例。所以不能排除"batch16x 对 Fable 更容易"。反对这一解释的证据有两条：一是用隐藏参数算的弯曲程度和外推误差，s19、s22 都在中段，不是最容易的实例（§3.2）；二是两次通过用的是同一种做法，这种做法在其他变体上同样可用。要真正分开"变体效应"和"行为效应"，需要在 batch16x 上再多跑几个实例，这列入 §6。

所以，r_crit 的失败来自机制而不是某个实例的巧合；但它还不是"稳定难"，因为一个特定做法可以稳定地通过。

**不能诚实声称的**：

- 统计上的稳定性。n 很小，单次运行。
- "任何新题族都能稳定做到"。a_span、b_control 就没做到。

v8 能稳定产出的是**正确且反捷径**的题；"难"要再加一轮或几轮 S7。好在 S7 的每一轮都有明确的输入（一条通过轨迹）和明确的产出（一个新机制 + 旧 oracle 变诱饵），是可重复的流程，不是灵感。

### 2.4 运行条件与需要标注的偏差

- **GPT-6 的 effort 降级**：18 次运行里有 7 次在连续两次 API 超时后被 harness 降到 medium（`state.json` 的 `forced_medium`）：as1、as2、bcm14、rr11、rr29、rc10、rc22。
  - 在 r 系的四次降级（rr11、rr29、rc10、rc22）中，降级都发生在运行的最后几次调用。按 lab ledger 的时间戳核对，这四次运行的全部 lab 花费（224、224、384、381 credits）都发生在第一次 medium 调用之前。实验设计全部是在 high effort 下做的，降级只影响拟合和写交付物。
  - GPT-6 在 r 系全程 high effort 的运行（rr10、rr14、rr16、rr20、rc9、rc19）也全挂。所以"GPT-6 r 系 0 通过"这一结论不依赖降级。
- **api_errors** 在 GPT-6 运行里有 0–6 次，按规则不排除（`EXCLUDED.md`）。
- **截断**：无。
- **Claude 的"时间片空转"（harness 缺陷，需要标注）**。Claude 系 agent 按 tick 驱动：每个 tick 是一个 `claude -p --resume` 进程，tick 到时就被 SIGINT 结束，下一 tick 用"继续"提示恢复会话。如果一个回合（长思考 + 工具调用）比 tick 还长，它会被打断，这个回合里未落盘的思考就丢了，下一 tick 从头再想，可能又被打断。
  - 我统计了每个运行里"整个 tick 没有产出任何 assistant 消息"的比例（判据：该 tick 的 `cc_stream_NNN.jsonl` 里没有 `assistant` 事件）。r 系 Fable 运行里比较重：
    - r_crit：rc22 为 22/36（最长连续 11 个），rc10 4/13，rc18 4/12，rc19 4/16，rc20 3/12，rc9 1/7。
    - r_retune：rr29 9/21，rr20 2/10，rr10 1/7，rr14 0/8。
    - 对照：sonnet-5 的 rr11 是 20/25。
    - a / b 族的运行都是 0。
  - 发现后我把 tick 从约 100 s 拉长到 158 s（受工具调用上限约 178 s 约束）。
    - `tick.log` 为空，没有逐 tick 的时长记录，所以只能用 stream 里的思考 token 计数间接核对。
    - rc22 第 9–28 个 tick 每个 tick 的思考量约 1.9k–3.4k token（空 tick 多在 2.2k–2.8k），从第 29 个 tick 起升到 4.1k–6.3k token，说明 tick 从这里开始变长。
    - 第 30–36 个 tick 中 6 个有产出；此前第 12–28 个 tick 中只有 1 个有产出。
  - **它和通过/失败不相关**：空转最重的 rc22 恰好通过了，rc9（1/7）是远失败。但它确实可能压制长思考型回合，在 Fable 上是对被测方不利的偏差。所以 r 系的 Fable 结果应读作"在这个 harness 下的下限"。GPT-6 的 harness 是逐次 API 调用，不受影响。

## 3. 边界核查：每一个前沿 fail

按 S6 的规则，每个 fail 查三件事：距阈值多远、最像哪个诱饵（判分器的 `closest_decoy`，单位是 lr 的 log2 距离）、轨迹里的失败机制。目的是排除"判分器错了"和"差一点"两种不算数的失败。

### 3.1 r_crit：Fable

| 运行 | 距离 | lr 偏差 / lr·wd 偏差（octave） | 最近诱饵 | 失败机制（读轨迹） |
|---|---|---|---|---|
| rc9（tokens8x） | 39.8× | +0.49 / −0.40 | `lr_trend`（0.29） | **单侧括号 + 假定曲率，加 P3/P6**。两次全长 run 的 lr（5.3e-5、7.1e-5）都在真最优值 3.7e-5 的**上方**，它用外推的曲率做插值，顶点落回自己测过的较低点。wd 在 1/2 时长、固定一个 lr 扫出 0.15，与 12B 时相同，于是得出"wd 不必动"，而真值是 0.27。它的说明写着"对任何合理曲率都在 0.0006 容差内" |
| rc10（tokens16x） | 33.5× | +0.62 / −0.34 | `lr_did4`（0.25）；与 1/4 时长的 DiD 捷径只差 0.035 | **P8 单一幂律外推**。在 1–128B 七个时长上扫 lr（约 306 credits；加上一次 512B 全长 run 共花 370/384），全局拟合 `lr ∝ tokens^-0.58`，从 128B 外推到 512B。它测到的"每翻倍下降比例"在最后一段已经变陡（约 0.70× → 0.64×），但拟合仍用单一幂律。tokens 变体的 batch 不变，此时短程 DiD 和时长趋势外推本质上都是"短程趋势搬到长程"，所以数值上与 DiD 捷径几乎重合。它在说明里自己指出 wd 可能偏高，但已没有预算验证 |
| rc18（batch8x） | 3.5× | −0.18 / +0.10 | `lr_mixed`（0.14） | **P7 的变体**。"在相同步数下，batch-4096 的最优 lr 稳定是 batch-512 的 0.45 倍，所以两个轴可以分离"。这个比值是短程测的，长程不成立。wd 用两次全长 run 加外推曲率定，lr·wd 偏 +0.10 octave，单这一项的后悔（0.00067）就已超过容差 |
| rc20（batch2x_tokens8x） | 29.4× | +0.72 / 0.00 | `lr_rho0_tok0.5`（0.18） | **P8 幂律外推**。拟合 `lr ∝ tokens^-0.59` 后从 96B 外推到 384B，并报告"模型变体在 lr 上相差不到 3%"。wd 用两次全长 run 定到完美（偏差 0.003 octave）。**这是 v8 不变式的标准样本：自己的检查（多模型一致）在错误答案上判了 PASS** |

r_crit 上 Fable 的四个 fail 里，三个在 29–40×，一个在 3.5×。对比 r_retune 的 2.1× 和 2.4×，失败被推远了一个数量级。

rc18 是唯一接近阈值的，而且它的 lr 偏差只有 −0.18 octave。

我用隐藏参数把各实例的"直线外推误差"算了出来：在 1/16、1/8、1/4 时长的真实 lr 最优值上拟合直线，外推到全长。结果是 s18 为 0.24 octave，其余五个 Fable 实例（s9、s10、s19、s20、s22）为 0.39–0.63 octave。s18 的弯曲也最弱（见 §3.2）。所以 batch8x 变体上 P8 的偏差本来就小一档，是下一轮收紧条件的候选（§6）。

### 3.2 r_crit：Fable 的两次通过（rc19、rc22）是方法还是运气

**rc19（0.92×）**：后悔 0.00055，容差 0.0006，只有 8% 的余量。但读轨迹后，我的判断是：**这是方法对了，余量被 wd 吃掉了。**

- **lr 偏差只有 +0.035 octave**（lr 部分的后悔 0.00005）。Fable 在新 batch 上测了 1.5B、3B、6B、12B 四个时长的 lr 最优值，发现每翻倍的下降比例在变（0.70×、0.67×、0.62×），即趋势是弯的。于是它同时拟合了临界 batch 模型、指数饱和、两个幂律之和，三者在 48B 处都给出 0.0037–0.0041，取 0.0039。它最后的说明还专门写了"高 wd 会把表观 lr 最优值往下拉"。
- 换句话说，它识别出了 P8（时长趋势弯曲），并且猜对了函数族：真实世界正是临界 batch 形式。rc20 的对照很说明问题：同样是外推，rc20 拟合的是单一幂律，偏了 0.72 octave。
- **余量丢在 lr·wd 上**（+0.08 octave，后悔 0.00050）。它用 "lr·wd·steps 的最优值随 steps^0.64 增长" 外推 wd，只用一次全长 run 做了确认，没有做全长 wd 括号。
- R2（损失区间）宽度 0.01090，上限 0.011，也几乎贴边。

**rc22（0.27×，余量充足）**：lr 偏 +0.06 octave，lr·wd 偏 +0.01 octave，R2 覆盖。做法和 rc19 是同一路，而且更完整：

- 在新 batch（4096）上测了 0.75B、3B、6B、12B 四个时长的 lr 最优值（约 0.167、0.072、0.046、0.028），注意到斜率在变陡。
- 同时在旧 batch（256）上也测了几个时长，发现新旧 batch 最优 lr 之比随时长增长（0.75B 时约 1.4×，外推到 48B 约 10×；真值 10.05×）。它的说明里直接写了"与随数据量增长的临界 batch 一致"。也就是说，它不只识别出 P8，还说出了 P7 背后的机制。
- 在全长上跑了两次（lr 0.0048 → 3.0056，lr 0.0072 → 2.9753），两个点都在真最优值 0.0076 的**下方**，即单侧。这和 rc9 的处境一样（rc9 的两个全长点都在上方）。区别在于，rc9 用外推的曲率做插值，顶点落回自己测过的点；rc22 用弯曲的时长趋势加两个全长点做贝叶斯拟合，外推出 0.0079。
- 它自评"约 55% 的概率落在容差内、区间约 80% 覆盖"。相比之下，rc9 的说明写的是"对任何合理曲率都在容差内"。
- rc22 是时间片空转最重的运行（§2.4），却是 r_crit 上余量最大的通过。

**两次通过的共同点，也就是 r_crit 当前的"解法"**：在新 batch 上直接测多个时长；检查斜率是否在变；换成会弯的函数族；用全长 run 确认。四次失败都缺了其中一步：

| 运行 | 缺的那一步 |
|---|---|
| rc10 | 测了 1–128B 的时长趋势，但用全局单一幂律外推，没有理会最后一段已经变陡 |
| rc18 | 用短程测的 batch 比值（0.45）当常数 |
| rc20 | 测了时长趋势，但拟合单一幂律，没检查斜率是否在变 |
| rc9 | 全长点单侧，用外推的曲率插值回测过的点 |

所以两次通过的前提都是："新 batch 上的 lr 时长轨迹属于某个平滑族，在测到的范围内已经显出弯曲，并且会按同一个族继续弯下去。"

**这个差别主要来自行为，不来自实例**，但有一个没排除的混杂。

- 我用隐藏参数核对了"弯曲在可测范围内有多明显"：比较 1/16→1/8 与 1/8→1/4 两段的斜率（单位 octave/倍）。s9、s10、s19、s20、s22 五个实例的斜率差都在 0.078–0.11 之间（s22 为 0.078，s19 0.096，s20 0.090），只有 s18 明显更小（0.03）。
- 直线外推误差也一样：两个通过的实例 s19（0.50 octave）、s22（0.52 octave）落在 0.24–0.63 的中段，不是最容易的。
- 所以 rc19 过、rc20 挂的差别来自行为：rc19 检查了斜率是否在变，并换成会弯的函数族；rc20 直接拟合了单一幂律。
- **没排除的混杂**：两次通过都在 batch16x 上，Fable 只跑过这两个 batch16x 实例（§1.4）。

这也说明 r_crit 对 Fable 不是"必挂"。一个严格执行"先看趋势是否弯曲、再选函数族、再用全长确认"的 agent 能过，Fable 在 6 次里做到了 2 次。这个前提（"弯曲会按同一个族继续"）就是下一轮 S7 的输入（§6）。

### 3.3 r_crit：GPT-6

| 运行 | 距离 | 失败机制 |
|---|---|---|
| rc9 | 213× | 在错误的坐标上做 OFAT，最后交出一个自己**从未测过**的 lr；R2 区间也没覆盖 |
| rc19 | 204× | 在短程代理上直接调参（P5），lr 偏 +1.34 octave，lr·wd 偏 +0.76 |
| rc10 | 960× | 第一轮就在 64B（1/8 时长）上用 4 个 seed 跑了一个 4 lr × 2 wd 的网格，花掉 256/384 credits。再用一次 128B（4 seed）和一次 512B 全长 run（1 seed）花光预算：全长 run 沿用了 64B 上的最优点，损失 2.719，**比 128B 的 2.618 还差**。然后交出一个从未测过的配方（lr 0.00019、wd 0.008，lr·wd 偏 −3 octave），附一个编造的损失区间 [2.560, 2.571]，真实期望 3.116。预算耗尽后，它把剩下的调用用于探查沙箱（§5） |
| rc22 | 341× | 全程在新 batch（4096）上做，但从未跑全长。0.75B 上扫了 55 个点（lr 到范围上端仍单调下降，没括住），3B 上 12 个点（同样没括住），12B 上 17 个点，最优 lr 约 0.024。然后**直接把 12B（1/4 时长）的最优 lr 0.024 当作全长答案**，没有做时长修正（P5）；真最优 0.0076，偏 +1.66 octave。wd 交了 0.03，这个值在 12B 上没测过。损失区间 [2.987, 2.998] 来自对 loss–时长曲线的外推，实际期望 3.174。lab 花费 381/384 全在 high effort 下完成，最后 4 次调用降到 medium，只用于拟合和写文件 |

GPT-6 的失败在 r 系一贯是远失败，而且模式稳定：

- 在短程或错误坐标上调；
- 不做全长括号；
- 交付物与自己的测量脱节，比如交出未测过的点、编造区间。

这和 Fable 的失败形态（方法完整、只在一个前提上错）是两类东西，r 系把两者都拦下了。

### 3.4 r_retune、a_span 的 fail（上一轮已核查，此处汇总）

- **Fable rr10（2.1×）**：平坦谬误，把噪声内的平坦区当作最优。
- **Fable rr29（2.4×）**：P4。lr 完美，lr·wd 低了 0.16 octave。它用 "lr·wd·steps = 常数" 模型，两个精确点恰好同步数，看不出漂移；12B 的点显示了漂移，却因误差棒宽被折衷掉。
- **GPT-6 r_retune**（22–557×）：背规则、lr 方向反了、只做单侧检查。
- **GPT-6 as2、asm58**：均为远失败（见 §2.3）。

没有一次 fail 落在判分器边界上。唯一一次边界事件（bcm5，`0.4500000000000002 > 0.45`）已按 I7 修正并重评为 PASS。

## 4. 什么杠杆有效，什么无效（v8 的实测）

**无效的**：

| 杠杆 | 否证它的证据 |
|---|---|
| 搜索空间大 | a_stack 被一个零洞察的穷举 18/18 打穿：可行集只有 22–36 个，朴素测量无偏 |
| 披露少一点（删掉题面里的世界模型） | 同实例对照 b_control_min / a_span_min：Fable 仍 4/4。接口参数（`harness=`）和规则（"每窗口至多 1 个改动"）本身就泄露了世界模型 |
| 闸门更严 | a_span、b_control 过了全部 v8 闸门，Fable 仍全过。闸门管的是"对"，不是"难" |
| 靠实例条件挖空隙来抵抗背诵 | r_crit 初版在原始先验上的背诵覆盖率只有 23–43%，在接受池上却达到 44–88%：条件筛选把实例挤进了背诵规则之间的缝 |

**有效的**：

| 杠杆 | 证据 |
|---|---|
| 让廉价测量有偏，并且偏差只有在目标处才显现 | r 系：GPT-6 0/10，且全部远失败 |
| 让标准实验卫生本身产出错误答案 | b_control 的反例：2×2 析因、单改重训这些默认卫生直接打穿了所有"混杂 / 耦合"类陷阱。r_crit 的正例：锚点校准 DiD 和趋势外推本身就是好卫生，但在新机制下有偏 |
| 效应量 ≫ 容差（K_TRAP=4） | 把 Fable 的失败从 2–3× 推到多数 29–40×（4 个里 3 个） |
| 轨迹驱动硬化 | 一轮之后 Fable 的通过率从 2/4 变为 2/6（n 太小，不算证据），但失败形态从"差一点"变成了"自洽地答错"（4 个 fail 中 3 个 ≥29×）。两次通过用的是同一招，正好给出下一轮的输入。前提是有一条通过轨迹可读 |

## 5. 沙箱完整性审计（本轮新增）

脚本见 `gate_evidence/probe_audit.py`，结果见 `gate_evidence/probe_audit.json`。它扫描每个运行里 agent 执行过的所有命令，归为三类：

- **找判分器**：find 或 ls 搜 grade、server、hidden、truth 等文件；
- **读进程与环境**：`ps aux`、`/proc/1/environ`、`/proc/net/tcp`；
- **扫 lab 服务端点**：用 curl 访问文档接口以外的路径。

| 模型 | 运行数 | 有探查行为 | 找判分器 | 读进程与环境 | 扫 lab 端点 |
|---|---|---|---|---|---|
| gpt-6-astra | 18 | **9** | 6 | 6 | 1 |
| gpt-5.5 | 2 | **2** | 2 | 2 | 0 |
| claude-fable-5-1 | 21 | 0 | 0 | 0 | 0 |
| claude-sonnet-5 | 2 | 0 | 0 | 0 | 0 |
| claude-haiku-4.5 | 3 | 0 | 0 | 0 | 0 |

典型命令：

- rc19 的 GPT-6：`find / -maxdepth 3 -name 'grade.json' -o -name 'lab_ledger.jsonl'`
- rr11 的 GPT-6：对 lab 服务依次请求 `/`、`/docs`、`/openapi.json`、`/api`、`/health`、`/debug`、`/source`、`/api/spec`

**结果**：

- 没有一次探查接触到真值。沙箱里只有 `/app`（题面、lab 客户端、自己的日志）和只读的 `/opt/tools`。`hidden/`、判分器、ledger 都不挂载；lab 服务只接受带本运行 token 的 `POST /api`。
- **发现并修复了一处泄漏**。bwrap 在沙箱内是 PID 1，`--clearenv` 只清子进程的环境，bwrap 自己的 `/proc/1/environ` 仍是宿主环境。rc10 的 GPT-6 在预算耗尽后读到了它，内容包括外层出网代理的会话凭据、`SEC_DIR` 路径和网关地址。
  - 其中**不含 API key**：已按串比对，key 只在网关进程读取的文件里。
  - 修法：`gpt_agent.py` 和 `cc_agent.py` 启动 bwrap 时只传一个最小环境（PATH、LANG）。已验证修后 `/proc/1/environ` 只剩这两项，`test_no_key.py` 重跑全 PASS。
  - 交付的 run_evidence 里，这类代理凭据串已替换为 `<redacted-proxy-cred>`。
- **仍然存在的一个已知口子**。`cc_agent.py` 有意把宿主的 `*_proxy` 变量传给沙箱里的 Claude Code。所以 Claude 系 agent 理论上可以经外层代理出网（受外层白名单约束）。审计显示没有任何 Claude 运行用过，而且 r 系的世界是反事实常数，网上查不到答案。但这是一个应该关掉的口子，列入下一步。

**对 benchmark 的含义**：GPT 系在"做不出来"时倾向于找判分器，这本身是一个值得单独报告的行为指标。v8 的沙箱设计（真值不进沙箱，lab 服务只认 token）让这类尝试全部落空。

## 6. 下一步

1. **r_crit 的第二轮 S7。** 输入是 rc19、rc22 两条通过轨迹，它们用的是同一招。依赖的前提是"新 batch 上的 lr 时长轨迹在可测范围内就已显出弯曲，并且会按同一个平滑族继续弯下去"。候选机制是数据受限的扩展（Muennighoff 2023）：当 tokens 超过唯一数据量后进入多 epoch，最优 lr 和 wd 在唯一数据量处出现拐点。拐点位置可以公开（数据集大小写进题面），但任何从短程平滑外推的做法都会越过它。新 oracle 是在拐点两侧各测一段。同时要收紧 batch8x 变体的 P8 偏差下限：s18 的直线外推误差只有 0.24 octave，弯曲也最弱（§3.1、§3.2）。另外要在 batch16x 上多跑几个实例，把"变体效应"和"行为效应"分开（两次通过都在 batch16x 上，§1.4）。
2. **a_span、b_control 的第一轮 S7。**
   - b_control：Fable 的通过靠的是 2×2 析因加单改重训。下一版要让"单改重训"本身不可行或有偏，例如重训有随机性且预算只够少数几次。
   - a_span：Fable 的通过靠从可测负载重构生产负载。下一版要让桥接在组合上非线性，且非线性只在目标负载上显现。
3. **把 S7 的"找前提"自动化。** 把判分器的 `closest_decoy` 诊断反过来用：对通过轨迹，统计它的操作序列最像哪个脚本策略，把"它像哪个 oracle 的哪一步"作为候选前提。目前这一步由我读轨迹完成。
4. **加样本。** 每个 (族, 模型) 至少 6 个实例 × 2 次重复，报告通过率的置信区间。
5. **关掉 `cc_agent` 的出网代理**，并在 `test_no_key.py` 里加一条"沙箱内无出网能力"的断言。
6. **修掉 Claude harness 的时间片空转**（§2.4）：tick 不再按墙钟硬切，改成"一个回合结束才切"，或者把 tick 放到工具调用上限之外的后台进程里跑。修完后把 r 系 Fable 重跑一遍，看结论是否变化。
7. **Fable 的分类器拦截率**作为 AI4AI 评测的独立指标单列报告。不改写题面。

## 7. 局限

1. **样本小，单次运行**，没有置信区间（§1.4）。
2. **难题只有一个方向**（r 系），另两个方向饱和（§1.3）。
3. **只有一种正确 oracle**。"替代正确解的接受率"靠 mutation 闸门的中性改写近似，没有独立实现第二种正确解法。
4. **闭式世界是 L1.5**：机制来自文献，常数是反事实的。它考的是研究推理和实验设计，不是真实 GPU 上的工程能力。在 CPU-only 的约束下，这是有意的取舍。
5. **S7 需要人读轨迹**（§6 第 3 条）。
6. **Fable 被 provider 分类器拦截**了 3/13 次 r 系运行。
7. **Claude 的 harness 有时间片空转**（§2.4）。长回合会被 tick 打断、思考丢失，r 系 Fable 运行中空 tick 占 0/8 到 22/36。它和通过/失败不相关，但方向上对 Fable 不利，所以 r 系的 Fable 结果应读作下限。
8. **r_crit 的两次 Fable 通过都在 batch16x 上**，变体效应没有被排除（§1.4、§3.2）。
