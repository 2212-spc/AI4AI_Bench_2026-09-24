### 2.6 相关度与难度机制分布

**相关度（23 个题族）**

| 档 | 数量 | 题族 |
|---|---|---|
| CORE | 12 | v7 全部 6 个；r_retune、r_crit；scaleup；sched_law（有效性存疑）、dedup_cv、temporal_leak（偏 MLOps） |
| ADJACENT | 9 | a_span、a_span_min、b_control、b_control_min、judge_audit、serve_ab、ab_interference、unit_pipeline、d_shift_repair（偏 OFF） |
| ADJACENT/OFF | 2 | cache_policy、delayed_labels |

**相关度在漂移**：v7 是 6/6 CORE，v8 是 2/6，v10 是 1/3，v11 是 3/7，而且 v11 的场景是市场 A/B、缓存、信贷、医院、零售。

**难度机制（21 个机制不同的题族）**

| 机制 | 题族 | 是否"看似合理其实错"的陷阱 |
|---|---|---|
| 廉价或短程测量有偏，一外推就错 | k2、k3、r_retune、r_crit、sched_law | 是 |
| 估计量或统计假设被违背 | k1、judge_audit、ab_interference、delayed_labels | 是 |
| 验证或特征程序本身给出虚假确认（记录不独立、时间点不对） | scaleup、dedup_cv、temporal_leak | 是 |
| 过信代理或二手信号 | k4、a_span | 是 |
| 归因之后还要联动修复 | k8、b_control、d_shift_repair | 是 |
| 聚合时的 Jensen 效应、排队 | serve_ab | 是 |
| 协变量来源不一致 | unit_pipeline | 是 |
| 在线决策的类别粒度 | cache_policy | 是（缓存领域） |
| 在线变点控制 | k6 | **否**：技能加方差 |

结论：**20/21 的难度都来自同一种手法**，即"被违背的假设 × 看似合理的捷径"。

v11 还多出一个共同特征：有 3/7 题（sched_law、ab_interference、delayed_labels）的参考解**与隐藏生成器是同一个函数族**，阈值正好卡在"这个族"和"相邻族"之间。难度因此变成"猜中作者的生成器"。

真正让前沿稳定失败的机制只有两类：
- 第一类（r_retune、r_crit）；
- 第三类里的 scaleup L2，但它有时间片混杂。

k8-c2 看上去让前沿失败，其中一半是判分噪声造成的（§3 A11）。

## 6. v11 逐题批判审查

每道题回答四个问题：
1. 题面清楚吗？
2. 阈值有依据吗？
3. 不懂考点的通用做法能不能过，证书测过没有？
4. 隐藏测试测的是不是题面说的东西？

证书数字取自各题的 `certificate.json`（创建时间见 §1）。

### 6.1 sched_law（证书 11:33；3 个 dev + 4 个隐藏世界；阈值：|pred − true| / scale 的平均 ≤ 0.10）

- **题面**：给 4 条训练曲线，预测没见过的 LR 日程的最终 loss。清楚。
- **世界**：逐模态的噪声二次模型（NQM），`v ← (1 − lr·h)² v + lr² s`；种子固定为 11–13、101–104。隐藏查询是 rewarm、cyclic4、cos_long、wsd_long、warm_cos。
- **参考解**：用非负最小二乘拟合 NQM 的线性响应基，**正好就是生成器的模型族**。误差 0.0022–0.0298（README 写 ≤ 0.034）。
- **阈值**：0.10 没有推导。**通用的 GBM 诱饵在隐藏世界上只以微弱差距挂掉**（0.11、0.118、0.126、0.151），余量 10%–50%。
- **通用做法**：三条已发表的日程律（lr_area、momentum_law、multi_power）全挂，multi_power 在隐藏世界上误差 2.3–3.1。但这是因为**世界本来就不是真实的 LLM 训练**。已发表律在这里失败是构造出来的，不能说明它们在真实世界里也不行。
- **隐藏测试测的是什么**：测的是"能不能从 4 条曲线里辨认出 NQM 这个生成器"，而不是题面暗示的"找一条更好的日程律"。
- **dev 过、只挂隐藏的诱饵**：没有。
- **本审计**：需要 scipy，没有复算。
- **结论**：CLEAN-UNVERIFIED。CORE 话题，但有效性存疑：它奖励的是"对上作者的模拟器"。

### 6.2 dedup_cv（证书 13:06；2 个 dev + 4 个隐藏；阈值：所选候选的 MSE / 17 个候选中最好的 MSE ≤ 1.20）

- **题面**：从固定菜单里选一个配置。题面宣称"records come from a real-world logging pipeline"，**这是假的**，数据是合成的（E4）。
- **世界**：每个实体被复制成若干近似拷贝，共用同一个带噪标签；测试集是新实体、无噪声目标。
- **参考解**：用最近邻距离恢复分组，再做 GroupKFold。
- **通用做法**【实测，来自 `hidden/_oracle_cache.json`，其 key 与当前文件一致】：
  - **没有任何一个固定候选能过全部 6 个 setting**。这是好的一面。
  - `gbm_lr0.03_leaf300` 只挂 hid_b（1.52），这就是 `always_smooth` 诱饵。
  - 各 setting 能过的候选数：dev_a 6、dev_b 14、hid_a 6、hid_b 4、hid_c 2、hid_d 9。
  - `rf_leaf1` 在 hid_b 上是 1.2022，只差千分之二就过线，是刀刃。
- **泄漏**：唯一 y 值数等于实体数（E3）。`groups = y` 能精确恢复分组，比参考解的最近邻聚类还准。这不一定让题目"错"，但会让考点变成一次 EDA 就能看出来的事。
- **隐藏测试测的是什么**：测的是"记录不独立时，随机 CV 会给出虚假确认"。这与 v10 scaleup L2 是**同一个考点**（E11）。
- **本审计**：需要 sklearn，没有复算。
- **结论**：DEFECT-OPEN（泄漏 + 虚假陈述 + 跨版本重复）。

### 6.3 unit_pipeline（证书 12:47；2 个 dev + 4 个隐藏；阈值：MSE 与用干净数据训练的模型之比 ≤ 1.10）

- **各站点的问题**：
  - S2：血糖用 mmol/L；
  - S3：血压两列对调，心率按每 30 s 计；
  - S4：温度用 °F，体重用 lb；
  - S5：身高用米，心率 0 表示缺失；
  - S6、S7：没见过的站点，是已见问题的重新组合；

- **参考解**：按站点批次做合理性检查和单位修复，然后丢掉站点列。比值 0.996–1.04；**hid_S5 1.04 对 1.10，余量很薄**。
- **诱饵**：
  - `robust_rowwise` 在 dev 上过，在 hid_new6/new7 上挂（3.07/3.18）。这很好，说明隐藏站点确实在考泛化。
  - **`quantile_global` 与 `drop_site` 基线的 6 个指标完全一样**（E2）。单调变换对树模型是空操作，这个诱饵什么也没检验。

### 6.4 delayed_labels（证书 12:57；2 个 dev + 4 个隐藏；阈值：十分位校准误差 ≤ 0.25）

- **世界**：离散比例风险模型 `h0(k) · exp(r(x)) · m(c)`，外加销户。真值里 m_now 取最近 3 个月的平均。
- **参考解**：人-月 pooled logistic，带在账月数哑变量和日历季度哑变量。**这是教科书做法，也与生成器同形**。误差 0.037–0.061。
- **阈值**：**0.25 比参考宽 4–6 倍**，没有依据。
- **题面**：提示很强，比如"assuming the account stays open"、"like the last 3 months"，几乎直接说出了建模方式。
- **诱饵与基线**：
  - 基线在 dev_flat 上能过；
  - `km_calibrated` 过 dev_flat 和 hid_cycle（0.183）；
  - `tenure_feature` 过 hid_rise 和 hid_flat_churn。
  - **没有 dev 过、只挂隐藏的候选**，README §6 自己也承认。
- **本审计**：需要 sklearn，没有复算。
- **结论**：CLEAN-UNVERIFIED。阈值宽松、题面提示强，加上 ADJACENT/OFF 的领域，【推断】作为难题的价值很低。

### 6.5 ab_interference（证书 12:59；2 个 dev + 4 个隐藏；阈值：8 次重复实验上 (est − GTE)/B 的 RMSE ≤ 0.04）

**世界**：`Y = … e^{βT} / ((1 − s) + s·r_m) · (1 + E_m(p))`，其中 `E = γ_m·p + κ·p(1 − p)`，`γ_m = γ0 + γ_size·log(n / median)`；市场冲击 g_sig 只有 0.012。
- 两个 dev setting 的 γ_size 都是 0。
- 四个隐藏 setting 各打开生成器的一项：
  - hid_none：s = 0；
  - hid_zero_sum：s = 1，γ_size = −0.09，n_sig = 0.9；
  - hid_cautious：κ = 0.4，谨慎设计（多数市场处理比例低）；
  - hid_small：粗网格设计，M = 50。

**参考解**：在市场层面对 q = ybar / xbar 做加权最小二乘，自变量是 p 的二次式乘以 [1, 中心化 log n]，权重 n·x。与生成器的各项一一对应。

**本审计复算【实测】**（在 `/tmp` 副本上重跑 `common/certify.py`）：
- 9 个候选 × 6 个 setting，共 54 个指标，**与项目里的 `certificate.json` 逐位相同**。

**变体测试【实测】**（直接调用 `hidden/world.py`，与判分器口径相同）：

| 变体 | dev_steal | dev_grow | hid_none | hid_zero_sum | hid_cautious | hid_small | 过？ |
|---|---|---|---|---|---|---|---|
| 参考（二次、n·x 权重、规模交互） | 0.0109 | 0.0131 | 0.0171 | 0.0104 | 0.0219 | 0.0122 | 过 |
| 二次、n·x 权重、**无规模交互** | 0.0114 | 0.0137 | 0.0182 | 0.0303 | 0.0218 | 0.0168 | **过** |
| 二次、按 n 加权、有交互 | 0.0083 | 0.0145 | 0.0096 | 0.0088 | 0.0169 | 0.0075 | 过 |

**种子稳定性【实测】**：所有种子加偏移 50000、90000 再跑。参考和"无交互加权二次"都仍然过；三次和两个诱饵都仍然挂（三次在 hid_cautious 上是 0.073、0.083）。**证书对种子是稳健的**。

**评价**
- 题面清楚，GTE 定义明确。
- 阈值 0.04 恰好落在"二次的方差"（≤ 0.022）与"三次的方差"（0.074）之间。**通过窗口是"多项式次数恰好为 2"**：更灵活的三次会因为外推到 p = 0 和 p = 1 方差过大而挂，一次会因为曲率而挂。所以这道题奖励的是"与生成器同次"，而不是一个有原则的选择（E6）。

- 通用做法：3 个基线（diff_in_means、cuped、reg_adjust）和单元层面的 IPW 全挂，因为它们估的是部分处理效应。这一点证书测到了。
- **结论**：CLEAN-VERIFIED，本审计唯一做了逐位复现加变体测试的题。但难度来自"次数刀刃"，【推断】前沿模型如果先做 dev 上的模型选择（dev 上三次也勉强能过，dev_grow 0.0399），有可能靠运气落在二次上。

  - 本审计的 TinyLFU 用精确计数加周期减半，代替 count-min sketch，只能算近似。
  - **5 个现代通用策略没有一个能过**，每个都挂 4–6 个 setting。"不懂考点的通用做法过不去"这一点有了正向证据。
- **诱饵**：`first_token_gittins` 在 hid_zipf 0.305、hid_media 0.179 上挂；`global_gittins` 在 hid_zipf 0.305 上挂。
- **阈值**：0.35 没有推导，而**整道题的通过与否实际上由 hid_zipf 一个 setting 决定**。在这个 setting 上只有参考解过线，余量 0.065。
- **隐藏测试测的是什么**：测的是"是否按完整模板而不是首个 token 做分类"，与题面一致。
- **结论**：CLEAN-VERIFIED。但领域是 ADJACENT/OFF（通用系统缓存，不是 AI 研发）；而且 hid_zipf 的余量薄，一个更强但不同的策略可能被误杀，README §6 也承认这一点。

### 6.7 temporal_leak（证书 13:30；2 个 dev + 4 个隐藏；60 个上线日锁步回放；metric = max(WAPE比 / 1.55, |bias| / 0.03) ≤ 1）

- **世界**：销量会被修订；有门店晚报；闪购的 `planned_at` 就是当天；天气有预报和实测两种。oracle 知道到 d − 1 为止的真实潜在水平，再乘以 0.985。
- **参考解**：3 种写法都过，分数 0.79–0.906。"线不是贴着某一种实现画的"这个说法成立。
- **基线**：current、drop_leaky、shift_all 都挂，而且挂得很远。
- **诱饵**：`final_lags` 挂 5 个 setting；`safe_lag3` 过 dev_a（0.998）和 hid_returns（0.966），挂 4 个。
- **被删的两个诱饵（E1）**：README §4 列了 4 条泄漏通道（修订、晚报、闪购、实测天气）。证书里的诱饵只覆盖了"修订"（`final_lags`）和"修订加晚报"（`safe_lag3`）。**覆盖"实测天气"和"闪购"的两个诱饵，在 13:20 编译过，之后源文件被删，也没进证书**。
  - 【推断】最可能的原因是它们通过了判分，也就是这两条泄漏通道在当前阈值下不绑定：闪购只让偏差约 −1.3%，在 3% 的 bias 线内。
  - 若果真如此，题面宣称的 4 个考点里只有 2 个是真考点。
- **阈值**：1.55 倍和 3% 都没有推导；hid_late 0.91 余量薄（README §6 也承认）。
- **本审计**：pyc 是 Python 3.13 的，沙箱是 3.10，又缺 sklearn，无法运行。
- **结论**：DEFECT-OPEN（疑似）。在修复之前，至少应恢复这两个诱饵并重新出证书，或者在 README 里如实说明这两条通道不绑定。

### 6.8 v11 的共性问题

1. **每个 setting 只有一个固定世界**，`--seeds` 参数没有实现。本审计只对 ab_interference 做了种子扰动，是稳定的；其余 6 题未知。
2. **所有诱饵都是作者自己写的**，没有独立的通用基线。cache_policy 由本审计补测了 5 个；其余题没有人测过"文献里的标准强方法"之外的通用做法，比如 AutoML 式集成、稳健回归。
3. **3/7 题的参考解与生成器同形**，难度在于"猜中作者的模拟器"。这与 v8 的教训"被认证的是正确性不是难度"方向相同，而且更进一步：这里连"正确"都是相对于作者选定的函数族而言的。
4. **隔离**：判分器把宿主的完整环境变量传给 agent 代码；harness 没有容器，claude 以 `--dangerously-skip-permissions` 运行。**正式实跑前必须修**，否则任何一次通过都要人工排查是不是读了 `hidden/`。
5. **异质性**：v11 内部，7 道题的考点确实不同；跨版本看，dedup_cv 与 scaleup L2 相同，sched_law 与 r_crit 相近。
6. **相关度漂移**：只有 sched_law、dedup_cv、temporal_leak 是 ML 自身的问题，其余 4 题是 ML 方法在别的领域的应用。
