# ScaleLab v3：AI4AI 虚拟预训练实验室 benchmark 试点报告

日期：2026-09-25 · 范围：一个 domain 做深（LLM 预训练的 scaling / 训练动力学实验）· 状态：半自动试点，12 个已发布任务

---

## TL;DR

我们做了一个虚拟预训练实验室 **ScaleLab v3**。流程是：从已有文献里整理出机制卡，给每张卡固定函数形式、重新抽常数；再从障碍模板里挑一种"让团队结论出错"的方式；二者组合成蓝图，由一条 pipeline 自动生成题目。每道题给 agent 一份有缺陷的团队实验笔记、一个按 FLOPs 计费的 `lab run` 接口和 5–8 个问题，问题都是关于实验室里跑不到的生产规模的。自动生成之后，每道题要过 11 道机械闸门才能发布。闸门确认三件事：题可解（oracle 用新种子重做仍然通过）；每个标为 must-kill 的捷径对手都被至少一道题以 ≥2T 的余量击杀（另有少数"只报告、不强制"的 INFO 对手，见第 2.3 节）；每张机制卡都是必需的（去掉它就会答错某一题）。全程不用 LLM 出题，也不用 LLM 判分。

目前产出 12 个任务：4 个独立蓝图（T01/T02/T03/T07），外加 2 个紧预算变体（T01b/T03b），覆盖 10 种障碍模板中的 6 种。第五个蓝图 T05（benchmark 污染 / 度量伪影 O4）被闸门拒收，下文作为**负结果**记录。

实测结论要老实说：**v3 总体上还没有难倒 GPT-6**。

- **总数。** 12 个任务各跑一次无提示（H0），GPT-6 全对 7/12，平均 0.85；fable 全对 3/12，平均 0.75。把数值容差放宽到 2T 后，GPT-6 全对 9/12。剩下 3 个里，只有 T02 ws2 做过重复运行：两次都没全对，而且失败落在同一个对手上。
- **会饱和的题型。** 预算充足时，机制推断退化为系统辨识，GPT-6 能做满：T01 两个实例都是 8/8，T03 两个模型都是满分。
- **紧预算。** 只收紧预算、世界不变时，T03b 上 fable 从 1.00 降到 0.50，GPT-6 从 1.00 降到 0.33。T01b 则没有变难。所以紧预算只对"需要分离两个重叠效应"的题有效。
- **唯一跨模型、可复现、并且能精确归因的失败点：T02 q2。** 实验室里 qk-layernorm 永远不发散（被截尾），只能对它做**部分识别**。
  - GPT-6 在 T02 ws2 上独立跑两次，q2 下界两次都落在同一个具名对手 `B2_doc_range_only` 上，也就是直接照抄文档给的范围。首跑其实在最不稳角落（N=3e8、warmup=0、lr 上限）跑过一次 qk-on（没有发散），但没有在同一角落测 qk-off 边缘，也没有把这次结果用进下界；重跑则从没到过这个角落（N 最高 2.2e8，没用过 warmup=0）。
  - gpt-5.5，以及 fable 在 ws3 上，落在 warmup 族对手上：`B3_bound_at_prod_warmup`、`B7_no_warmup_effect`、`drop:C4:warmup` 三者数值彼此相差不到 0.3T，都是在生产 warmup 下而不是最不稳角落收紧下界。
  - haiku 的下界也偏松，但离任何具名对手都超过 1T，记为未归因。
  - fable 在 ws2 上两次独立运行，一次失败（1.65T 精度型），一次通过。
- **验证阶梯。** 弱模型 haiku 得 0.12 和 0.43，强弱能拉开。给出精确函数形式（H2）后 fable 7/7；GPT-6 第一次 H2 运行在没写任何答案时自行退出（0/7），重跑得 6/7（只在 q2 上差 1.12T 的精度）。说明题目上限可达，但"上限"本身也受 agent 可靠性噪声影响。

这份报告最想交付的是两条经验：

1. 难度的真杠杆不是"藏更多信息"，而是**让实验设计选择决定能说到多精确**，也就是截尾 / 部分识别 + 紧预算下的效应分解。
2. 捷径对手必须构造成**最小对**（真值只换掉一处）。否则对手会被别的题的噪声"误杀"，闸门就会放行本不该放行的题。T05 的教训就是这个。

## 1. 对四个问题的回答

### 问题一：如何稳定、可控地产出难题？

结论是：**"难"不能靠闸门保证，只能靠蓝图设计 + 模型实测来确认。能稳定保证的是"对"和"难得有意义"。**

我们把一道题拆成三层。

**机制卡。** 例如 C4 发散边缘、C11 调度相关的中间 checkpoint 损失。每张卡有文献出处和固定函数形式，常数每个世界重新抽。

**障碍模板（O1–O10）。** 规定团队的笔记为什么会错，例如：

- 两个原因在所有旧实验里共变（O1）；
- 两个效应在观测范围内互相抵消（O2）；
- 目标量在实验室里被截尾（O3+O5）。

**题型。** 每道题要求至少三种：

- point：点估计；
- set：部分识别区间；
- verdict：supported / refuted / undetermined；
- decision：选项，以 regret 判分。

可控性来自三个旋钮：选哪种障碍、预算上限（`run_flops / total_flops / max_runs`），以及是否引入"已知的未知量"。已知的未知量指在实验室里零足迹、只有文档范围的参数，它逼出 set 型答案和 undetermined 判定。

稳定性来自闸门：每个世界种子都要重新校准容差，并在新种子上重做 oracle。蓝图的**自然产率**全部落盘在 `yield_logs/`，不挑选：

| 蓝图 | 自然产率 | 主要拒收原因 |
|---|---|---|
| T02 | 34/40 | G0 ×4，G6 ×2 |
| T07 | 32/40 | G0 ×6，G6 ×2，G1 ×1 |
| T03 | 2/22 | G8 决策间隙 ×19，G3 集合宽度 ×15，G2 ×14 |
| T05 | 0/40 | 见第 5 节 |

单个种子的构建（含全部闸门）耗时：T02/T03/T07 为 1.1–2.5 秒，T05 为 7.5–17.2 秒（见 `yield_logs/` 的 `secs` 字段）；已发布任务重新构建时为 1.2–4.3 秒。

但实测表明，闸门能保证"每个 must-kill 捷径对手都失败"，**不能**保证"前沿模型会失败"：

- 预算充足时，T01 和 T03 都被 GPT-6 满分解掉；
- 同一 GPT-6 在 T02 ws2 上两次都掉进同一个对手，fable 在同一题上两次运行一败一胜。

所以我们的建议是：难度声明以**蓝图**为单位，每个"模型 × 实例"格子至少跑 3 次，报告"全对率"和"逐题失败落在哪个对手上"，不报告单次平均分。到本报告为止，只有 T02 ws2 做了重复运行（fable、GPT-6 各 2 次 H0，GPT-6 另有 2 次 H2；gpt-5.5、haiku、sonnet 各只有 1 次），其余格子都是单次（见第 8 节）。

**什么样的蓝图更容易难住前沿模型？** 按证据强弱排列：

1. **截尾 / 部分识别，且下界的紧度取决于实验设计**（T02 q2）。这是唯一跨模型复现的失败点。
2. **紧预算下分解两个互相掩蔽的效应**（T03b）。两个模型都掉分，而且是远超容差的粗错，但只有一个实例、单次运行。
3. **把 checkpoint 当成训完的 run（调度混杂，T07）**。两个前沿模型在 3 个实例中各有 2–3 个没有全对，但多数失败在 1–2T 之间。容差放宽到 2T 后，GPT-6 只剩 ws3（2.01T）没有全对。
4. **把一个轴上拟合的规则搬到另一个轴上**（T01 的 O9）。对 fable 有效（0.50/0.62），对 GPT-6 无效。
5. **在充足预算下辨识单一机制**。已饱和，不建议再投入。

这与 v2 的结论一致："藏信息"不是杠杆，逼模型**精确陈述自己不知道什么、以及用什么实验把不知道的范围缩到多小**才是杠杆。

### 问题二：怎样保证考的是不同机制，而不是换背景换变量？

我们的回答分三部分：定义考点单位，度量异质性，再用机械检查确认"题真的需要这个机制"。

**考点单位是蓝图，不是任务目录。** 同一蓝图的不同世界种子只是换数字，考的是同一个点。所以 12 个任务应当诚实地读作"4 个考点 + 2 个预算变体 + 若干重复实例"。第 6 节给出按机制卡、障碍模板、题型计算的 Jaccard 矩阵：

- 所有蓝图共享 C1（损失面）和 C10（种子噪声），它们是"实验室本身"，不是考点；
- 去掉这两张后，各蓝图的考点卡是 T01 {C2}、T02 {C2, C4}、T03 {C6, C7}、T07 {C11}、T05 {C9}，除 C2 外两两不相交；
- 卡片 ∪ 障碍的 Jaccard 在 0.27–0.62 之间；
- 题型 Jaccard 全是 1.00，这是 G7 故意要求的，异质性只体现在内容上。

**"这道题真的需要这个机制"由 G9 机械检查。** 对每张机制卡构造一个 `drop:<卡>` 对手：在真值世界里把这张卡关掉（或换成教科书常数）重新作答，它必须在至少一道题上以余量被击杀。否则说明这张卡在题里是装饰。

有些卡确实只通过别的卡间接起作用，比如 T05 里 C1 只通过 loss→accuracy 映射进入题目。这种情况必须在 `EXEMPT_LOAD_BEARING` 里**声明式豁免**并写明理由，不能静默跳过。

**机制之间的区分还要看"错成什么样"。** 每个蓝图的对手邻域是按它的障碍模板写的，例如：

- T02 的 `B3_bound_at_prod_warmup`：在生产 warmup 而不是最不稳角落收紧下界；
- T02 的 `B7_no_warmup_effect`；
- T07 的 `B2_cosine_finals_no_schedule`；
- T03 的 `B1_notebook_naive`（按团队笔记的读法作答）。

对手分 must-kill 和 INFO 两类，只有前者由闸门强制击杀。INFO 对手是"合法但不够好"或"有时碰巧能对"的做法，例如 T03 的 `B4_replicate_ablation`（重复做消融，ws28 上 1.00、ws11 上 0.83）和 T07 的 `B4_cosine_grid_full_law`（ws1、ws3 上都是 1.00）。闸门不要求击杀它们：有的在某些实例上会被击杀，有的在某些实例上能拿满分。

模型的错误答案可以映射到最近的具名对手，于是"考到了什么"能从分数下沉到具体机制。但不是每个失败都能这样归因。本轮 T02 q2 共失败 9 次：

- 4 次落在强对手 1T 以内：GPT-6 两次落在 B2，gpt-5.5 和 fable（ws3）各一次落在 warmup 族；
- 3 次是 1.09–1.65T 的精度型；
- 1 次是 haiku 的未归因粗错；
- 1 次空答。

全部 27 个前沿模型数值题失败里，只有 6 个能强归因，而且其中 3 个指向的是 INFO 对手（见第 4.3 节）。27 这个数的口径是：包含 T02 ws2 的 H0 重跑和 H2 重跑，不含空答。如果每个任务只算第一次 H0，是 25 个（GPT-6 8 个），其中强归因 5 个、精度型 6 个。

### 问题三：AI4AI 题目必须来自真实场景吗？

**不必。基于真实机制的虚构世界可以，而且在防记忆这一点上更好。但必须同时满足四个条件，并且要清楚它能声称什么、不能声称什么。**

1. **机制有出处。** 每张卡都在 `scalelab/cards.py` 写明文献来源和抽象边界，例如：
   - C1 引用 Hoffmann 2022 和 Besiroglu 2024 的复现；
   - C4 引用 Wortsman 2023 和 Dehghani 2023；
   - C11 引用 Hägele 2024 和 Porian 2024。

   函数形式照搬文献中已被反复报告的规律，常数在文献报告范围附近重新抽取。
2. **自洽由构造保证。** 实验室接口、oracle、对手、闸门都走同一个 `Session.run()`。agent 能观测到的，正是闸门认证过的。不存在"题面说一套、模拟器算另一套"的空间。
3. **抽象边界写进题面。** 每份 `manual.md` 开头都写着：这是模拟实验室，不是任何真实训练栈的复刻，常数是新抽的，文献数字（Chinchilla 指数、"最优"学习率、epoch 经验法则等）只描述别的系统。
4. **文献常数必须答错。** 每个蓝图都有 `B0_textbook` 对手（用文献常数作答），它必须被击杀。这让"背文献"成为一条被证伪的捷径：模型必须在这个世界里做实验。

**能声称的：** 模型能否在一个机制已知类别、常数未知、笔记有缺陷的实验室里，设计实验、推断机制、给出可辨识范围内的结论。这正是你们要的 claim："根据不完整实验结果进行机制推断和实验设计"。

**不能声称的：** 模型在真实预训练中会做对。外部效度没有验证。而且本 domain 只覆盖预训练的 scaling / 稳定性 / 数据 / 调度实验，不代表"AI 研究"整体。建议在报告和对外口径中把 claim 写成"在基于文献机制的模拟训练实验室中……"。

### 问题四：如何确认题目真的需要目标机制、没有意外捷径？你提议的验证阶梯怎么样？

我们把验证分成**机械层**（发布前，零模型调用）和**模型层**（你提议的阶梯）。结论是：**阶梯有用，但只有配合"失败归因到具名对手"才有解释力。否则"强模型失败"分不清是题难，还是题错，还是 agent 不稳。**

**机械层（每个发布实例都过）：**

1. **对手邻域 + G2。** 对手包括：
   - 教科书常数；
   - 照读笔记；
   - 每张卡的 `drop:` 版本；
   - `collapse_sets`（把区间塌成点）；
   - `widen_points`（把点放宽成区间）；
   - 每个障碍模板专属的捷径。

   每个 must-kill 对手都必须至少在一道题上以余量被击杀：数值题误差 ≥2T，或者在稳定题上给出错误类别。**关键教训是：捷径对手必须是最小对。** 做法是在真值世界的答案上只替换捷径影响的那一处。如果对手是"用捷径的思路从噪声数据重新拟合整套答案"，它会因为拟合噪声在无关题目上被"误杀"，闸门就会放行实际上没杀住捷径的题。T05 v2 就是这样被放行了 2 个实例（第 5 节）。
2. **G9 负载检查。** 见问题二。
3. **G4 可辨识性证书。** 声明为"未知"的量，在实验室可跑区域内必须零足迹：取 1500 个随机请求加上全部笔记配置，让该未知量分别取范围两端和中点，所有输出必须逐字节相同。因此 undetermined 和 set 型答案是可证明正确的，不是出题人的主观判断。
4. **G5 重放、G6 泄漏。** 笔记中的每一行都能由 `lab run` 逐字重放；题面里不能出现答案数值及其常见变换。
5. **G1 可解性。** oracle 在 10 组新种子上重做实验，全对率 ≥0.8，每道题通过率 ≥0.9，而且发布出去的那组 oracle 答案本身全对。所以"强模型失败"不可能是题目无解。

**模型层（你提议的阶梯，本轮实跑结果）：**

| 阶梯 | 预期 | 实测 | 判断 |
|---|---|---|---|
| 简单基线失败 | 规则 / 教科书 / 照读笔记都答不全 | 所有发布实例上 must-kill 对手全部被击杀。但**逐题分数**上，最强的 must-kill 对手能拿 0.80–0.88：它是最小对，只错一题，这是构造使然 | 应以"全对率"为主指标，逐题分只作诊断 |
| 弱模型失败 | haiku 级低分 | haiku-4.5：T01 ws1 0.12，T02 ws2 0.43。sonnet-4.6 在 T02 ws2 上因单轮思考超出宿主时间片而活锁，未完成 | 通过 |
| 强弱拉开 | 前沿 ≫ 弱 | T01：GPT-6 1.00 / fable 0.50–0.62 / haiku 0.12。T02：0.57–1.00 对 0.43 | 通过，而且两个前沿模型之间也拉开了 |
| 满提示给上界 | H2（精确函数形式）接近满分 | fable H2 7/7。GPT-6 H2 第一次在没写答案时自行退出（0/7），重跑 6/7（q2 差 1.12T） | 上界可达，但 agent 可靠性本身是噪声源 |

建议在阶梯上补两条：

1. **失败归因。** 把每个错答映射到最近的具名对手，或标为"精度型"（误差在 1–2T，不对应任何对手）。
2. **重复运行。** 每格至少 3 次，报告全对率及其区间。

本轮最有信息量的结论正是靠这两条得到的：GPT-6 在 T02 q2 上"两次都落在 B2"，比"GPT-6 在 T02 上得 0.57"有用得多。

## 2. 设计与 pipeline

### 2.1 从"机制图"到"蓝图"

你提议把题目表示成半合成的机制 / 因果图：隐藏节点、观测节点、干预节点、目标节点、干扰节点。ScaleLab 把这张图拆成两个可复用的库。

**机制卡库（C1–C11）。** 每张卡是一个有文献出处的子图：函数形式 + 参数 + 抽象边界。

**障碍模板库（O1–O10）。** 每个模板描述一种"观测结构让结论出错"的方式，决定哪些边在旧实验里不可见、哪些节点被混杂或截尾。

一个**蓝图** = 若干机制卡 + 若干障碍模板 + 题目生成函数 + 对手邻域。一个**实例** = 蓝图 + 世界种子。这样"种子图由人审"就落在两处：人只需要审卡片和蓝图（本轮共 11 张卡、5 个蓝图），不必逐题审；每个实例附一张 `review_card.md`，供抽检。

**机制卡（`scalelab/cards.py`）**

| 卡 | 机制 | 主要出处 | 用在 |
|---|---|---|---|
| C1 | Chinchilla 型损失面 L = E + A·N^-α + B·D^-β | Hoffmann 2022；Besiroglu 2024 复现 | 全部（底座） |
| C2 | 学习率碗：最优 lr 随规模和 token 视野移动，两侧不对称 | Wortsman 2023；Bjorck 2024 | T01，T02 |
| C3 | 临界 batch 由数据视野决定 | McCandlish 2018；Zhang 2024 | （未用） |

### 2.2 生成流程（一条命令一个种子）

`python3 -m scalelab.suite <blueprint> <ws_from> <ws_to> [--want K]` 会依次对每个种子做下面几步：

1. **抽世界。** 在蓝图声明的范围内抽常数，保证障碍条件成立。例如 T02 要求生产规模下的发散边缘低于最优 lr，T03 要求过滤和重复在团队的消融里正好抵消。
2. **生成笔记。** 用同一个模拟器"跑"团队的旧实验，得到 `runs.csv`；按障碍模板写出带错误结论的 `lab_notes.md`，以及团队的生产计划。
3. **生成题目。** 题目指向实验室跑不到的生产配置（例如 N=7e9、D=1.4e11）。题型至少三种，至少一道"必须承认不知道"的题（set 或 undetermined）。
4. **oracle 校准。** 参考解题器在实验室里按预算做实验、拟合、作答。10 组新种子用于定容差，point/set 题的容差为 T = max(floor, 2.25 × p90(oracle 误差))，decision 题为 r_tol = 最优与次优之差 / 3；另外 10 组新种子用于验证可解性。
5. **对手作答。** 对手邻域逐个作答，得到击杀矩阵。
6. **过闸门。** 通过全部闸门后导出。每个尝试过的种子（通过与否、为什么）都写进日志。

### 2.3 闸门

| 闸门 | 检查 | 失败意味着 |
|---|---|---|
| G0 wellposed | 蓝图自定义的良定条件，例如障碍确实生效（T02：笔记 lr 与生产发散边缘相差足够；T07：团队的有偏分配选错 q1、q5 判定边际足够） | 这个世界里障碍不成立 |
| G1 solvable | oracle 新种子全对率 ≥0.8、每题 ≥0.9，且发布的 oracle 答案全对 | 题目在预算内不可解，或容差太紧 |
| G2 kill_matrix | 每个 must-kill 对手至少在一题上以余量被击杀（数值 ≥2T 或稳定题类别错） | 某条捷径能拿满分 |
| G3 set_width | set 题区间宽度 ≥4T | "承认不知道"的题退化为点估计 |
| G4 identifiability | 已知未知量在可跑区域零足迹（逐字节） | undetermined 的判定不可证 |
| G5 replay | 笔记每一行都能被 `lab run` 逐字重放 | 笔记与模拟器不一致 |
| G6 leakage | 隐藏参数和数值答案（多种格式）不出现在 agent 可读文本里 | 泄漏 |
| G7 key_types | ≥3 种题型，且有"无知题" | 题目单一 |
| G8 decision_gap | decision 题最优与次优的损失差 ≥0.004 | 选项在噪声内不可分 |
| G9 load_bearing | 每张卡的 drop 对手都被击杀（或声明式豁免） | 某张卡是装饰 |
| G10 item_useful | 信息性：每道题击杀哪些对手 | —— |

对手分成两类：`must_kill`，由闸门强制；`INFO_RIVALS`，只报告不强制，并且每个都要写明理由。例如 T01 的 `B3_random_design` 是随机设计，有时碰巧能做对，所以不作为硬约束。

### 2.4 导出格式（Harbor 风格）

每个任务目录的内容：

- `instruction.md`：任务说明，题目内联。
- `task.toml`：卡片、障碍、claim、超时等元数据。
- `environment/app/`：agent 能读到的全部内容，包括 `manual.md`、`questions.json`、`answers.json`（模板）、`notebook/runs.csv`、`notebook/lab_notes.md`、`bin/lab`。
- `environment/lab_service/`：实验室服务说明。
- `hidden/world.json`：只在服务端。
- `tests/`：判分，包括 `grade.py`、`key.json`、`queries.py`。
- `solution/`：oracle 在本实例噪声下的实验记录和答案，证明预算内可解。
- `hints/H1.md, H2.md`：提示阶梯。H1 列出生效的机制名；H2 给出精确函数形式但不给常数。
- `cert.json`：校准、击杀矩阵、闸门结果。
- `review_card.md`：人审卡片，状态为 pending。

agent 只能通过 `bin/lab` 访问实验室。预算账本在服务端，agent 的文件系统里没有。

### 2.5 运行框架与密钥安全

两个 agent 都带 shell 工具：Claude 系模型走 Claude Code CLI（`cc_agent.py`），GPT 系走 Responses API 工具循环（`gpt_agent.py`）。它们运行在 bubblewrap 沙箱里，`/app` 是任务的 `environment/app` 副本。

密钥只存在操作员目录 `.sec/` 里（权限 700/600）。回环网关 `gateway.py` 是唯一读取密钥的进程。沙箱内的环境变量只有占位符 `sk-sandbox-placeholder-not-a-credential`，网关在出站时替换成真实密钥。所以被测模型即使读 `/proc/self/environ`，也拿不到真实凭据。

发布物、报告、记忆、桌面副本都经过密钥扫描（第 9 节）。**建议你们在本轮结束后轮换这把 key**，因为它曾经出现在对话里。

### 4.3 失败归因

`harness/attrib.py` 对每个运行做三件事：

1. 用冻结代码从（蓝图，世界种子）重建实例，检查重建出的答案键与发布的 `key.json` 是否逐字节一致。12 个任务全部一致，说明发布物可由代码复现。
2. 对每道失败的 point/set 题，找离模型答案最近、而且自身也答错（离真值 ≥1T）的具名对手。如果这个对手离模型答案不到 min(1T, 模型误差)，就记为"对手"。对手自身误差 ≥2T 的记为**强**，否则记为**弱**，因为这时模型夹在真值和一个"只错一点"的对手之间，匹配说明不了什么。
3. 找不到对手的，误差 <2T 记为**精度型**，≥2T 记为**未归因**。verdict 和 decision 题列出给出同样错答的对手。

完整输出在 `docs/attribution.txt`。

- T02 ws2 GPT-6 首跑 q3 答"计划中的生产 run 不发散"，与团队笔记的读法（B1）和教科书对手相同，正是 O9 的核心陷阱；重跑时答对了。同一次运行的 q4 答 undetermined，与 B2 相同，和它自己照抄文档范围的 q2 一致。
- haiku 在 T01 q5 上与团队笔记读法（B1_notebook_naive）相同。
- GPT-6 在 T03b q3 上选了 q=0.85，与 `drop:C6:Rs`（忽略重复代价）相同。

### 4.4 按蓝图解读

**T01 / T01b（lr 规则的尺度迁移）：对 GPT-6 饱和。** 结果：

- GPT-6 在四个实例上都是 8/8，包括只给 15 次 run 的紧预算版本。
- 去混杂只需要少量离对角的 run。GPT-6 在 T01b ws2 上 15 次里有 10 次离开 D=20N 对角线，只用了 4 个不同的 (N, D) 点。
- fable 的实验设计也离开了对角线（T01b ws2 15/15 次离对角），但它在 T01b ws2 上的 q2/q4 与 `B2_notebook_allcards` 相差不到 0.14T。这个对手只用笔记对角线数据拟合全模型。我们的**推测**是分析阶段没有用上自己的离对角数据，但没有逐步读它的轨迹来证实。
- haiku 基本停在对角线附近：D/N ≤200，而另外两个模型最高到 10000；40 次里只有 14 次离对角。它的 q5 判定与团队笔记的读法一致。阶梯底端按设计工作。

**T02（发散边缘 + 截尾）：唯一复现的强失败点。** q2 的真值区间是 [−1.839, −1.358]，T=0.025。

| 运行 | q2 下界 | q2 上界 | 归因 |
|---|---|---|---|
| 真值 | −1.839 | −1.358 | |
| GPT-6 H0 | −2.857 | −1.380 | B2 文档范围（−2.835） |
| GPT-6 H0 重跑 | −2.843 | −1.366 | B2 文档范围 |
| gpt-5.5 | −1.985 | −1.366 | warmup 族（B3/B7 −1.978；drop:C4:warmup −1.981） |
| fable H0 | −1.880 | −1.360 | 精度型 1.65T |
| fable H0 重跑 | 通过 | | |
| haiku | −2.7 | −1.2 | 未归因 |
| GPT-6 H2 重跑 | | | 精度型 1.12T |

为什么难：

- 实验室里，qk-norm 在 lr 上限内**永不发散**，所以生产规模下 qk-on 的发散边缘只能部分识别。它等于"生产 qk-off 边缘（q1）× qk-norm 的放宽倍数 Q"。Q 的上限只能取文档值 60，所以区间上界是 q1 + log10(60)。
- 下界取决于**你在哪里证明了"不发散"**。在最不稳的角落（N 最大、warmup=0）先测出 qk-off 边缘，再在 lr 上限上跑 qk-on、确认不发散，就得到 Q ≥ lr 上限 / 该角落的 qk-off 边缘。这是实验室能给出的最紧下界。
- 在生产 warmup 下做同样的事，得到的下界松约 0.14（log10），就是 B3 族对手。
- 什么都不跑、照抄文档（Q ≥ 2），得到的下界松约 1.0，就是 B2。

这正是"实验设计决定能说到多精确"。GPT-6 两次都花了大量算力（1.79e19 和 2.55e19，是 fable 两次运行的 3.3–5.5 倍），却都没有把这部分算力变成更紧的下界。首跑在最不稳角落（N=3e8、warmup=0、lr=0.05 上限）跑过一次 qk-on，结果是不发散，但它没有在同一角落测 qk-off 边缘，所以这次 run 没法换算成 Q 的下界，最终答案也没用到它。重跑的 N 最高只到 2.2e8，也从没用过 warmup=0。作为对照，fable 两次 H0 都在这个角落既测了 qk-off 边缘、又跑了 qk-on。

还有一个值得注意的细节：GPT-6 重跑时，q2 的下界仍是 −2.84，但 q4 判"lr=10^−2.33 下 qk-on 不发散"为 supported。这个判定是对的，却和它自己的区间矛盾：按它的区间，这个 lr 可能发散，应该答 undetermined。这说明它的 set 答案更像是按格式填写的，而不是由实验推出来的。

**T03 / T03b（过滤 vs 重复）：预算是开关。**

- 40 次 run 时，两个模型在两个实例上都是 6/6。
- 12 次 run 时两个都崩：
  - fable 的 q1（重复代价）是对的，但 q2（过滤效应）答 +0.037，真值 +0.009，差 9.5T；q6 判 refuted，真值是 undetermined，与团队读法 B1 同答。
  - GPT-6 的 q1 答 0.68，真值 0.022，差 116T；q3 选了最激进的过滤（与"忽略重复代价"的 `drop:C6:Rs` 同答），这和它自己"重复代价巨大"的 q1 自相矛盾。
- 这些失败大多是**未归因的粗错**，不对应任何现成的对手。这说明对手邻域覆盖的是"系统性捷径"，覆盖不了"预算不足时辨识失败 + 前后不一致"。这也是第 8 节"对手完备性由人写"这条局限的实例。

**T07（checkpoint ≠ 训完的 run）：多为边界失败。**

| 运行 | 结果 |
|---|---|
| GPT-6 ws1 | 5/5 |
| GPT-6 ws3 | q4（提前停的损失差区间）差 2.01T，未归因 |
| GPT-6 ws4 | q3 差 1.55T，弱匹配 `B4_cosine_grid_full_law`。这个对手是"一条合法但精度不够的设计"，只报告、不强制 |
| fable ws1 | q3 强匹配 `B3_linear_in_lr` |
| fable ws3 | q2 差 1.12T，弱匹配 `drop:C11:ca`；q5 与 `drop:C1:textbook` 同答 |
| fable ws4 | q2 差 1.01T |

T07 的 q2 容差偏松（0.013–0.037），ws3 上 q2 只击杀了 `widen_points`，所以 q2 上的"弱匹配"不能当证据用。

### 4.5 验证阶梯与 agent 可靠性

- **上界（H2）。** fable 7/7。GPT-6 首跑用了 13 次 high effort 调用、39 次 lab run，把 FLOPs 预算用到只剩 3.3e17 时，回复"Unable to complete the requested artifact within the available execution window"，没写任何答案就结束了。任务说明和系统提示里都没有提到时间窗口，这是模型自己放弃，而不是被框架截断。重跑 6/7，只差 q2 的 1.12T。所以上界可达，但"满提示仍失败"里混着 agent 可靠性噪声。
- **弱模型。** haiku 在 T01 ws1 上 0.12，在 T02 ws2 上 0.43。它在 T02 上只跑了 14 次 run 就自己停了，这时已用掉约 98% 的 FLOPs。run 贵不是因为模型大（N 只在 5e7–2e8），而是因为它一律按 D=20N 配 token（1e9–4e9 tokens），而 fable 和 GPT-6 测发散边缘时多用 D=2e8 的短 run。
- **sonnet-4.6 活锁。** 它走 Claude Code CLI（`cc_agent.py`）。从第 29 轮起，它的单轮思考连续 20 多个时间片都没能在一个时间片（约 158 秒）内完成，每次都被中断、再从同一会话恢复，没有任何进展。`SLICE_NEED_CAP` 只存在于 GPT 的 `gpt_agent.py` 里，CLI 框架没有等价机制，所以那个修复对它不适用。最终在 34 次 run、没有写任何答案时中止，记为 `aborted_livelock`，不计分。这反映的是运行框架的约束，不是模型能力。
- **gpt-5.5。** 在 T02 ws2 上得 0.86，与 fable 首跑相同，高于 GPT-6 首跑的 0.57。这是单任务单次运行，不能据此说 GPT-6 弱于 gpt-5.5，但它提示我们：在这类题上，模型代际和分数之间不一定单调。

### 4.6 小结：难住 GPT-6 了吗？

按严格容差，GPT-6 首跑有 5/12 个任务没全对；放宽到 2T 后剩 3/12。其中：

- **复现过的、可强归因到机制层面的 GPT-6 失败只有一个：T02 q2。** 截尾下的部分识别，需要主动去最不稳角落做实验。GPT-6 两次都退回到照抄文档范围。
- T03b 给出了"两个前沿模型在紧预算效应分解上都粗错"的**单次信号**。
- T07 的失败大多在边界上。

所以 v3 的产出应该读作：**1 个已确认的难点 + 1 个待复现的难点 + 一套能把失败定位到具体机制的工具**，而不是"12 道难住 GPT-6 的题"。

## 5. 负结果：T05 被闸门拒收

**设计。** T05 考 C9：benchmark 污染经由混合数据源进入训练，属于 O4 度量伪影。

- 数据混合里有书籍语料，一个 2000 题的公开 QA benchmark 有比例 φ 泄漏进了书籍语料。
- 公开分数 = 真实知识（书籍调整后损失的 sigmoid，在 b* 处最优）+ 记忆的泄漏题。记忆程度随模型大小（N^ξ）和见过的书籍 token 数（b·D）增长。另有一个 250 题的干净集，它噪声大，笔记里没有采信。
- 团队在实验室最大配置（N=3e8, D=1e10）上扫了书籍占比 b，发现公开分数随 b 一路上涨，于是计划在"看起来最好"的 b 上做生产（N=1e9, D=3e10）。
- 设计意图是：生产规模下记忆接近饱和，公开分数高估的幅度远大于笔记里测到的差距（O9）。小版本发布时的书籍占比还没定（b∈[0.02, 0.4]），这是已知的未知量，所以它的污染差距要以区间作答。

**三轮产率**（全部在 `yield_logs/`，每轮 40 个种子）：

| 版本 | 通过 | 主要拒收 | 未被击杀的 must-kill 对手（种子数） |
|---|---|---|---|
| v1 | 0/40 | G2 ×40，G3 ×40，G9 ×38，G0 ×27，G1 ×20 | collapse_sets 37，drop:C1:textbook 37，B3 31，B1 14，drop:C9:phi 13 |
| v2（C1 声明式豁免等修正） | 2/40（ws20、ws35） | G2 ×36，G3 ×32，G0 ×27 | collapse_sets 32，B3 28，B1 12，drop:C9:phi 12 |
| v3（B3 改为最小对） | 0/40 | G2 ×38，G3 ×32，G0 ×27 | **B3 37**，collapse_sets 32，B1 12，drop:C9:phi 12 |

**v2 的 2 个"通过"是假的。** v2 的 B3 对手（"把实验室测到的污染差距直接搬到生产"）是按捷径思路**从带噪数据重新拟合整套答案**的。

- ws20 上，它只在 q1 上被击杀，而 q1 根本不受这条捷径影响，是拟合噪声造成的误杀。
- 把 B3 改成最小对以后，也就是在真值世界的答案上只替换 q3/q4 这两道捷径触及的题，ws20 和 ws35 都不再击杀 B3。ws35 上 B3 甚至拿到满分。

最小对版本的 B3 代码（`scalelab/bp/t05_contaminated_benchmark.py`）：

```python
pt = W.full(p)
b3 = answers_from(pt, ctx)                       # 真值世界的全部答案
a_lab, agg_lab = _acc(pt, LAB_N, LAB_D, ctx["b_team"])
b3["q3"] = {"lo": _acc(pt, PROD_N, PROD_D, ctx["b_team"])[0] + agg_lab - a_lab}   # 只替换捷径触及的题
b3["q3"]["hi"] = b3["q3"]["lo"]
gl = [_acc(pt, LAB_N, LAB_D, b) for b in np.linspace(BREL[0], BREL[1], 31)]
b3["q4"] = {"lo": min(g[1] - g[0] for g in gl), "hi": max(g[1] - g[0] for g in gl)}
out["B3_lab_gap_transfer"] = b3
```

**解读。** 设计意图是"生产规模的污染差距远大于实验室"，但在实际抽到的世界里，这个差异大多落在 2T 的击杀余量以内，所以"直接搬运实验室差距"这条捷径在数值上基本是对的。障碍没有生效，蓝图考不到它声称要考的东西。此外，已知未知量（b 的范围）产生的区间太窄，collapse_sets 在 32/40 个种子上活了下来（G3 失败）。闸门做了它该做的事：拒收。

**两条教训：**

1. **捷径对手必须是最小对**，否则误杀会让闸门放行坏题。这条已写进第 1 节问题四。
2. **如果一个蓝图的核心捷径只能靠拟合噪声被击杀，它就不是一道题。** 要修 T05，得让记忆效应随 N 强烈变化（加大 ξ 的范围），或者让生产的数据配比与实验室不同，使"搬运差距"在结构上就是错的。本轮没有做，T05 保持未发布。

## 6. 异质性：12 个任务到底考了几个点

本节数字由 `python3 -m scalelab.hetero` 从蓝图定义和已发布的 `key.json` 直接算出，全文见 `docs/heterogeneity.md`。同一蓝图的不同实例共享机制卡、障碍模板和题型，只有世界抽样不同，所以异质性按**蓝图**算，不按任务目录算。

**蓝图构成**

| 蓝图 | 已发布实例 | 机制卡 | 考点卡（去掉 C1、C10） | 障碍模板 |
|---|---|---|---|---|
| T01 lr 规则的尺度迁移 | 2 + 紧预算 2 | C1, C2, C10 | C2 | O1, O9, O5 |
| T02 发散边缘 | 2 | C1, C2, C4, C10 | C2, C4 | O3, O5, O9 |
| T03 过滤 vs 重复 | 2 + 紧预算 1 | C1, C6, C7, C10 | C6, C7 | O2, O3, O5 |
| T07 checkpoint ≠ 训完的 run | 3 | C1, C11, C10 | C11 | O7, O1, O5, O9 |
| T05 benchmark 污染（未发布） | 0 | C1, C9, C10 | C9 | O4, O1, O9, O5 |

C1（损失面）和 C10（种子噪声）是所有蓝图共有的底座，相当于"实验室本身"，不算考点。四个蓝图都用了全部四种题型（point、set、verdict、decision），这是 G7 的要求，所以题型 Jaccard 全是 1.00，不在下表列出。

**两两 Jaccard**

| 对 | 卡片 | 障碍 | 卡片 ∪ 障碍 |
|---|---|---|---|
| T01–T02 | 0.75 | 0.50 | 0.62 |
| T01–T03 | 0.40 | 0.20 | 0.30 |
| T01–T07 | 0.50 | 0.75 | 0.62 |
| T02–T03 | 0.33 | 0.50 | 0.40 |
| T02–T07 | 0.40 | 0.40 | 0.40 |

**覆盖。** 已发布任务覆盖了 6/10 个障碍模板（O1、O2、O3、O5、O7、O9）。O4、O6、O8、O10 没有覆盖，其中 O4 只在被拒收的 T05 里尝试过。C3（临界 batch）、C5（AdamW EMA 时间尺度）、C8（exact-match 指标）三张卡没有被任何蓝图使用。

**应当如何诚实地读这些数字：**

- **独立考点是 4 个，不是 12 个。** 12 个任务 = 4 个蓝图 × 若干世界种子 + 2 个紧预算变体（T01b 两个实例、T03b 一个实例）。紧预算变体是同一世界、同一题目，只收紧预算，不算新考点。
- **T01 和 T02 的重叠最大。** 它们的卡片 Jaccard 是 0.75，因为都依赖 C2（lr 碗）。但两者的失败落在不同的对手上：T01 落在 `B2_notebook_allcards`（只用笔记对角线数据拟合），T02 落在 `B2_doc_range_only`（照抄文档范围）和 warmup 族。所以在"错成什么样"这个层面，它们考的是不同的东西。
- **障碍的实际多样性低于 6/10 这个数字。** O5（不可辨识）出现在全部 4 个蓝图里，因为 G7 要求每个实例都有一道"无知题"。O9 出现在 3 个里。只出现在单个蓝图里的是 O2（T03）和 O7（T07）。
- **失败高度集中，而且两个前沿模型的难点几乎不重叠。** 27 个前沿模型数值题失败中：
  - GPT-6 有 10 个：T02 5 个（其中 4 个是 q2），T03b 3 个，T07 2 个，T01 0 个；
  - fable 有 17 个：T01 10 个，T02 2 个，T03b 2 个，T07 3 个；
  - 正常预算的 T03 上，两个模型都没有失败。

  跨模型复现过的难点只有 T02 q2 一个。所以本轮能说的是"每个模型在不同的考点上被卡住"，还不能说"这 4 个考点对前沿模型普遍都难"。

**下一步最能增加异质性的蓝图**（候选，本轮没有做）：

| 候选 | 机制卡 | 障碍 | 预期难点 |
|---|---|---|---|
| batch × lr 交互 | C3, C2 | O6 | 在一个 batch 上调出的 lr 在另一个 batch 上不适用，笔记里 batch 从没变过 |
| 涌现是指标伪影 | C8 | O4 | exact-match 的"突变"其实是逐 token 概率的幂次，换成连续指标就是平滑的 |
| 挑最好种子 | C10 | O8 | 团队从很多种子里挑最好的那个报告，小改动的"收益"其实是赢家诅咒 |
| 混合配比聚合 | C6, C7 | O10 | 汇总后的消融结论与每个数据源内部的结论相反 |

T05 的教训（第 5 节）同样适用于这些候选：障碍必须在抽到的世界里真的生效，而且要在 2T 的击杀余量以外生效，否则闸门会拒收。

## 7. 已有 benchmark → 机制图映射

你提议把已有 benchmark 映射到"机制图"上：隐藏了什么、难在哪里、干扰是什么，再决定借鉴什么、在哪里拉开区分。我们调研了下面这些与"实验 → 推断"最接近的工作。表中数字来自各论文的摘要或正文，均为我们检索时的读数，没有独立复现。

**映射表**

| Benchmark | 隐藏节点 | 难度来源 | 干扰 / 捷径 | 在 ScaleLab 里的对应 |
|---|---|---|---|---|
| **SLDBench**（ICLR 2026，arXiv 2507.21184） | 真实文献实验背后的 scaling law 符号形式 | 从 5000+ 条文献实验（7–8 个任务）外推到更大尺度，用 held-out 大尺度的 R²（截到 [−1, 1]）打分。SLDAgent + GPT-5 0.748，人类 0.517 | 记忆：数据和 law 都来自公开文献；没有"真生成律"，只能拿拟合优度打分 | C1 + O9，但没有 O1（笔记混杂）这类观测结构障碍 |
| **SL2**（arXiv 2604.22753，代码 PlanarG/active-sl） | 同一族 law 的常数 | 预算约束下的序贯实验设计。8 个任务、65 个 scaling-law 实例，最大化 V-optimality，约 10% 预算就接近全量拟合 | 函数形式已知 | 相当于我们的 H2 提示级：给了精确函数形式以后，设计就成了例行公事 |

| **CLadder / Corr2Cause** | 文本里的因果结构 | 静态因果问答 | 已接近饱和（CLadder 从约 70% 到约 95%） | 促使我们只做交互式、带预算的题 |

**我们借鉴了什么**

- **SLDBench → 任务形态和导出格式。** "从小尺度实验外推到大尺度"是 AI4AI 里最自然的推断任务。SLDBench 有 Harbor 适配器，我们的导出也按 Harbor 目录格式来做（第 2.4 节）。
- **SL2 → "难度不在设计本身"。** SL2 显示函数形式已知时，序贯设计用很少预算就够了。这和我们的 H2 结果一致：给了函数形式，fable 7/7，GPT-6 重跑 6/7。所以 ScaleLab 的难度放在观测结构上（障碍模板），不放在预算分配上。紧预算变体的结果也支持这一点：只收紧预算，GPT-6 在 T01b 上仍然全对；T03b 掉分，是因为紧预算下要分离两个互相掩蔽的效应（O2），难点仍然在观测结构上，而不在预算怎么分。
- **NewtonBench → 反事实常数 + 噪声。** 每个蓝图都有必须被击杀的 `B0_textbook` 对手，常数重新抽取；C10 是随模型大小变化的异方差种子噪声，容差由 oracle 的重复实验校准。
- **CausaLab、CausalGame → "答对不等于理解"和"泄漏会虚高分数"。** 前者对应我们的 G9 负载检查和失败归因，后者对应 G6 泄漏闸门和"沙箱里只有占位符 key"的运行框架。
- **BoxingGym、DiscoveryWorld → 多维评分**。我们只保留了能机械判分的维度，没有引入解释质量这类需要 LLM 评审的维度。

**我们与它们的区分**

1. **有真生成律，答案是精确的。** SLDBench 只能用拟合优度打分；我们的世界是有文献出处的机制卡拼起来的，每道题的 key 从无噪声世界直接算出。
2. **难度来自有缺陷的前期笔记。** 已有工作的难点主要是"隐藏的函数形式"或"隐藏的因果图"。我们的难点是"团队的旧实验在结构上会误导你"：混杂、掩盖、截尾、checkpoint 混淆、尺度迁移。障碍模板库 O1–O10 就是对这类观测结构的枚举。
3. **"不知道"是一种可证明正确的答案。** set 和 undetermined 题的正确性由 G4 可辨识性证书保证（未知量在可跑区域内零足迹）。已有工作几乎都只考"估出来"，不考"证明估不出来"。
4. **一部分失败能定位到具名捷径。** 每个错答都会被映射到最近的对手或标为精度型/未归因（第 4.3 节）。这让我们能说"GPT-6 两次都退回到照抄文档范围"，而不只是"GPT-6 得了 0.57"。

## 8. 局限

**统计**

- **大部分格子只有单次运行。** 只有 T02 ws2 做了重复（fable、GPT-6 各 2 次 H0，GPT-6 2 次 H2）。重复之间的波动很大：GPT-6 在 T02 ws2 H0 上从 0.57 到 0.86，H2 从 0.00 到 0.86。第 4.2 节的汇总是每个任务第一次 H0 运行的单次抽样。
- **1.0–1.6T 的精度型失败是边界情况。** 容差放到 1.5T，GPT-6 全对任务从 7/12 变成 8/12；放到 2T 变成 9/12（第 4.2 节）。所以"GPT-6 5/12 没全对"里有一部分是容差定义的问题，不是能力问题。
- **T07 q2 的容差偏松**（ws1/ws3/ws4 分别是 0.029/0.037/0.013），而且 ws3 上 q2 只击杀了 `widen_points`。T07 q2 上的"弱匹配"不能当证据用。

**运行框架**

- **时间片约束。** 宿主单次工具调用约 178 秒封顶，agent 按约 158 秒的时间片推进。GPT 系连续两次超时就降到 medium effort，有 3 次运行因此是 high/medium 混合（第 4.1 节，每次运行的 `state.json` 里有 `calls_by_effort`）。
- **`SLICE_NEED_CAP` 是中途补的，只作用于 GPT 系。** t03ws28 GPT-6 有一次调用用了 142 秒，之后"下一个时间片需要的时长"超过了任何时间片能给的，空转了 4 个时间片。我们在 `gpt_agent.py` 里加了上限（默认 140 秒）后它继续推进。这个修复没有改变 agent 的其他行为，但补丁前后的运行不是完全同一套代码。
- **sonnet-4.6 活锁。** 它走 `cc_agent.py`，没有 `SLICE_NEED_CAP` 这类机制。从第 29 轮起单轮思考连续 20 多个时间片都没完成，34 次 run 后中止，记为 `aborted_livelock`，不计分。要让 CLI 类 agent 可靠地跑完，需要更长的时间片或真实的容器环境。
- **agent 可靠性本身是噪声源。** GPT-6 H2 首跑在没写答案的情况下主动退出（任务说明里没有提到时间窗口）。"满提示仍失败"里混着这种噪声。
- **没有在真实 docker / Harbor 上跑。** 阿里云服务器从本环境的 VM 无法连通，所以本轮全部运行都在 VM 内的 bwrap 沙箱里完成。导出目录是 Harbor 风格，但没有经过 Harbor 实际加载。我们没有在该服务器上做任何操作。

**题目**

- **T01/T03 的手册里"已知未知量"的说明文字是旧版。** 这 7 个实例（含 T01b、T03b）写的是"lo/hi 是该未知量在文档范围上的最小值和最大值"；T02/T07 写的是新版"在文档范围内、且与实验室可测结果一致的取值上的最小值和最大值"。T01/T03 的未知量在可跑区域内零足迹（G4 证书），两种定义给出同一个区间，所以答案不受影响。但文字确实不一致。用今天的代码重新构建 T01 ws1 和 T03 ws11，与发布版相比只有这一处不同：旧版的 1 行说明被新版的 2 行替换（`diff` 输出 `51c51,52`，第 9 节）。
- **手册里的通用示例带了 `lr`。** 所有任务共用的命令帮助里有一行 `lab run N=6e7 D=1.5e10 lr=0.002 seed=3`，而 T03 和 T07 并没有 lr 这个旋钮。这不构成泄漏（G6 检查过），但对 T03/T07 是一处不准确的说明。
- **对手的完备性是人写的。** 失败归因只能找到有人事先写下的捷径。27 个前沿模型数值题失败里有 10 个是未归因的，T03b 的 5 个全在其中。
- **强归因里有一半指向 INFO 对手。** 前沿模型的 6 个强归因中，3 个落在闸门不强制击杀的 INFO 对手上（T01b 的 `B2_notebook_allcards` 两次，T07 的 `B3_linear_in_lr` 一次）。这些匹配本身成立，在这两个实例里这两个对手也确实在相应题上被击杀了（见各任务的 `review_card.md`），但这是抽样结果，不是闸门保证。所以"模型掉进了一个闸门保证会错的捷径"这种说法，只对 T02 q2 上的 must-kill 对手成立。另外，INFO 对手里有的在部分实例上能拿满分（T07 的 `B4_cosine_grid_full_law` 在 ws1、ws3 上都是 1.00），说明这些实例存在不需要完整机制也能全对的合法做法。
- **推测没有读轨迹验证。** 例如第 4.4 节里对 fable 在 T01 上失败原因的推测（分析阶段没用上自己的离对角数据），只有账本统计支持，没有逐步读轨迹。

**覆盖与声称范围**

- 已发布的只有 4 个蓝图；O4、O6、O8、O10 未覆盖；C3、C5、C8 未使用；T05 被拒收。
- 声称范围只限于**模拟的预训练实验室**里的 scaling、稳定性、数据、调度实验。没有验证外部效度，也不代表"AI 研究"整体。

**安全**

- API key 只存在本环境的 `.sec/` 里，只由宿主侧的回环网关持有，沙箱里只有占位符。发布物、报告、记忆、桌面副本都做了密钥扫描（第 9 节）。**建议在本轮结束后轮换这把 key**，因为它曾出现在对话里。

## 9. 复现与核查

**依赖。** Python 3 + numpy。运行 agent 还需要 bwrap、Claude Code CLI（跑 Claude 系）和一个能访问模型 API 的密钥目录。构建和判分不需要任何模型调用。

**命令**（都在 v3 根目录执行）

```bash
# 构建：从 ws_from 到 ws_to 逐个种子构建 + 过闸门；--want K 表示导出前 K 个通过的实例
# 每个尝试过的种子（无论通过与否）都写进日志，产率和拒收原因可查
python3 -m scalelab.suite <blueprint> <ws_from> <ws_to> [--want K] [--out DIR] [--log FILE]

# 异质性报告（第 6 节）
python3 -m scalelab.hetero > docs/heterogeneity.md

# 发起一次 agent 运行（hint 必须是整数 0/1/2）
python3 harness/launch.py <task_dir> <cc|gpt> <model> <hint> <run_name> [effort]

# 推进所有运行中的 agent 一个时间片；网关和实验室服务在这个进程内启动，随它退出
SEC_DIR=<密钥目录> timeout 172 python3 harness/drive.py 158 [run_dir ...]

# 判分与失败归因
python3 harness/grade_runs.py [out.jsonl]
LAB_RUN_ROOT=runs python3 harness/attrib.py
```

`LAB_RUN_ROOT` 默认是 `/tmp/v3/runs`。随报告附带的 `runs/` 是整理过的运行证据，把它设为 `LAB_RUN_ROOT` 就能直接重新判分和归因。

**运行证据 `runs/`**

每次运行保留：`state.json`（agent 状态、调用次数、effort 分布）、`instruction.md`、`lab_ledger.jsonl`（服务端账本）、`tick.log`、`traj.jsonl`（GPT 系轨迹）或 `cc_stream_*.jsonl`（Claude 系流），以及 `app/` 里 agent 写下的文件（`answers.json`、`lab_runs.jsonl` 和它自己的脚本）。

为安全起见，下列内容没有复制：

- `home/`：含 CLI 会话文件和 shell 快照；
- `sbx_tmp/`：沙箱临时目录；
- `lab.json` 里的实验室令牌：替换成了 `redacted`，`task_dir` 改成指向 `tasks/` 的相对路径。
