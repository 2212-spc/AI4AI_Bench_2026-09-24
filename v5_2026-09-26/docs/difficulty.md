# 难度机制：从五个失效的杠杆到一条可测的定律

> v5，2026-09-26。本文回答用户要求 1：**探索难度机制 —— 什么样的题目是难的、需要考察什么能力、如何造出匹配的题目。**
> 文中每个数字都来自 `exp/` 下的可复现脚本，JSON 证据与脚本同目录。没有一句是推测。

---

## 0. 结论先行（三句话）

1. **难度必须被定义成"最近的捷径离真值多远"**，而不是"推理链多长"。定义为
   `B = min over routes |route(world) − truth(world)| / T`。

2. **B 的构造公式已被实测**：

   ```
   B  =  bias_geom / (2.25 · κ · σ/√n)
   ```

   其中 `bias_geom` 是捷径的几何偏差，`κ` 是**参考估计量（oracle）自身的条件数**，`σ` 是测量噪声，
   `n` 是买来的 run 数。四次受控 sweep 把两个指数都测出来了：`d log B / d log σ = −0.93`（理论 −1），
   `d log B / d log n = +0.48`（理论 +0.5）。

3. **两个"显而易见"的难度旋钮是错的**：把目标推到量程之外（reach）、把响应曲线弄得更弯（curv）。
   两者都能把几何偏差抬高 4–7 倍，但 B 反而下降，因为它们同时摧毁了 oracle 的条件数 κ。
   **正确的法则是反直觉的：好的难题要求 oracle 本身"好条件"（κ≈1：只内插、只求平均、只做匹配比较），
   把非线性留给捷径，不要留给答案。**

4. **这条法则已经造出了第一道题**（§6）：`s01-mix-p99`，18 道门在 15 个世界种子上全绿，
   **B = 15.8–27.6**，而 v4 最好的同实验室题目在任何预算下都过不了 B≥3。
   建构过程里又掉出两条新结论：**ρ 是 oracle 精度的影子**（§6.1），
   以及**没有一道门在测"诚实答案会不会免费"**（§6.2）。

## 1. 为什么必须重做：v4 的五个杠杆有四个不咬人

v4 声明了五个难度来源，并在 20 次前沿模型 run 上做了测量。结果是 **18/20 通过**，而且：

| v4 声明的难度杠杆 | 预测的失败数 |
|---|---|
| 推理链深度 depth | 0 |
| nuisance 机制个数 | 0 |
| 反直觉先验落差 anti-prior | 0 |
| 预算紧张度 | 0 |
| （唯一咬人的）估计路径错误 | 2 |

唯一真正区分了两个前沿模型的题是 `e05` 的 q2：gpt-6-astra 两次都低了 **4.16 / 4.06 个容差**，
fable-5-1 只差 0.1 / 0.6。它的失败原因五个杠杆一个都没说出来 —— 模型买了一个**斜率**然后乘上距离：

> 原话（run ledger）："approximately 0.001 proxy units per token at the proposal's distance"

这不是"链条不够深"，这是一条**路线（route）**：一个用给定实验室真能执行、会返回一个数、而那个数是错的程序。
难度的正确定义因此只能是"离最近的错路线有多远"。这就是 `scalelab/routes.py`：把路线族从
`Estimand` 声明里**机械枚举**出来，而不是靠人手写清单（v4 的清单被一次 run 找到了洞）。

路线族：R0 先验常数、R1 读最近可买点、R2 读最极端点、R3 局部斜率线性化、R4 最宽割线线性化、
R5 两点外推、R6 幂律拟合、R7 在均值处求值（Jensen）、R8 假设已饱和；外加蓝图手写的结构族
（`skip:` 漏步骤、`naive_ignore:` 忽略机制卡、`B_prior` 背书面值）。

## 2. 四次 sweep：难度从哪来

全部在 `e05` ws=2 q2 上做（真值 0.392261，抽到的 `sl`=161.7，`sig_proxy`=0.01，容差地板 0.010，
`MAX_RUNS`=130），每行 24 次独立噪声抽样。脚本 `exp/sweep_B.py`，四个 `--knob`。

容差的定义是 `T = max(floor, 2.25 × p90(oracle 误差))` —— **分子分母来自同一个世界**，
所以一个旋钮只有在"抬分子比抬分母快"时才真的加难度。这正是四次 sweep 要测的东西。

### 2.1 reach（把目标推出量程）—— 失效

把长度惩罚网格整体缩放，目标（零距离极限）相对更远：

|-----|--------|--------|-------------|--------|-----------|----------------------|
| 1.00| 8.00   | 0.725  | 0.0290      | 0.0652 | **0.90**  | 5.84 |
| 0.70| 5.60   | 0.648  | 0.0470      | 0.1058 | **0.96**  | 10.12 |
| 0.50| 4.00   | 0.568  | 0.0883      | 0.1987 | **0.76**  | 15.07 |
| 0.35| 2.80   | 0.479  | 0.2554      | 0.5747 | **0.36**  | 20.40 |
| 0.25| 2.00   | 0.397  | 0.5405      | 1.2160 | **0.20**  | 24.80 |
| 0.17| 1.36   | 0.309  | 1.4220      | 3.2010 | **0.09**  | 28.65 |

### 2.3 noise（正交性测试）—— 这不是难度提案，是**诊断**

几何完全不动，只缩放测量噪声本身：

| ×σ   | p90    | T_cal  | **B_cal** | B_floor |
|------|--------|--------|-----------|---------|
| 4.00 | 0.1233 | 0.2774 | **0.21**  | 5.84 |
| 2.00 | 0.0553 | 0.1245 | **0.47**  | 5.84 |
| 1.00 | 0.0290 | 0.0652 | **0.90**  | 5.84 |
| 0.50 | 0.0135 | 0.0304 | **1.92**  | 5.84 |
| 0.25 | 0.0097 | 0.0218 | **2.68**  | 5.84 |
| 0.125| 0.0028 | 0.0100 | **5.84**（撞地板）| 5.84 |

**d log B / d log σ = −0.93**（理论 −1）。判决：*noise-limited, B is buyable*。

> 这条 sweep 推翻了我自己前一版的诊断。我先以为"oracle 和捷径一起失效，B 有 O(1) 天花板"；
> −0.93 说明分母确实是噪声主导的，真正的机制是 reach/curv 破坏了非线性拟合的**条件数**，
> 把 σ 放大成了 p90。错误诊断被实验替换，而不是并列保留。

**这条测试值得单独保留成机械诊断**：固定几何、缩放 σ、拟合斜率。
≈ −1 → 噪声主导，B 可以用 reps 买；≈ 0 → 余项主导，B 有天花板，**要换估计量而不是换几何**。

### 2.4 reps（pipeline 自己能转的旋钮：给 oracle 买重复）

| ×    | p90    | T_cal  | **B_cal** | n_runs | ρ=n/预算 |
|------|--------|--------|-----------|--------|---------|

| 16.0 | 0.0084 | 0.0188 | **3.11**  | 1408   | 10.83 |

**d log B / d log n_runs = +0.48**（理论 +0.50）。于是有了 v4 的判决：

> 从 88 runs 的 B=0.90 走到 B=3.0 需要约 **987 runs**，而这道题的全部预算是 **130 runs**。
> **v4 最好的那道区分题，结构上就付不起 B=3。**

这不是调参问题。这是题族问题。

## 3. 判决实验：κ 就是价格（`exp/kappa_demo.py`）

要证明"换题族"能解决，必须做一个**只差 κ 的对照**。两道题放在同一个实验室（servelab 的 S4 卡，
Pollaczek–Khinchine M/G/1 排队）、同一个测量噪声（`sig_lat/√(dur/20)` 对数正态）、同一个 run 预算、
同一个 1% 报数地板。世界：`cs2=2.9931`，`E[S]=44.71 ms @ batch=32`，饱和速率 22.37 req/s。

* **题 A「饱和速率」**（外推 + 反解，κ≫1）：p99 何时越过 900 ms SLO？
  实验室只卖到利用率 0.55，答案落在 ρ\*=0.628（超出量程 **仅 14%**）。
  oracle 必须在曲线平缓段拟合排队公式的两个自由常数再反解外推。

* **题 B「混合流量 p99」**（聚合，κ=1）：给定流量配比（ρ = 0.25/0.40/0.55/0.70/0.82/0.90 等权），
  平均 p99 是多少？每个桶实验室**都卖**。oracle 逐桶买、求平均。没有拟合、没有外推、没有反解。

同样 24 runs 的结果：

| 题 | 参考估计量 | runs | 真值 | T | T/真值 | **B** | 最近捷径 |
|---|---|---|---|---|---|---|---|
| svc.sat_rate | 外推+反解 | 24 | 14.0481 req/s | 0.2797 | 1.99% | **1.31** | R3:local_slope |
| svc.mix_p99  | 聚合      | 24 | 1446.68 ms    | 31.649 | 2.19% | **8.22** | R6:loglinear |

同实验室、同噪声、同预算，**B 差 6.3 倍**。

再把两道题放到同一条精度阶梯上（`--sweep`），κ 就从"说法"变成"价格"：

| reps | runs | A p90 | A T | **A B** | B p90 | B T | **B B** |
|---|---|---|---|---|---|---|---|
| 1 | 6   | 0.3235 | 0.7278 | 0.50 | 22.78 | 51.26 | 5.07 |
| 2 | 12  | 0.1253 | 0.2820 | 1.30 | 17.69 | 39.81 | 6.53 |
| 4 | 24  | 0.1243 | 0.2797 | 1.31 | 14.07 | 31.65 | 8.22 |
| 8 | 48  | 0.1159 | 0.2608 | 1.40 | 7.82  | 17.60 | 14.78 |
| 16| 96  | 0.0702 | 0.1580 | 2.32 | 5.50  | 14.47 | 17.98（撞地板）|
| 32| 192 | 0.0449 | 0.1405 | 2.61（撞地板）| 4.60 | 14.47 | 17.98 |

```
item A: d log B / d log n = +0.45   B = 3 需要 173 runs   （容差地板把 B 封在 2.6）
item B: d log B / d log n = +0.50   B = 3 需要   2 runs   （容差地板把 B 封在 18.0）
B=3 的价格差 73 倍 = κ²，κ ≈ 8.6
```

两条曲线在 log-log 上是**斜率同为 +1/2 的平行线**，垂直间距就是 log κ。这正是第 0 节公式的形状。

### 最锋利的一条

```
              捷径偏差    占真值    1% 地板 T    B 的天花板
svc.sat_rate   0.3664      2.6%      0.1405        2.6
svc.mix_p99  260.0854     18.0%     14.4668       18.0
```

**题 A 的天花板是 2.6 < 3：任何预算都不能让它变难。** 因为它最近的捷径只错 2.6%，
而答案本身只能报到 1% 精度。这不是"贵"，这是**不可能**。

### 为什么这两个因子总是同向（反直觉的那一半）

一次**温和**的外推（超出量程 14%）捷径偏差必然小 —— 捷径在那儿本来就差不多对，
这恰恰是外推"感觉上很难"的原因；而一个跨越凸性爆炸的 Jensen 缺口偏差必然是 O(1)。
于是 **κ 和 bias 一起往同一边倒**：

* 外推题：bias 小、κ 大 → B 双重被压。
* 聚合题：bias 大（18%）、κ=1 → B 双重被抬。

**"外推才是难题"这个直觉，对造 benchmark 来说是完全相反的。**
v4 的障碍模板 O3（机制超出观测范围）、O17（不可达配置）正好就是 κ≫1 那一族 ——
v4 把难结构放进了**障碍**、把外推放进了**被估量**；v5 必须把这两者对调。

## 4. 设计法则：什么样的题目是难的

> **好的难题 = 好条件的参考估计量（κ≈1：只内插 / 只求平均 / 只做匹配比较，绝不外推）
> + 一个由独立世界常数控制的 O(1) 捷径偏差。**

已经识别并验证/待建的三个 κ≈1 题族：

| 题族 | oracle 做什么（κ=1 的理由） | 捷径是什么 | 偏差由什么世界常数控制 | 状态 |
|---|---|---|---|---|
| **Jensen / 聚合** | 直接买每个桶，加权平均 | R7:plugin —— 在均值处求值（"按平均负载算"） | 配比的离散度 × 响应的凸性（排队：`cs2`、利用率跨度） | **已验证 B=8.2–18.0** |
| **去混淆 / 匹配比较** | 比较匹配好的两组，两边都直接可测 | 直接比较未匹配的组均值 | 混淆强度（一个自由抽的常数） | 待建（`sharp_vs_naive`，Manski 部分识别） |
| **内插型反函数 / 积分** | 在网格**内部**内插或数值积分 | 用端点斜率线性化、或幂律外推 | 被积函数的曲率（在网格内部，不在外面） | 待建（6 条既有物理定律） |

三族的共同点：**答案需要的每一个量都在实验室的量程内**，难的是**知道要买什么、怎么组合**，
而不是"把测不到的东西猜出来"。后者只会同时放大偏差和方差。

反过来，**不要造的题**：

* 任何 oracle 必须外推/反解非线性拟合的题（κ≫1，B ∝ √预算，经济上不可达）；
* 任何最近捷径只错几个百分点的题（B 天花板 < 3，任何预算都救不回来）；
* 任何靠"链条长"、"nuisance 多"、"反直觉"来声明难度的题 —— v4 已经证明这三样预测不了任何失败。

## 5. 一个必须讲清的区分：B 是**区分度**旋钮，不是**难度**旋钮

这是本轮最容易误用的结论。把 σ 降低或者给 oracle 买重复，**并没有让诚实路径变难** ——
诚实估计量的误差也随 σ 缩放。它做的是让**不诚实路径可被检出**。

所以难度是三维的，B 只占一维：

| 维度 | 含义 | 由什么控制 | 门 |
|---|---|---|---|
| **D** 设计难度 | 估计量需不需要被**发明**出来？（要不要想到"必须逐桶买再平均"、"必须重新规划 batch"） | 题面与机制卡的结构 | G11 深度 / 能力轴 A1–A8 |
| **ρ** 可负担性 | 诚实方案的 run 数 / 预算，目标 0.6–0.8 | caps 与 oracle 计划 | 预算校准 |
| **B** 区分度 | 最近捷径离带外多远，目标 ≥ 3 | `bias_geom / (2.25 κ σ/√n)` | **G18** |

`svc.mix_p99` 的 B=3 只要 2 runs，说明它的**区分度是免费的**，但它的 D 不是免费的：
S4 卡写明"利用率不是旋钮"—— ρ = rate × E[S]，而 E[S] 由 batch 决定，
所以高负载桶在默认 batch 下直接返回 `status: unstable`，
agent 必须自己重新规划 batch，而加大 batch 降低 E[S]（降 ρ）却抬高单请求时延。
这层设计难度和 B 正交，要单独计。**G18 只保证题目能区分，不保证题目需要本事；两件事分开度量。**

## 6. 第一道按这条定律造出来的题：`s01-mix-p99`

前面五节全是**测量和否证**。这一节是**建构**：`scalelab/bp/s01_mix_p99_jensen.py`
是第一道不是"先想题面再算难度"、而是**先定 κ≈1 的被估量、再把题面围着它写**的蓝图，
落在 §4 表格的第一族（Jensen / 聚合）上。

被估量：六个租户各自经历的 p99 端到端时延，**在租户上等权求平均**。
不是合并流量的 p99（那是另一个更大的量，题面里明确排除）。
每个租户是独立的 M/G/1，`util` 在 servelab 里是精确读数，
所以 E[S] 和每个 ρ 都免费，**唯一要花钱买的是 `cs2`（服务时间的变异系数）**，
而 `cs2` 线性地进入 E[T] —— oracle 是一个**逆方差加权平均**，κ=1。

三道题，三个考察方向，共享同一个世界常数：

| 题 | 形式 | 考什么 | 实测 |
|---|---|---|---|
| q1 | point | **被估量识别**：凸函数下 Jensen 不等式，"按平均负载算"错 20–50% | **B = 15.8–27.6** |
| q2 | set | **部分识别**：只在文档给出的增长带上报区间，不许坍缩成点 | 带宽 **14.4–19.1 T** |
| q3 | decision | **可行性筛查**：预留 KV 池能否装下整条生产上下文（S5），与开发机的 `batch_max` 无关 | regret gap **398–1129 ms** |

结果：18 道门在 **ws=0..14 共 15 个世界种子上全绿**，`ver_allpass = 1.0`，
T = q1 真值的 **1.18–1.20%**，`G17_oracle_bias` 比值 0.468（限 0.90），
`G13_anti_prior` 的 `gap_over_T = 33.42`。
对照：v4 最好的 servelab 题（外推型）**在任何预算下都过不了 B≥3**，
因为它的捷径偏差只有真值的 2.6%，而 T 的地板是 1% —— 天花板 2.6 < 3。
这道题是"B≥3 这条门槛不是空的"的存在性证明，也是 G18 上线的前提。

### 6.1 新发现：**ρ 不是由 caps 决定的，是由 oracle 自己的设计决定的**

这条在 §5 的三维表里补了一个之前没说清的因果方向。
`calibrate` 用 `T = 2.25 × p90(oracle 误差)` 定容差，所以 **oracle 越精确，T 越小，
而 T 越小，诚实路径就必须买得越多才够用** —— ρ（可负担性）不是独立旋钮，是 oracle 精度的影子。

具体地，每一行 `load` 关于 `cs2` 的信息量按 x = ρ/(1−ρ) 放大。
把同样的钱从"六个桶平摊"改成**只买 ρ 最高的三个桶、并且买长时段**
（`OR_IDX=(3,4,5)`，`OR_REPS=4`，`OR_DUR=30`），花费不变，但：

| | T（占真值） | B | 参考方案占成本上限 |
|---|---|---|---|
| 六桶平摊 | 2.42–2.46% | 7.7–14.2 | ~0.20 |
| 三个最忙的桶买长 | **1.18–1.20%** | **15.8–27.6** | **~0.72** |

**让 oracle 更精确，是同时抬高 B 和让预算真正咬人的那个杠杆。** 一个动作，两维都涨。

### 6.2 新发现：免费读数是一个必须在建题时封掉的洞

第一版把 notebook 自带的 `load` 探针设成 `dur=20` × 3 次重复。
算了一下：一个推导全对的 agent **不买任何 run**，误差就到真值的 ~1%，而 T ≈ 1.7% ——
**q1 可以零成本做对**，18 道门没有一道会发现。
改成 `NB_DUR = 5.0` 后自由路线的误差是真值的 9.0–10.0%，即 **7.4–8.4 T**，洞封上了。

教训是通用的：**门测的是"捷径会不会错"，没有一道门测"诚实答案会不会免费"。**
这直接变成待办里的 **G20 no_free_readout** —— 建题时对 notebook 公开数据做一次二分攻击，
算出自由路线的误差下界，要求它 ≥ 某个 T 的倍数。

### 6.3 两条被否证的"难点"，记录在案

* **servelab 的 roofline 开关（S1）在生产上下文长度下是惰性的。**
  `service_time` 的 prefill 项确实还带着 `P_peak` / `prefill_flop_eff`，
  但 S1 这张卡真正命名的那个机制（memory-bound / compute-bound 的**切换**）在这个量程里不会翻转：
  `kv_per_token × seq / BW > 2N / (P_peak × eff)` 恒成立。
  所以这道题**不声明 S1**，并在 `_admissible` 里把这个不等式写成硬约束，
  确保将来重抽常数时不会悄悄把一张惰性卡算进覆盖率。
* **在 batch 轴上，"队列稳定性"不可能是决策的紧约束。**
  E[S] 随 batch 单调下降，于是每个租户的 ρ = rate × E[S] 也随之下降 ——
  **队列不收敛的那个选项（menu[0]，前三个租户 ρ > 1），必然同时是服务时间最长、损失最大的选项。**
  任何"跳过稳定性检查"的捷径都不可能因此选错，除非它同时把服务时间也算错，
  而那已经由 `skip:service` 覆盖了。
  所以 q3 的 `chain` 只声明 `["pool"]`，`skip:stability` 登记为 `INFO_RIVALS`。
  这一条是 **G11 抓出来的**：它先报 `steps_without_a_killed_shortcut: ["q3/stability"]`，
  逼着把纸面深度改成实测深度 —— 正是这道门存在的理由。

## 7. 落到 pipeline

1. **G18 difficulty_floor**：每道数值题 `B ≥ 3.0`，且路线普查 ≥2 个数值族 + ≥1 个结构族
   （B 是一个集合上的最小值，集合大小为 1 的最小值只是对一次猜测的断言）。
   已知：**裸的 B≥3 会直接否掉 v4 最好的题** —— 所以 G18 必须和"选 κ≈1 的被估量"这条建构路径成对出现，
   否则它只是一个否决器。
2. `certify(..., reference=(...))`：聚合题的参考估计量**就是** `R7:average`，
   不排除它会让唯一 B 最大的题族报 B=0。排除口开得很窄：写进 `reference` 等于声明
   "执行这条路线需要本题要考的那个推导，并且要花 run 去买"。
3. **正交性测试进 cert**：每道题记录 `d log B / d log σ`。≈0 的题标记为 remainder-limited，
   直接退回改被估量，不允许靠加预算硬拉。
4. **B 的天花板进 cert**：`bias_geom / floor_T`。天花板 < 3 的题在**建题时**就拒掉，不要等 sweep。
