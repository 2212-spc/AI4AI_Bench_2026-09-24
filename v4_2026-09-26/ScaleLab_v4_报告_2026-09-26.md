## 0. 一页结论

**交付物。** 4 个实验室（`pretrain` / `evallab` / `rllab` / `servelab`）、5 个新蓝图（e01–e05）、15 个已导出实例、63 个 item、7 种答题形式、32 张机制卡（83 条文献锚点）、**18 道构建门 G0–G17**（本轮新增 G11–G17）、17 个障碍模板（本轮新增 O17）。

**验证规模。** 24 次真实前沿模型运行：gpt-6-astra 与 claude-fable-5-1，每格 2 次重复，全部用**出货的那份 grader**（子进程调 `tasks/*/tests/grade.py`）评分。20 次全对，4 次失败。

**本轮的核心是一个否证：用户选定的三个难度杠杆全部不绑，我新加的第四个也不绑。**

| 杠杆 | 怎么加的 | 实测是否绑 |
|---|---|---|
| 反先验常数 | e04 q1 声明 51.09 T 差距；e05 q1 声明 **340.61 T** | ❌ 10/10 次运行误差 **0.00 T** |
| 推理链深度 | 声明 depth 3–4，G11 强制每步有被打死的捷径 | ❌ 同上 |
| 干扰机制数量 | 声明 3–5 张干扰卡，G12 强制每张有被打死的忽略基线 | ❌ 同上 |
| **不可达配置（O17，本轮新增）** | e05 q5 问 `steps=2160`，knob 上限 1000，请求直接被拒 | ❌ 4/4 次运行误差 **0.00 T** |
| **预算收紧** | caps 从参考解的 2.58× 收到 **1.37×** | ❌ 2 次用满 130 上限，仍全对 |

**唯一绑的是统计结构。** e05 的 q2 要求自己设计一个带噪声的估计量，并把一个饱和响应外推到买不到的点：

| e05-ws2 q2（真值 0.3923，T = 0.0433） | 第 1 次 | 第 2 次 |
|---|---|---|
| claude-fable-5-1 | 0.388 → 0.10 T ✅ | 0.42 → 0.64 T ✅ |
| gpt-6-astra | 0.2120 → **4.16 T ❌** | 0.2162 → **4.06 T ❌** |

错法已完整反查：gpt-6-astra 自己写"length effect ≈ 0.001 proxy units per token"——它用**能买到的最大 `len_pen` 处的 secant** 代替对饱和项到零距离的外推。解析复现该路线得 0.2183 = 4.02 T，与实测 4.16 / 4.06 T 吻合；两次重复偏低到同一处，是共享的**概念**错误而非噪声。

**难度定律（本轮主要产出）。**

> 只要被问的量在 lab 的可请求集合内**可测**，声明的深链 / 干扰 / 反先验都会被"直接测量"绕开。把它挪到**不可达**区确实能强迫推导发生——两个模型都写下了趋近律并反解了 best-of-n 恒等式——但当那条定律光滑、低维、且关键观测无噪声时，前沿模型能把它**精确**识别出来，难度不增加。**真正的难度来自：答案必须由一个需要实验设计的、有离散度的估计量得到，并且要把非线性响应外推或求逆到一个买不到的点。**

**本轮还发现并修掉了一个我自己造的评分缺陷。** 交付前重算证据时发现 e05 q5 的四次"0.44 T 误差"完全来自我的 key：匹配预算解出 2162.6907 而采样预算是整数，key 带着小数，于是**包括参考解在内**的每个正确答案都固定差 0.309。更糟的是容差规则 `tol = max(floor, 2.25·p90(参考解误差))` 把这个偏置变成了容差：band 从 0.5 涨到 0.696，44% 的判别区间被我自己的四舍五入吃掉。修法：key 取整；并新增 **G17 `oracle_bias`** 门——当参考解的误差是**偏置**而不是**离散度**、并且这个偏置**为自己买到了容差**时，构建失败。G17 上线后立刻在 v3 已交付的 `t02` 上查出第二例同类模式（正确判定为无害，见 §6.2）。

## 1. Q1：考查内容能不能更多样？机制来源是什么？

### 1.1 从 1 个域扩到 4 个域，32 张卡

| 前缀 | 域 | 卡数 | 本轮新增 |
|---|---|---|---|
| C1–C11 | 预训练 / scaling law | 11 | v3 已有 |
| E1–E8 | 评测方法学 | 8 | ✅ |
| R1–R7 | 后训练与 RL | 7 | ✅ |
| S1–S6 | 推理与服务 | 6 | ✅ |

用户未选的"数据与系统"域未实现，按选择执行。

### 1.2 机制来源是三层，不是一层

这是"机制来源于什么"的实质回答。83 条 `grounding` 引文不是同一类东西：

**(a) 有闭式且被独立复现的定律** —— 可以直接当世界的物理：Chinchilla 的 `E + A/N^α + B/D^β`（Hoffmann 2022 与 Besiroglu 2024 复现的两套常数都在卡里）；best-of-n 的 KL 恒等式 `log n − (n−1)/n`（Beirami 2024 定理 3.1，卡里注明它只在奖励分布绝对连续时**精确**，有并列时是上界）；M/G/1 的 Pollaczek–Khinchine 公式；roofline；投机解码的期望接受长度 `(1−a^(g+1))/(1−a)`；pass@k 无偏估计量。

**(b) 有文献报告但没有闭式的经验形状** —— 只能给**形状**，常数由世界自己抽：RLHF 的 KL-vs-steps 轨迹（Stiennon 2020 报告了轨迹但没给函数形式，且 β 系数跨 run 不可比——可比的是达到的 KL，这正是 e04/e05 q1 的题眼）；RM 过优化的 α/β（Gao 2023，α 跨 RM 尺寸近似恒定而 β 约对数下降）；长度偏置占 RLHF 奖励改善的 70–90%（Singhal 2024）。

**(c) 文献明确没有常数的地方** —— **不能**作为答案，只能作为 `known_unknowns` 或欠定性的燃料：污染检测器的斜率/截距/噪声；任何真实服务栈的"利用率–尾延迟"曲线；"更多数据让量化更糟"这个效应的符号在已发表拟合里是混淆的（数据量与训练后量化损伤共变），所以题目不许把任一方向当定论。

每张卡都写了 `Published numbers describe other worlds`，并在 manual 里对 agent 明示。这是 v2 的教训：一旦"查文献常数就能答"，它就退化成知识题。

### 1.3 4 个实验室，每个有自己的物理与计费

`spec["lab"]` 分派到 `scalelab/labs/<name>.py`。以 `rllab`（e04/e05 用）为例，全部物理在约 120 行里：

```
kl_of:   bon → log n − (n−1)/n ;  ppo → min(kl·(1 − exp(−steps/steps0)), kl_cap)
quality: d = sqrt(kl) ; bon → R0 + d(α − β_bon·d) ; ppo → R0 + d(α − β_eff·log d)
mean_len:     len0·(1 + λ·d/(1 + cl·len_pen))
proxy_reward: wq·α·d + wl·tanh((L − len0)/sl)
gold_wr:      sigmoid(kg·(quality − q_ref))
cost:  train → train_cost·sz·(steps/100 或 n/8) ;  gold → human_cost·gold_n/100
```

噪声：proxy sd 0.01、mean_len sd 4.0、entropy sd 0.01；**`kl` 的 sd 是 0**（结构量，6 位小数）。最后这一条是本轮否证的物理根源——见 §3.3。

## 2. Q2：题目形式能不能更丰富？

### 2.1 7 种答题形式，63 个 item

| 形式 | item 数 | 出现在 | grader 怎么判 |
|---|---|---|---|
| `point` | 27 | e01, e02, e04, e05 | 数值 ± 校准容差 |
| `interval`(set) | 9 | e01, e02, e03 | 端点误差 + 宽度门 G3 |
| `verdict` | 6 | e01, e03 | 分类 |
| `decision` | 6 | e04, e05 | 按**后悔值**判，不按标签；G8 保证选项间有真实间隔 |
| **`cex` 反例见证** | 6 | e02 | 把交上来的世界参数**重建成世界**，检验它是否同时符合被披露证据**和 agent 自己 ledger 里的每一行**，再判"可反驳/被蕴含" |
| **`prereg` 预注册方案** | 6 | e04, e05 | 把交上来的 ≤3 次运行和决策规则**在 3 个候选世界 × 12 个独立噪声盐里执行** |
| **`audit` 缺陷定位** | 3 | e03 | 行号命中 + 修正后数值落在带内 |

三种新形式正是用户选定的三种；未选的"策略程序提交（policy.py）"未实现。

按蓝图：e01 = point×3 + set + verdict；e02 = point + set + cex×2；e03 = audit + set + verdict；e04 = point×2 + prereg + decision；e05 = point×3 + prereg + decision。

### 2.2 为什么这三种形式不是"换个问法"

**CEX 的引擎是一对互为陷阱的障碍模板。** O11（欠定且有方向：被披露证据留了一条缝，第二个机制可以占进去，所以头条结论是**可反驳**而非错）与 O12（证据恰好把量钉住，那条诱人的反例**不存在**，诚实答案是"被蕴含"）。同一套题面下两种都会出现，所以"总能找到反例"这个先验会被罚。关键设计：见证必须同时兼容 **agent 自己刚跑出来的行**，这挡住"先编一个世界再说"的路线。实测见证空间体积占比 e02-ws1 q3 = 0.0263、q4 = 0.0（G14）。

**PREREG 的引擎是 O13（方案依赖性）。** e04/e05 的 q3：best-of-n 与 PPO 在同一 KL 下产生**完全相同的 proxy reward**（proxy 只是 `d = sqrt(KL)` 与 mean_len 的函数，而 mean_len 又只是 d 与 len_pen 的函数——方法根本不进入这个式子）。gold 胜率**会**不同，因为两者为距离付费的方式不同（`d²` vs `d·log d`），而谁更便宜取决于一个被披露 notebook **完全没有信息**的常数。于是 3 个世界同时与团队披露的一切一致，且对"该上哪个"给出 3 个不同答案。比 proxy 的方案在 3 个世界返回同一个数；买 gold 的方案能分开，但只有买够了才行。**预注册形式的全部意义在于 agent 不能先测后写规则。** 12 个盐（不是 3 个）是必须的：盐从 3 提到 12 后，`plan:underpowered`（gold_n=50）从 24% 概率蒙对变成几乎必败。实测参考方案的判别边际：e04-ws1 8.79 sd、e05-ws2 **13.07 sd**（G15 要求 ≥4）。

**AUDIT 的引擎是 O14 + O15。** 一段会跑通、不报错、结果看着合理的分析脚本，用一条推断上错误的路线算出一个可辩护的数（O14 静默缺陷）；同时埋一条"看起来同样可疑、改了却只动不到 1/4 容差"的红鲱鱼（O15），所以动它就是假阳性。实测真缺陷的影响 a1 = 22.83 T（G16 要求 >2 T，红鲱鱼 <0.25 T）。e03 的实测特征：**6 次运行里 5 次的 lab 调用数是 0，第 6 次是 1**——几乎纯代码/日志审计，不需要买实验，与 e04 的 79–240 次实验完全互补。

### 2.3 与 MLE-bench / RE-Bench 这一族的关系

这一族（MLE-bench、RE-Bench、PaperBench、MLGym）的任务是"把一个指标做上去"：可无限试错，grader 是分数。它们量化工程执行力。

ScaleLab 量化**另一件现实需要但没被量化的事**：在预算内做出一个可辩护的判断。差别具体化：

- grader 判**过程事实**而不是解证书——"你预注册的方案在所有仍然开放的世界里是否都能把结论分开"，而不是"你的数字是否等于我的数字"。
- **rival 邻域**是题目的一部分：每期实例必须证明一组机械捷径（跳某一步、忽略某张卡、用文献常数、用题面数字的几何/算术平均）全部被打死且至少 2 倍容差。e05-ws2 有 25 个 rival。
- 预算是硬的：`max_runs` / `total_cost` / `run_cost` 三重上限，超限是**拒绝**而非截断。

两者互补，不替代。本轮没做"把指标做上去"的任务——那需要真实训练栈，与"可大量生产 + 真值可证"冲突。

## 3. Q3：难度能不能更好管理？——主验证与否证实验

### 3.1 主验证：20 次运行

| 蓝图 | lab | 形式 | 声明 depth / nuisance / 反先验差距 | 结果 |
|---|---|---|---|---|
| e01-release-gap-ws1 | evallab | point×3, set, verdict | 3 / 3 / q4 = 4.32 T | 4/4 全对 |
| e02-spec-tail-ws1 | servelab | **cex**×2, point, set | 3 / 3 / q1 = 13.73 T | 4/4 全对 |
| e03-audit-headline-ws1 | evallab | **audit**, set, verdict | 4 / 5 / a2 = 100.15 T | 3/4 全对 |
| e04-matched-kl-ws1 | rllab | **prereg**, decision, point×2 | 4 / 3 / q1 = 51.09 T | 5/6 全对 |

- `e03ws1_fable51_H0r2`：a1 的修正值区间 `[0.389, 0.392]` 越出允许带 `[0.38876, 0.39176]`——缺陷定位对了，修正值差一点。

### 3.2 逐题边际：24 次运行的最大 err/T

| 实例 | 各 item 的 max(err/T) |
|---|---|
| e01-release-gap-ws1 | q1 **0.50**, q2 0.22, q3 0.28, q4 0.33 |
| e02-spec-tail-ws1 | q1 0.16, q2 0.16 |
| e03-audit-headline-ws1 | a2 0.01 |

### 3.3 诊断：为什么声明的杠杆不绑

e04 q1 声明 51.09 T 的反先验差距——题面 memo 用 `KL = log n` 且把自己的 `kl=` knob 读成实际达到的 KL，两个错误各自纠正一个仍得错答案，三个错答案都在几百倍容差之外。设计上这应该很难。

实测六次全部 0.00 T。ledger 给出原因：

1. `svc=train` 上报的 `kl` **没有噪声**；
2. 于是"哪个 n 达到同一 KL"退化成在一个已上报字段上的一维单调搜索；
3. `e04ws1_gpt6astra_H0` 的 177 行 ledger 里有 **133 行是 `method=bon`**（其余 44 行 ppo；按服务分是 171 次 train + 6 次 gold）——四分之三的实验预算花在对 best-of-n 做一维搜索上。

同一逻辑适用于 depth 与 nuisance：它们描述的是**作者打算走的推导**。G11 强制"每个声明的推导步都有一个被打死的 skip rival"，G12 强制"每张声明为干扰的卡都有 `naive_ignore:<卡>` 被打死"——**这些门保证声明为真，不保证题目难。** 这个区分是本轮最值得记住的一句话：**门是防作者自欺的，不是造难度的。**

### 3.4 e05：匹配对否证实验

只改两件事，其余全部继承 e04：

| | e04-matched-kl | e05-matched-kl-far |
|---|---|---|
| `steps` knob 上限 | 2000 | **1000** |
| q5（新） | — | **q1 的同一个问题，问在 `steps=2160`** |
| manual 是否明示 | — | "`steps` accepts [10, 1000] … 超限是**拒绝而非截断**" |
| caps（次 / 信用） | 240 / 20000 | **130 / 9000** |
| 参考解实测用量 | 93 / 6745 | 95 / 7106 |
| caps ÷ 参考解 | 2.58× / 2.97× | **1.37× / 1.27×** |
| 门 | 18/18 绿 | 18/18 绿 |
| 产出率 | 3/6 = 50%（ws 1–6） | **9/16 = 56%** |

**为什么 (q1, q5) 是一个干净的匹配对：** 同一实例、同一世界、同一套被披露证据、同一组可观测字段、同一种容差语义（都是"答出准确的整数 n"，容差都是 0.5 sample）、同一次运行里由同一个 agent 回答。唯一差别是 q1 问的配置可以买，q5 问的配置买不到。

**为什么不能共用 e04 的世界：** 试过。`WORLD_ID` 机制允许受控变体复用底座的世界/notebook/噪声盐，但 e04 的 notebook 里有一行 900 步的 PPO 运行而 `q_ST = 470`，所以不存在一个 `steps` 上限能同时**保留 notebook** 又**把被问配置放到不可达区**。e05 因此自己抽世界——代价是 e04↔e05 的跨题比较多了一个混淆项，而**题内**的 (q1, q5) 匹配对不受影响。这是本实验的主证据。

**结果：**

| e05-ws2 | q1（可达，T=0.5） | q5（不可达，T=0.5） | q2（噪声估计量，T=0.0433） | lab 用量 / 上限 |
|---|---|---|---|---|
| fable-5-1 #1 | 270 → 0.00 ✅ | 2163 → 0.00 ✅ | 0.388 → 0.10 ✅ | 110 / 130 |
| fable-5-1 #2 | 270 → 0.00 ✅ | 2163 → 0.00 ✅ | 0.42 → 0.64 ✅ | **130 / 130** |
| gpt-6-astra #1 | 270 → 0.00 ✅ | 2163 → 0.00 ✅ | 0.212 → **4.16 ❌** | 63 / 130 |
| gpt-6-astra #2 | 270 → 0.00 ✅ | 2163 → 0.00 ✅ | 0.2162 → **4.06 ❌** | **130 / 130** |

**O17 确实逼出了推导。** gpt-6-astra 的中间总结原文："the PPO law matches an exponential approach, and the matched sampling budgets are near the exact integer crossings `n=270` for the 945-step proposal and `n=2163` for the 2160-step continuation." 它识别出趋近律、外推、反解了 best-of-n 恒等式。

**但它完全没有增加难度。** 四次运行的 q5 误差与可达的 q1 一样是 **0.00 T**。结论只能是：当支配律光滑、低维、且关键观测无噪声时，"不可达"只改变**路线**，不改变**难度**。

**预算杠杆同样不绑。** 两次运行正好用到 130 上限（上限确实机械地绑住了），但两者都已收集够信息，答案不受影响。

## 4. 唯一起作用的杠杆，以及它给出的下一步

### 4.1 q2 的难点结构

q2 问：这个 PPO 配方的 proxy 增益里，有多大比例来自**长度项**而不是质量？真值 = `wl·tanh((L − len0)/sl) / proxy`。

三个结构性障碍叠在一起：

1. **团队的 sweep 只动了 KL 目标**，所以 mean_len 与 proxy 同涨同落，memo 把全部增益读成质量（O1 混淆 notebook）。
2. 唯一能在**固定 KL 下**移动长度的仪器是 `len_pen`；但它有上限 8.0，所以"纯质量极限"必须**外推**，不能在最大惩罚处读出（O3 区间外的 regime）。
3. 长度项要对着"**零距离时的长度** `len0`"算，而那不是 notebook 里最短的那次运行（O4 测量假象）。

而且 mean_len 的噪声 sd = 4.0，每个点都要重复；估计量本身有离散度，`wellposed()` 用 24 次真实蒙特卡洛测它的 p90 并要求 `2 × max(floor, 2.25·p90) × 1.25 ≤ 最近错答距离`。

### 4.2 gpt-6-astra 的错法：完整反查

它自己的话：*"the remaining measurements identify the length effect as approximately **0.001 proxy units per token** at the proposal's distance; relative to the initial policy length, about **0.212** of the proposal's proxy gain is length driven."*

在 ws=2 的世界参数（`len0=222.00, L=617.95, sl=161.72, wl=0.7373, proxy=1.85183`）下解析枚举"测斜率再乘"的各条路线：

| 路线 | 斜率 (proxy/token) | 得到的份额 | 距真值 |
|---|---|---|---|
| L 处的局部导数 `(wl/sl)·sech²(u)` | 0.000134 | 0.0287 | 8.39 T |
| `len_pen` 0→0.15 的 secant | 0.000151 | 0.0322 | — |
| `len_pen` 0→1.80 的 secant | 0.000367 | 0.0786 | — |
| **`len_pen` 0→8.00（build 允许的最大）的 secant** | **0.001021** | **0.2183** | **4.02 T** |
| `len0`→L 的平均斜率（= 正确答案） | 0.001835 | 0.3923 | 0 |

**gpt-6-astra 报的是 0.2120 与 0.2162，它说的斜率是"约 0.001"。** 匹配到它自己的测量噪声以内。它的错误是：用**能买到的最宽 secant** 代替对饱和项到零距离的外推。因为 `tanh` 在正半轴是凹的，任何在 `[len0, L]` 右端附近测到的斜率都小于该区间的平均斜率，于是答案系统性偏低——两次重复偏低到同一处（0.2120 / 0.2162），这是共享的**概念**错误，不是噪声。

### 4.3 已固化进管线

这条路线之前**不在** rival 邻域里。已注册的 q2 rival 的答案值是 `skip:separate`(0)、`skip:len_pen`(1)、`skip:baseline`(0.069)、`skip:extrapolate`(0.158)、`naive_ignore:R4`(0)——`skip:extrapolate` 覆盖的是"停在最大惩罚处"的**水平形式**，而 gpt 走的是同一捷径的**斜率形式**。

本轮已补：

```python
def _q2_slope_routes(p):      # scalelab/bp/e05_matched_kl_far.py
    local = (wl / sl) * (1 - tanh(u)**2)                      # L 处的导数
    span  = (prox[0] - prox[-1]) / (lens[0] - lens[-1])        # build 卖得到的最宽 secant
    return {...}                                              # 各乘 (L - len0) / proxy
```

- 注册成 rival `B_slope:local` / `B_slope:span`，进 kill matrix。实测 err/T（ws2 / ws3 / ws4）：local **8.39 / 6.94 / 9.21**，span **4.02 / 3.72 / 3.15**，全部 ≥2 T 被打死。
- 同时进 `wellposed()` 的 `seps` 筛选：**任何未来世界，只要容差有可能宽到吃下这两条路线，就直接不出题。**
- 该改动只影响 `wellposed` 的通过与否与 kill matrix 条目，不影响世界抽样，因此重导出后三个 `environment/` 目录**逐字节不变**（已验证），上述 4 次运行的证据继续有效。

### 4.4 方法论收获

**rival 邻域必须同时覆盖捷径的"水平形式"和"斜率形式"。** 一个能写出正确饱和函数形式、能做正确指数外推、能反解 best-of-n 恒等式的前沿模型，在同一道题里用了一个未注册的线性化捷径。这是过去两轮记录的 13 类作者高估之外的新一类，而且只能由真实运行发现——所有内部门当时都是绿的。

**由此得到 v5 的可检验杠杆假设：** 让答案必须由非线性响应的**积分或反函数**得到，并保证任何在可买区间内测到的斜率/secant 都偏离 ≥3 T；再叠加噪声，使"把采样加密"也救不回来（因为偏差不是方差）。e05 的 q2 是这一类的偶然样本；下一版应把它做成**显式题族模板**而非单点。

## 6. 交付前自查抓到的两件事

### 6.1 我自己造的评分缺陷（已修）

重算证据表时发现：e05 q5 的四次运行**全部**报 0.44 T 误差，四个值一模一样——这个整齐程度本身就是可疑信号。查下去：

```
key  = 2162.690716050147     （匹配预算的解析解）
tol  = 0.6958888871695308
参考解的 10 次校准重复的误差 = [0.3093, 0.3093, 0.3093, … ]   ← 完全相同
```

**采样预算是整数**，`_bon` 里就是 `int(round(n))`，所以任何答案都只能是整数，而 key 带着小数 0.6907。于是**包括参考解在内**，每个正确答案都固定差 0.309。更糟：容差规则是 `tol = max(floor, 2.25 · p90(参考解误差))`，这个规则对**噪声估计量**是对的、对**确定性偏置**是错的——偏置把 band 从 floor 0.5 顶到 0.696，然后参考解停在它的 0.44 处，**44% 的判别区间被我的四舍五入吃掉**。

四次运行的"0.44 T"于是根本不是模型的推导误差，而是我的 key 的四舍五入。修正后：**q5 的四次运行误差都是 0.00 T，与可达的 q1 完全一样。** 这个更正让 §3.4 的否证结论更强也更干净：O17 不是"绑精度不绑可能性"，而是**完全不绑**。

**修法两层：**

1. **源头**：q5 的 key 取整（`round(p["q_nfull"])`）。tol 随之回落到 floor 0.5，item 变**更严**，四次运行仍全对。
2. **机制**：新增 G17。判别统计量是校准重复里参考解误差的 **median / p90**：确定性偏置没有离散度，比值恰好 **1.000**；真实估计量在全部 15 个实例里落在 **0.24–0.71**。阈值 0.90 落在这个空隙中间，两侧都有余量。

G17 的完整判据是三个条件同时成立才失败：`median/p90 > 0.90`（是偏置不是离散度）**且** `median/tol > 0.05`（偏置大到有影响）**且** `tol > floor`（**这个偏置为自己买到了容差**）。第三条是关键——见下节。

**G17 有配套的失败演示测试。** `tools/test_g17.py` 把 q5 的小数 key 故意放回去，断言 G17 必须失败且必须指向 q5；一道无法被证明会失败的门不构成证据。7/7 通过。

### 6.2 G17 立刻在 v3 已交付的任务上查出第二例（判定为无害）

G17 上线后扫全部 12 个蓝图 × 3 种子 = 36 次构建，只有 `t02_stability_edge` 出现同一模式：q1/q2 的 median/p90 = **1.000**，偏置占容差 12%–26%，三个种子都有，**并且 v3 交付的 `t02-stability-edge-ws2 / ws3` 两个实例都带着它**。

但这一例**不是**同类缺陷。诊断：q1 问 qk-off 的发散边界，而 `status == "diverged"` 是**无噪声布尔量**，所以答案精度只由二分最终 bracket 的宽度决定。`find_edge` 做 6 次二分 → 残差约 0.005 log10(lr)，每次重复完全相同。我先试着把二分提到 10 次——**`LabError: request limit reached (40 requests)`**，t02 的 40 次请求上限根本不允许。也就是说：在预算内，**任何**求解者（包括参考解）都不可能把这些边界定得更准。这是题目的物理，不是作者的疏忽。

**区分标准正是 G17 的第三个条件**：t02 的 q1/q2 容差是作者声明的 floor 0.025（残差的 5 倍），偏置只是**落在**里面；而 e05 q5 的 band 是被偏置**顶起来的**。所以 G17 对 t02 正确放行，并在 cert 里记录 `{'q1': ratio 1.0, tol_above_floor: False}` 作为留痕。`t02_stability_edge.py` 的 `find_edge` docstring 现在写明了这个权衡与 40 次上限的实测证据，`EDGE_BISECTIONS = 6` 成了具名常量而不是字面量。

## 7. 局限与诚实声明

1. **样本量小。** 每格 2 次重复、两个模型。"gpt-6-astra 在 q2 上失败、fable-5-1 通过"是 2/2 vs 2/2，加上错法可解析复现，我认为是真信号；但不足以做模型排名。
2. **只有 3 个 lab 出了新蓝图。** `pretrain` 域在 v4 没有新蓝图（沿用 v3 的 7 个）。
3. **e05 与 e04 的跨题比较有混淆项**（不同世界抽样）。题内的 (q1, q5) 匹配对没有这个问题，主结论只依赖它。
4. **一次运行有 4 次调用降到 medium effort。** 宿主单次 shell 调用上限约 178 s，`gpt_agent.call_api` 的超时是 `rem−5`，所以单次调用上限约 163 s；上下文变大后有若干次调用超时未返回。harness 的既定行为是连续两次超时后该次调用降到 medium，成功后回到 high。逐 run 核对 `state.json` 的 `calls_by_effort`：**只有 `e05ws2_gpt6astra_H0` 发生了降级**（19 次调用 = high 15 + medium 4，`effort_downgrades: 4`）；另一次 e05 gpt 运行（`H0r2`）尽管也有 6 次 api_error，18 次调用**全程 high**；其余 22 次运行全程 high。这是宿主限制，不是模型属性。注意这次降级的运行恰好也是 q2 答错的两次之一——但另一次（全程 high）错得一样（4.06 T vs 4.16 T）且错在同一个概念上，所以降级不是失败的原因。
5. **上游端点当日一度严重降速。** 一次"回一个 OK"的最小调用耗时 **149.9 s**（`runs/gateway_probe.log`，单行，200）。12 次 gpt 运行的 `state.json` 合计记录 **13 次 api_error**（全部集中在两次 e05 运行：7 + 6；其余 10 次 gpt 运行为 0），均为客户端侧超时后重试。`runs/gateway.log` 里 334 条**已完成**请求全部是 200、p50 18.1 s、p90 59.5 s、max 141.1 s——即完成了的调用没问题，那 13 次是客户端在 163 s 处断开、网关侧没有留下完成行的调用。fable 通道不经过这个网关，所以我**没有** fable 的逐次延迟数据，不对它的速度作声明。
6. **4 次 e05 运行是在修 key 之前收集的。** 但修正只动了 `tests/key.json`、`cert.json`、`review_card.md` 和内部库；三个实例的 `environment/`（即 agent 能看到的全部字节，含 `app/questions.json`）**逐字节未变**（`diff -rq` 已验证），所以用新 grader 重评旧答案是合法的，不是重跑。四个答案本来就都是 2163。
7. **e05 q5 现在的 0.00 T 是"格式允许的最高精度"。** 整数 n 的分辨率就是 1 sample，真值的小数部分 0.31 被 round 吸收。要在这个方向上继续施压只能换答题形式（例如要求给出 KL 本身），不能靠收紧容差。
8. **e04 的 `steps` 上限 2000 与 e05 的 1000 都是 build 的人为约束**，题面明确说明它是"这个部署的调度器限制，不是训练栈的限制"，所以不可达性是**部署事实**而非物理事实。这是诚实的，但也意味着足够怀疑的 agent 可能质疑约束的正当性——目前没有运行这么做。

## 附录 B：e05 相对 e04 的代码级差异

1. `STEPS_MAX = 1000`（e04 为 2000），`spec()["knobs"]["steps"]["max"]` 随之改，`LAB_EXTRA` 增加一段说明超限是拒绝而非截断。
2. `_try_draw` 增加远端筛选：`S_FULL ∈ [1.9, 3.1]×STEPS_MAX`；要求 `1.10·K ≤ kl_full ≤ 0.93·KL_T`（趋近律在远端仍在爬升，否则答案退化成 `klbon_inv(KL_T)`，一个不用外推就能写下的数）；且 `kl_full < 0.8·kl_cap`（cap 不承重，不能算进链深）；且 `n_full` 与 7 个廉价猜测（`N`、`n_logn`、`n_memo`、`n_reach`、线性延长 `n_lin`、按步数比例 `n_prop`、远端错恒等式 `n_flogn`）都相距 ≥8。
3. 新 item q5（`point`，单位 samples，链 `["saturation","extrapolate_far","bon_identity"]`，key 取整）。
4. `oracle()` 增加两行可达数据（`0.45·STEPS_MAX` 与 `STEPS_MAX`）→ `_fit_steps0` → 远端外推 → `klbon_inv` → `round`。
5. 新 rival：`skip:extrapolate_far`、`skip:saturation`、`B_far:linear`、`B_far:proportional`，以及 `skip:bon_identity` 扩展到远端。实测 q5 上的 err/T 在 1672–4465 之间。
