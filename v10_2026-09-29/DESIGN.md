# v10 设计文档：机制卡 → 加难算子 → 最小对阶梯 → 双证书 → 轨迹硬化

本文件讲 v10 的 **造题 pipeline 本身**。实测分数和每个失败的核查见 `V10_REPORT.md`。这里的数字都能在 `certs/` 和 `l15/tasks/*_cert.json` 里找到出处。

---

## 1. 要解决的问题

用户对 v10 提了三点要求：

1. 要有一条 pipeline，能把一道题**迭代成有意义的难题**，同时**完全保证正确**。难度应当来自完整机制（图结构），而不是偏题怪题。候选路线有三条：
   - 机制图耦合，或让信息更难获取；
   - 做轨迹分析，但不能针对某个具体模型；
   - 改成 MLS 式的"优化 / 实现，跑到多少分"。
2. **异质**：题型和难点都要不同，不能只有 JSON 输出。QA 和 open-ended 都要有。
3. **稳定产出**多类 demo，能困住 GPT-6 和 Fable 5.1。

v2–v9 留下的实测结论（见上层目录各版报告）决定了 v10 的出发点：

- **唯一稳定的难点**是"廉价测量有偏 + 外推"。v8 的 r_crit 和 v7 的 k8-c2 是例证。
- **"藏信息""披露多少""搜索规模"三类杠杆都被否证过。** 被证书认证的只是正确性，不是难度。
- 题面若写明了世界模型，前沿模型就能照着算出来（v8 a_span 被 Fable 4/4 打穿）。

所以 v10 的难点只从一个方向找：**标准的实验卫生本身在这个世界里给出一个自洽、却错误的答案，而 agent 自己的检查会确认它。**

## 2. Pipeline 总览

```
S0 机制卡 ──► S1 加难算子 ──► S2 实例条件(闭式) ──► S3 策略闸门 / 执行证书 ──► 正确性证书
     ▲                                                                                  │
     │                                                                                  ▼
S7 轨迹硬化：前沿解 → 下一档诱饵 ◄── S6 习惯归类 ◄── S5 边界核查 ◄── S4 前沿实跑（难度证书）
```

| 阶段 | 产出 | 零模型调用？ | v10 代码 |
|---|---|---|---|
| S0 机制卡 | 情境、原则 P1..Pk、识别路径、真值计算 | 是 | 各族文件头 docstring |
| S1 算子 | 一次图变换 + 被击败的习惯（写成策略程序）+ 保留的识别路径 + 证明义务 | 是 | `serve_ab_l2.py`（H7a/H7b）、`scaleup_l2.py`（D1） |
| S2 实例条件 | 每个种子上机制确实起作用的闭式条件 | 是 | `serve_ab._conditions`、`judge_audit.certify`、`scaleup*_cert` |
| S3 闸门 / 证书 | oracle 过、每个诱饵在目标项上失败、扰动/搜索/池闸门 | 是 | `l15/v8gates.py`、`l15/v8cert.py`、`*_cert.py` |
| S4 前沿实跑 | Fable 5.1（官方 CLI）/ GPT-6 的真实 agent 运行 | 否 | `harness/` |
| S5 边界核查 | 每个 fail：离阈值多远、离哪个诱饵最近、**只改一处**能否过 | 是（重放） | `certs/boundary/dup_holdout_cf.py` |
| S6 习惯归类 | 把失败归到"被违背的假设 × 使用的捷径"，不按模型写陷阱 | 是 | 报告 §4 |
| S7 轨迹硬化 | 上一档的前沿解**原样**成为下一档的诱饵，并加一个算子击败它 | 是 | `scaleup_l2_decoys/` |

两条硬规则：

- **轨迹只用于归类，不用于写陷阱。** S7 击败的是"作业内随机 holdout 选超参"这类一般习惯，不针对某个模型的措辞或偏好。被原样收作诱饵的前沿解只是这类习惯的一个样本；它必须失败，但陷阱是按习惯设计的。
- **证书只证正确性，难度只由实跑证明。** v8 的教训是"被认证的是正确性不是难度"。所以每族都有 L0 校准档，而且每个 fail 都要做边界核查。

## 3. S0 机制卡

一张机制卡包含以下内容（以 serve_ab 为例，全文见 `l15/tasks/serve_ab.py` 文件头）：

| 字段 | serve_ab 的内容 |
|---|---|
| 情境 | 一个自动扩缩容的共享 GPU 池，一个 FIFO 队列。B 模型更好但更慢（κ≈2–2.6×）。交付物是逐小时的上线比例 |
| P1 | **A/B 看不见成本**：两臂共享队列，逐臂差分把 B 施加给所有人的排队成本抵消掉了（SUTVA 被共享资源违背） |
| P2 | **护栏测试也看不见**：实验在高峰最多放 30% 给 B，这时扩缩容仍有配额余量，等待和放弃率都是平的；到 100% 高峰超配额，池子饱和 |
| P3 | **过载代价由耐心 θ 定价**：历史数据和护栏测试都不饱和，所以看不到过载代价本身。~~θ 不可识别，只能设计夜间容量演练去测~~ **（开跑后更正）**：θ 可以从历史数据经 Little 律识别（放弃率 = θ × 平均等待，在不饱和小时也精确成立）；drill 是信噪比更高的路径，但不是必需的。见 V10_REPORT §6.5 |
| P4 | **高峰上线比例是内点权衡**："守住扩缩容目标"太保守，"填满配额"太激进 |
| 识别路径 | 历史数据 → 负载曲线 **和耐心 θ**（Little 律：θ = 放弃率 / 平均等待）；A/B → 质量差与 κ；夜间 drill → 更精确的 θ；Erlang-A 逐小时优化 |
| 真值 | 每小时一个 M/M/c+M（Erlang-A）稳态，由截断生灭链算出（尾质量 < 1e-12）；日间负载噪声用 Gauss-Hermite 积分；逐小时细网格最大化 |
| 每条原则对应的诱饵 | P1 → `ship_all`；P2 → `sched_guard`（高峰只放 30%）；P3 → `loss_delta`（Erlang-B 不耐心极限）和 `fluid_delta`；P4 → `no_ship` 与 `rho_0.95` |

**卡的写法约束（来自 v2–v9 的教训）**：

- 每条原则都要写成"**一个图事实 + 忽略它的默认习惯 + 击败该习惯的诱饵程序**"。诱饵必须是可执行的策略，不能是文字描述。这样闸门才能验证"忽略这条原则就一定失败"（p_ablation）。
- 识别路径必须**只用 agent 拿得到的东西**。例如 serve_ab 要求 drill 在预算内可行（条件 `drill_feasible`）。
- **识别路径要穷举（v10 开跑后补的约束）**：设计时我声称 θ "只能通过 drill 得到"，但 Little 律让历史数据就能识别 θ。GPT-6 在 8 个 serve_ab 运行里有 7 个 0 次 drill，Q1 区间 8/8 覆盖真值。对每个"只能通过 X 得到"的声明，都要列出所有能识别该参数的恒等式，并用一个零洞察策略实测。
- 真值必须是**精确的**。可接受三种来源：闭式或数值精确（Erlang-A）、有限总体（judge_audit）、执行判分（scaleup）。v10 不用"模型拟合出的真值"。

## 4. S1 加难算子库

每个算子都有四个组成部分：**图变换 / 被击败的一般习惯 / 保留的识别路径 / 证明义务**。

| 算子 | 族 | 图变换 | 击败的习惯（诱饵程序） | 保留的识别路径 | 证明义务（闸门） |
|---|---|---|---|---|---|
| **L0 去机制** | serve_ab | 峰值负载即使 100% 上 B、在 +2.5 sd 的日子也不超目标 | 无（L0 下朴素 A/B 就是对的） | — | `no_binding`、`ship_all_ok`、`naive_q1_ok`：L0 下 `ship_all` 必须**通过** |
| **H7a 时段异质** | serve_ab L2 | B 的慢速因子 κ 和质量增益在工作时段与其余时段不同 | 跨小时合并 A/B 估计 | 按时段分组的 A/B | p_ablation 与 mutation 在 L2 池上重跑 |
| **H7b 日类型混合** | serve_ab L2 | 周末负载低 16–28%，日间噪声 sd 5%，同一日程的价值是跨日类型的混合 | 代入"平均日"（Jensen 偏差恰好落在饱和拐点上） | 按星期分组的历史数据 | 新增原则 `P5_mixture_not_average_day` 的消融 |
| **D1 语料重复** | scaleup L2 | 80,000 行 = 20,000 个不同行 × 4 份拷贝（特征、众包标签都相同） | ① L1 参考解"wd × N_sample/N_full"（行数是错的 N）；② 按行数的子采样外推；③ 作业内随机 holdout 选 wd（重复泄漏进验证集） | 样本里约 7% 的行是另一行的精确重复（生日计数，k̂ = 1 + pairs·(N−1)/C(n,2) ≈ 3.9–4.4）；可在样本的**不同行**上复现生产 regime，或在**按重复组切分**的 holdout 上作业内调参 | 参考解过 T + 0.015；四个诱饵（含 Fable L1 原样代码）≤ T − 0.015 |

算子库里的候选算子（设计过但 v10 没有实现，留作下一步）：

- **Q1 金标准代价分层**（judge_audit L2）：让"verify"本身在某一类上也有偏。
- **Q2 目标量不可直接抽样**（judge_audit L2）：问反事实或外推量，不问总体均值。
- **D2 分布漂移**（scaleup）：生产语料的类别比例与样本不同，且只能从无标签特征识别。

原因见 §9 的第 2 条教训：judge_audit L1 已被"pilot 验证 + 分层"这一默认卫生解出。

## 5. S2–S3 正确性证书（三种真值、三套证书）

### 5.1 serve_ab：精确真值 + v8 族闸门

- **S2 实例条件**（`serve_ab._conditions`）：
  - L1/L2 要求：`masked_at_guard`（30% 下不饱和）、`saturation_inside_window`、`drill_feasible`；
  - 每个诱饵的 regret ≥ K_DECOY·EPS_R = 2.5 × 0.0010，涉及 `decoy_ship_all`、`decoy_guard_safe`、`decoy_no_ship`、`decoy_rho_0.95`；
  - `q1_naive_far`、`q1_loss_far`：Q1 的朴素 A/B 答案和 Erlang-B 答案都在区间容差之外；
  - `peak_interior`：高峰最优比例在 (0, 1) 内部；
  - `positive_launch`：最优日程价值 > 0。
- **S3 闸门**（`l15/v8gates.py`，由 `l15/v8cert.py` 驱动，可续跑）：
  - **strategy gate**：oracle 通过，每个诱饵在其声明的目标项上失败；
  - **p_ablation**：每条原则 × 4 个实例，去掉该原则的策略必须在它保护的项上失败；
  - **item_activity**：没有惰性项，也没有坏项；
  - **mutation**：对 oracle 答案做"小扰动仍过、大扰动在预期项上失败"；
  - **search**：零洞察搜索策略（`sweep_guard`、`offpeak_full`）必须失败；
  - **pool**：配额多样性。
- 证书报告：`certs/serve_ab/sab_*_state.json.report.json`。
  - L1b、L2b 为 `ok: true`，任务实例取自这两个池。
  - L0 的 `ok: false` **只**因为 search 闸门未声明搜索策略：L0 下朴素答案本来就对，按设计不做搜索闸门。
  - 第一版 L2（`sab_L2`）没过：fluid 诱饵在饱和点不连续，p_ablation 漏过 1/4，mutation 的 q1_width 小扰动也失败。改为 Erlang-B loss 模型作 P3 消融后，得到 L2b。两版报告都保留。

### 5.2 judge_audit：有限总体精确真值 + Monte-Carlo 策略重放

- 真值：600 个 prompt × 2 个模型，每条回答的正确性是一个隐藏比特。通过率是**有限总体上的精确均值**，真值里没有模型，也没有抽样。
- 证书（`judge_audit.certify`，每个实例 300 次 Monte-Carlo 重放）的通过条件：
  - 参考策略通过率 ≥ 0.97；
  - 每个诱饵通过率 ≤ 0.02；
  - |B − A| ≥ D_MIN = 0.03，保证 SHIP/HOLD 有确定答案。
- 参考策略的做法：
  1. 全量 review，花费 120 credits；
  2. 在 B 上随机抽 40 条做 verify pilot；
  3. 剩余预算 verify B 中**最长**的回答；
  4. 已 verify 的按 verify 计，其余按 review 计。
- 四个诱饵分别把某一种仪器当作金标准：`judge_only`、`review_all`、`crowd5_majority`、`judge_corrected_by_review`（以 review 为金标准的 PPI）。
- 另有信息类策略 `info_ppi_random`（全量 review + 随机 verify 做 PPI）。它无偏但方差大，通过率 0.32–0.58（只在 B 上做 PPI 的变体为 0.56–0.79），只报告，不作为闸门。
- 结果：种子 0–19 共 **20/20 认证**，参考策略 1.00，四个诱饵全部 0.00。见 `certs/judge_audit_cert.json`。

### 5.3 scaleup：执行判分 + 双侧余量证书

- 真值就是**执行**：判分器在沙箱里运行交付的 repo。沙箱用 bwrap，无网络，单核，每个副本 CPU 上限 120 s，内存 2 GB。数据是 agent 看不到的全量语料（80,000 行）；指标是 20,000 行金标准测试集上两个种子的平均准确率。
- 证书（`scaleup_cert.py`、`scaleup_l2_cert.py`）的判据：
  - 参考解 ≥ T + MARGIN；
  - 每个诱饵 ≤ T − MARGIN，其中 MARGIN = 0.015；
  - T 取参考与最佳诱饵的中点，向下取到 0.005 格；
  - **全部分数都用判分器自己的 `run_job` 代码路径测出。**
- 证书按"副本"粒度缓存，可续跑。原因是每次 bash 调用只有约 178 s，后台进程会随调用一起结束。
- **与判分同机争用会抬高 CPU**：实测 17.5 s 被抬到 48 s，而这个数会写进题面。因此证书和判分都**单独**运行。
- L1 证书结果：种子 0/1/2 认证，种子 3 未过（诱饵余量 0.0132 < 0.015）。
- L2 证书结果：种子 0/5/6/7 认证，1/2/3/4/8/9 未过，**认证率 4/10**。
  - 未过的种子里，团队 wd（2 或 3）本身就接近最优，ship 与参考只差 0.017–0.034。
  - 种子 3 只因 T 取 0.005 格差 0.0003。按规则不事后改 T，也不改 MARGIN。
  - 这是一个真实的设计信号：**同一个算子在一半实例上不起作用**，必须靠证书筛掉。

### 5.4 三套证书的共同纪律

- 诱饵都是**可执行程序**。scaleup L2 甚至把前沿模型的 L1 repo 原样收为诱饵，见 `l15/tasks/scaleup_l2_decoys/`。
- 每个"信息类"策略（`row_extrap`、`l1_gpt6_ensemble`、`curve_wd*`、`info_ppi_random`）都报告，但不作为闸门。**它们能过，这件事写在报告里，不藏。**
- 规则不事后改：种子 3 的 T 格、种子 8 的诱饵余量 0.0082 都照实判为未认证。

## 6. S4–S6 难度证书：实跑、边界核查、习惯归类

- **实跑**：
  - Fable 5.1 走官方 Claude Code CLI（`cc_agent.py`）；
  - GPT-6 走 Responses API（`gpt_agent.py`）；
  - 两者都经本地网关（`gateway.py`，唯一持有上游 key 的进程）。
  - 沙箱只看到占位符 key，由 `test_no_key.py` 断言。
- **边界核查**（每个 fail 都做）有三类：
  1. **离阈值多远**：分数 vs T，以及离哪个诱饵最近。例如 GPT-6 sab_L2_s3 的 regret 0.00741，与 `guard_safe` 诱饵的 0.007415 一致到 4 位。
  2. **只改一处的反事实**：把失败 repo **只改一行**，重新执行判分。例如 `dup_holdout_cf.py` 只把随机 holdout 换成"按重复组 holdout"。改完能过 T，说明失败正是这个机制造成的；改完仍不过，就不能归因于它。
  3. **轨迹机制**：从 stream 或 traj 里找出做决定的那一步，看 agent 当时用什么证据确认了自己。
- **习惯归类**：失败归到"被违背的假设 × 使用的捷径"，例如"i.i.d. 行 × 随机 holdout""实验护栏 = 上线约束"。**不写"某模型喜欢 X"式的陷阱。**

## 7. S7 轨迹硬化示例：scaleup L1 → L2

**L1 的前沿结果**：有效运行 6/6 全过（0.843–0.893 vs T 0.765/0.785）。解法分两类：

- Fable：在作业内随机 5% holdout 上选 wd，再做平均 / 集成。
- GPT-6：前向校正噪声损失、4 成员集成、对冲的按行数衰减规则。

**加算子 D1（语料重复 ×4）**后，L1 的三条通过路线在新世界里的结果：

| L1 路线 | 在 D1 世界里 | L2 角色 | seed 0 实测 |
|---|---|---|---|
| L1 参考解：wd × N_s/N_f | 行数是错的 N，欠正则 | 诱饵 `row_rule` | 0.616（ship 0.723） |
| Fable L1 repo（作业内随机 holdout） | 验证集含训练行的拷贝，记忆看起来像准确率，最小 wd 胜出 | 诱饵 `l1_fable_injob`（原样代码） | 0.624 |
| 按行子采样外推 | 测的是错 regime（不同行上的少次遍历），外推到错的 N | 信息类 `row_extrap`（斜率噪声大，结果随种子摆动） | 0.767 |
| GPT-6 L1 repo（噪声鲁棒 + 集成 + 对冲） | **未被击败** | 信息类 `l1_gpt6_ensemble` | 0.791 |

**L2 参考解（正确世界模型）**：

1. 从样本的精确重复对估计 k̂；
2. 在样本的**不同行**上，以 32·k̂ 次遍历复现生产 regime，在 m = n_u/4、n_u/2、n_u 三个规模上测 wd*；
3. 做 log-log 拟合，外推到 N/k̂；
4. 只改 config 里的 wd。

**开跑前已登记的已知漏洞（测过）**：第一条写在 `scaleup_l2.py` 文件头，双侧通过带来自证书的 `curve_wd*` 信息项。

- L2 不击败"噪声鲁棒损失 + 对冲衰减"：GPT-6 的 L1 解在 4 个认证种子上全过。
- L2 陷阱是**双侧**的，通过带大约是 wd ∈ [0.6, 2]：
  - `curve_wd1` 在 4 个认证种子上全过；
  - 在团队 wd = 3 的三个种子（5/6/7）上，只把 wd 3→2 也能过。
- 所以 L2 困住的是"**激进地缩 wd**"的路线：按行数规则缩，或被泄漏的 holdout 推向最小 wd。"保守小改"的路线困不住。

**L2 的前沿结果**：Fable 4/8，GPT-6 3/5。L1 是 6/6，合计从 6/6 通过降到 7/13。

- 6 个失败都落在上面预言的路线上：4 个是泄漏 holdout，1 个是按行规则，1 个是看见了重复却没改 N。
- 7 个通过里，6 个走了已登记的漏洞路线。
- 详见 V10_REPORT §4–§6。

## 8. 异质性矩阵

| 族 | 交付形式 | 判分方式 | 难点来源（图结构） | 考察的 AI4AI 能力 | 真值类型 |
|---|---|---|---|---|---|
| **serve_ab** | 开放式日程文件 `rollout.conf`（24 行）+ 自由备忘录 `report.md`，内含两条区间 QA（`Q1: [lo, hi]`、`Q2: [lo, hi]`） | 日程 regret ≤ 0.0010；区间必须覆盖精确值且宽度受限 | 共享资源干扰（SUTVA）+ 护栏掩盖饱和 + 需要自己设计 drill 才能识别的参数 + 内点权衡；L2 再加异质性与 Jensen | 上线实验设计、干扰下的因果推断、排队建模、带约束优化 | 精确（Erlang-A 数值解） |
| **judge_audit** | 纯 QA：`answers.md` 三行（Q1 通过率、Q2 差值、Q3 SHIP/HOLD）+ 不计分的报告 | 容差 0.02 + 决策正确 | 仪器效度：LLM judge 与"金标准"专家 review 有同一个盲区；预算分配 | 评测方法学、标注预算分配、测量偏差诊断 | 精确（有限总体） |
| **scaleup** | 代码 + 配置：`/app/repo`（可改 `train.py`、加模块）+ 不计分的报告 | **执行判分**：隐藏语料上两个种子的金标准准确率 ≥ T | 超参跨规模迁移（AdamW 时间尺度）；L2 语料重复导致 regime 切换 + 验证泄漏 | 训练配方迁移、scaling 实验设计、验证集设计、MLS 式实现 | 执行（带双侧余量证书） |

三族在题型、真值来源和难点结构上都不同，不是同一模板换参数。

## 9. v10 新增的设计教训（每条都有实测依据）

1. **S7 在"击败一个验证程序"时最有效，在"击败一个答案"时最弱。**
   - D1 让 agent 自己的验证撒谎：重复泄漏进随机 holdout，带噪声标签（r = 0.2–0.3，噪声天花板 1 − 0.9r = 0.73–0.82）的 holdout 准确率达 0.82–1.00，于是最小 wd 胜出。
   - Fable 在 L2 的 4 个失败全部属于这一类。边界核查**只改 split**，4/4 就能过 T。
   - 相比之下，"答案型"陷阱（例如"wd 该缩多少"）会被对冲和保守改动中和。
2. **有限总体 + 金标准可买 + 协变量可见 → 默认卫生必然解出**（judge_audit L1 饱和）。
   - "随机 pilot 验证代理 → 按协变量分层 verify" 是教科书流程，两个前沿模型都会。
   - 要变难，目标量必须不能由金标准抽样直接得到（反事实、外推、干预）。
3. **开放式优化题的 T 锚在"正确洞察的参考解"上时，正交改进会买下余量**（scaleup L1 饱和）。
   - 噪声鲁棒损失、SWA、集成、对冲都属于正交改进，对冲天然中和单旋钮陷阱。
   - 下一步的 T 应锚在"正确洞察 + 标准正交改进"之上，或者让陷阱作用在所有正交改进都要经过的环节上（例如验证集）。
4. **自证式合成替身是一种真实的 AI4AI 失败模式。**
   - Fable 多次先造一个"合成的全量语料"，在上面验证自己的方案，例如 su_L2_s5_fcc 和 su_L2_s6_fcc。
   - 这个替身编码的是 agent 自己的世界模型（i.i.d.、无重复），所以只会确认错误答案。
   - 它和 serve_ab 里"用护栏测试确认无成本"是同一种结构：**agent 的检查与 agent 的假设同源。**
5. **证书认证率本身是设计信号。** scaleup L2 只有 4/10 认证：同一个算子在团队 wd 已接近最优的实例上不起作用。池子必须按证书筛，不能按"算子加了就行"。
6. **serve_ab 能区分 GPT-6，困不住 Fable。**
   - GPT-6 的 3 个失败都是把实验护栏（高峰 30%）带进了上线日程。两个 L2 失败的 regret 与 `guard_safe` 诱饵一致到 4 位，L1_s3 是 0.00730 vs 0.00721。
   - Fable 有效 7/8，唯一的失败是区间差 0.00017。
   - P3 的难度论证有一半不成立：θ 可从历史数据经 Little 律识别，GPT-6 7/8 运行 0 次 drill 仍答对 Q1（见 §3 的更正）。
   - 结论：该族是"中档 / 校准"族，不能算作"困住前沿"。
7. **正确世界模型的正交组件会关掉陷阱的伤害通路。**
   - su_L2_s7_gpt6 的 wd 从 0.15 到 3.0 都过 T，曲线是平的。
   - 在 wd 0.15 处去掉前向噪声校正，准确率从 0.770 掉到 0.6362（FAIL）；去掉白化或尾段平均几乎无影响。
   - 陷阱的伤害通路是"小 wd → 记住拷贝上的噪声标签"，而噪声校正恰好是这个世界的正确噪声模型。
   - 所以 L3 的伤害通路必须是通用稳健技术关不掉的（V10_REPORT §6.2、§9）。
8. **碰到了证据，又自己否定了。**
   - 三个失败运行碰到了"重复"这一证据，又把它归为"替身 / 工具的问题"：
     - su_L2_s0_fcc2 在平铺替身上实测到记忆赢；
     - su_L2_s6_gpt6 在真实样本里数出 294 个重复组；
     - su_L2_s7_fcc 只在计划里预见到。
   - i.i.d. 先验压过了 agent 自己观察到的证据。这是真实的 AI4AI 失败模式，但不能靠它稳定出难度：同一实例的两次运行结果相反。
9. **通过大多不靠设计的洞察，同实例复跑结果不稳定。**
   - scaleup L2 最终 Fable 4/8，GPT-6 3/5。13 个运行里只有 1 个（su_L2_s5_fcc2）识别重复并据此改了程序。
   - 其余 6 个通过都走开跑前已登记的路线：对冲衰减、噪声鲁棒、保守改 wd、按行外推、集成。
   - 5 对同实例复跑全部一过一挂。所以单次运行不足以判定一个实例"困住"了前沿，每个实例至少要跑 2 次。

## 10. 从 MLS-Bench / TB-Science 借鉴的做法

- **执行判分 + 隐藏数据**（MLS-Bench）：scaleup 的真值是"在 agent 看不到的语料上跑它交付的代码"。判分器、沙箱和资源上限都写在题面里。
- **阈值要有证书**：TB-Science 的阈值来自参考解，v10 更进一步，要求双侧余量，且诱饵是可执行程序（包括前沿模型的旧解）。
- **不同交付物混合**（TB-Science 的 rubric 思路）：同一题里既有机器判分的文件，也有不计分的备忘录。serve_ab 把 QA 嵌进自由文本备忘录，用正则抽取。
- **不借鉴的部分**：v10 不用 LLM 打分的 rubric，所有计分项都是确定性判分。
