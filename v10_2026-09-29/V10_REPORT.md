# v10 报告：三个异质题族、一条可证正确的加难 pipeline，以及它离"稳定困住前沿"还差多远

日期：2026-09-29。模型：Fable 5.1（claude-fable-5-1，官方 Claude Code CLI）、GPT-6（gpt-6-astra，Responses API，effort high）。

pipeline 本身的设计见 `DESIGN.md`；排除和标注规则见 `EXCLUDED.md`。本报告只写实测：每个数字都能在 `run_evidence/<run>/grade.json`、`certs/` 或 `certs/boundary/results/` 里找到出处。

## 0. 结论

**一句话**：v10 交付了三个题型和真值来源都不同的题族，每个实例都有正确性证书。最难的一档（scaleup L2）把前沿通过率从 L1 的 6/6 压到 7/13，两个模型都在里面失败过，而且失败能精确归因到设计的机制。但 v10 **没有做到"稳定困住"**：Fable 在 scaleup L2 过了 4/8，GPT-6 过了 3/5；而且大多数通过走的是事先已知、没有堵上的路线。

| | Fable 5.1 | GPT-6 |
|---|---|---|
| 全部有效运行 | 17/22 | 13/19 |
| 难档（serve_ab L1/L2 + scaleup L2） | 9/14 | 6/11 |
| 最难档 scaleup L2 | 4/8（95% Wilson 区间 0.22–0.78） | 3/5（0.23–0.88） |

五条最重要的发现：

1. **失败都能归因到机制，没有一个是"偏怪题"造成的。**
   - Fable 在 scaleup L2 的 4 个失败，都是作业内的随机 holdout 被重复行泄漏。每个失败 repo 都只改 split 这一处，改后 4/4 过 T。
   - GPT-6 的 su_L2_s0 得分 0.61585，与 L1 参考解诱饵 `row_rule`（0.6159）一致到 4 位。
   - GPT-6 在 serve_ab 的 3 个失败都把高峰上线比例停在实验护栏 0.3。两个 L2 失败的 regret 与 `guard_safe` 诱饵一致到 4 位；L1_s3 是 0.00730 vs 0.00721。
2. **通过大多不靠设计的洞察。** 13 个 L2 运行里，只有 1 个（su_L2_s5_fcc2）识别出语料重复并据此改了程序。另外 6 个通过都走了事先写在 `scaleup_l2.py` 文件头或证书信息项里的已知路线：对冲衰减、噪声鲁棒损失、保守改 wd、按行外推、集成。
3. **"答案型"陷阱会被通用的稳健技术中和。** 用 GPT-6 在 s7 上的配方，wd 从 0.15 扫到 3.0 全部过 T。消融后只去掉前向噪声校正，wd 0.15 就从 0.770 掉到 0.636。陷阱的伤害通路（记忆重复的噪声标签）被一个**正确的噪声模型**整个关掉了。
4. **"碰到了证据又自己否定"是反复出现的失败模式。** 3 个失败轨迹里，agent 都碰到了"重复"这一证据，然后把它解释掉了：
   - su_L2_s0_fcc2 在自己平铺的替身上实测到"重复让记忆赢"；
   - su_L2_s6_gpt6 在真实样本里数出 294 个重复组；
   - su_L2_s7_fcc 只在计划里预见到"重复会让准确率失去意义"，没有实测。
5. **我在设计里有一处声明是错的，已更正。** serve_ab 的耐心 θ **可以**从历史数据经 Little 律（放弃率 = θ × 平均等待）识别，不是"只能靠 drill"。GPT-6 在 8 个 serve_ab 运行里有 7 个 0 次 drill，Q1 区间 8/8 覆盖真值。这个错误不影响真值或判分的正确性，但 serve_ab 的一部分难度论证不成立。

**下一步**（§9）：L3 的算子必须作用在**所有路线都要经过的验证 / 测量程序**上，并且它的伤害通路不能被通用稳健技术（噪声鲁棒损失、集成、对冲、平均）关掉。证书里要把本轮的 6 个非洞察通过 repo 原样收为诱饵。

## 3. 正确性保证

**原则**：证书只证正确性，不证难度。难度只由实跑证明。

| 族 | 真值 | 证书 | 结果 |
|---|---|---|---|
| serve_ab | 每小时一个 M/M/c+M（Erlang-A）稳态，截断生灭链（尾质量 < 1e-12），日间噪声用 Gauss-Hermite 积分，逐小时细网格最优化 | v8 族闸门（`l15/v8cert.py`）：strategy / p_ablation / item_activity / mutation / search / pool | L1b `ok: true`，准入 [1, 3, 4, 8, 9, 12, 13, 15]（16 个候选中 15 个过策略闸门）；L2b `ok: true`，准入 [3, 7, 9, 11, 13, 14]（16 个候选全过策略闸门）；L0 `ok: false` 只因按设计不声明搜索策略 |

| scaleup | 执行本身（判分器的 `run_job`） | 参考 ≥ T + 0.015；每个诱饵 ≤ T − 0.015；T = 参考与最佳诱饵中点，向下取 0.005 格；全部分数用判分器代码路径测 | L1：种子 0/1/2 认证，3 未过（诱饵余量 0.0132）；L2：种子 0/5/6/7 认证，**认证率 4/10** |

## 5. 失败的边界核查与习惯归类

每个失败都做三件事：量离阈值多远、找最近的诱饵、做"只改一处"的反事实。反事实都用判分器自己的 `run_job` 重跑。除特别注明外，都只跑了 replica 0，一个副本约 18–70 s CPU。

### 5.1 scaleup L2

| 运行 | 分数 / T | 做决定的环节 | 只改一处的反事实 | 习惯归类 |
|---|---|---|---|---|
| su_L2_s0_fcc2 | 0.655 / 0.745 | 作业内随机 holdout 选 wd：wd 0.03 的 holdout 准确率 0.9845，选 0.03 | holdout 按重复组切分 → **0.7704 PASS**（选 1.07） | i.i.d. 行 × 随机 holdout |
| su_L2_s5_fcc | 0.7104 / 0.740 | 同上：wd 0.1 的 holdout 准确率 0.8206，选 0.1 | 按重复组切分 → **0.79415 PASS**（选 1.0） | 同上 |
| su_L2_s6_fcc | 0.70527 / 0.805 | 同上：wd 0.1 的 holdout 准确率 1.000 | 按重复组切分 → **0.8282 PASS**（选 1） | 同上 |
| su_L2_s7_fcc | 0.71683 / 0.735 | 同上：wd 0.1、lr 0.001 的 holdout 准确率 0.8482 | 按重复组切分 → **0.7895 PASS**（选 wd 1.0） | 同上 |
| su_L2_s0_gpt6 | 0.61585 / 0.745 | 用 L1 的缩放规则 wd × N_样本 / N_全量 | 分数与诱饵 `row_rule`（0.6159）一致到 4 位 | 行数即 N × 按样本比例缩放 |
| su_L2_s6_gpt6 | 0.79963 / 0.805 | 衰减规则里用行数作 N。它自己数出了样本里 294 个重复组，但没有改 N | 只把 `len(X)` 改成 `len(np.unique(X, axis=0))` → **0.8366 PASS**（两个副本） | 看见了但没改 N |

**一个本可发现的信号**：这 4 个 holdout 准确率都超过了"完美泛化模型在噪声标签上能达到的上限"。按这个世界的噪声模型（以噪声率 r 把标签换成 10 类中的均匀随机类），上限是 1 − 0.9r。四个运行对应的上限和实测如下：

| 运行 | 噪声率 r | 上限 1 − 0.9r | holdout 准确率 |
|---|---|---|---|
| s0 | 0.20 | 0.82 | 0.9845 |
| s5 | 0.30 | 0.73 | 0.8206 |
| s6 | 0.20 | 0.82 | 1.000 |
| s7 | 0.25 | 0.775 | 0.8482 |

"验证分数高于噪声天花板 = 泄漏"，这是一个 agent 手里就有的检查。4 个运行都没有做。

| 运行 | 失败项 | 数字 | 最近的诱饵 | 习惯归类 |

## 6. 通过路线分析与新教训

### 6.1 scaleup L2 的 7 个通过走了哪条路

| 运行 | 分数（余量） | 路线 | 反事实 / 归因 | 是否事先已知 |
|---|---|---|---|---|
| su_L2_s5_fcc2 | 0.7992（+0.059） | **识别重复**（数出样本里 312 行是另一行的拷贝，估计约 19,000 个不同行）→ 去重 → 在不同行上 holdout 选 wd + GCE 损失 | — | **设计的洞察**（13 个 L2 运行里唯一的 1 个） |
| su_L2_s0_fcc | 0.77208（+0.027） | 按行子采样曲线外推 + 合成替身 + wd 0.5 集成 | — | 是：证书信息项 `row_extrap`（种子 0 上 0.767） |
| su_L2_s6_fcc2 | 0.80795（+0.003） | 衰减指数 0.75 的对冲 + 3 成员集成 | 指数改成 1.0 → 0.7764 FAIL；N 改成不同行数 → 0.8345 PASS | 是：`scaleup_l2.py` 文件头写明"对冲衰减"不被击败 |
| su_L2_s7_fcc2 | 0.74467（+0.0097） | 集成，其中一个成员是二次特征线性模型（wd 0.01） | 去掉该成员 → 0.7182 FAIL（两个副本） | 部分：属于 L1 已观察到的"正交改进（集成）"类，但这个具体成员没有被单独登记 |
| su_L2_s0_gpt6b | 0.76392（+0.019） | wd 不变（团队 2.0）+ 白化 + GCE + EMA | 团队配置原样只有 0.7225 | 是：噪声鲁棒损失，文件头写明 |
| su_L2_s5_gpt6 | 0.74588（+0.006） | wd 3 → 2 + GCE | 证书 `curve_wd2` 在 s5 上 0.7478 | 是：证书信息项 `curve_wd2` |
| su_L2_s7_gpt6 | 0.82575（+0.091） | 按行 sqrt 衰减（wd 3 → 0.67）+ 前向噪声校正梯度（设 r = 0.35，真值 0.25）+ 白化 + 尾段平均 | 不衰减（wd 3）→ 0.74285 仍 PASS；见 §6.2 | 是：就是文件头写的"噪声鲁棒损失 + 对冲衰减" |

13 个 L2 运行里：

- 在**真实样本**里注意到重复的有 3 个：s5_fcc2、s0_gpt6b、s6_gpt6；
- 据此改了程序的只有 1 个：s5_fcc2；
- 另有 s0_fcc2、s7_fcc 只在**自己平铺的替身**上碰到或预见了重复，见 §6.4。

### 6.2 为什么 GPT-6 的 s7 配方能中和陷阱：wd 扫描和消融

用 `certs/boundary/cfg_cf.py` 只覆盖 config 里的键，其余代码不动，在 s7 上跑 replica 0。T = 0.735；同 wd 0.15 下，基线 `row_rule` 得 0.6196。

**wd 扫描**（decay_power = 0，即直接用该 wd）：

| wd | 0.15 | 0.3 | 0.6 | 1.07 | 1.6 | 3.0 |
|---|---|---|---|---|---|---|
| 准确率 | 0.770 | 0.7894 | 0.8198 | 0.8293 | 0.8119 | 0.74385 |

**在 wd 0.15 处的组件消融**：

| 去掉的组件 | 准确率 | 相对完整配方 0.770 |
|---|---|---|
| 前向噪声校正（noise_rate → 0） | **0.6362** | −0.134，FAIL |
| 白化（whitening → 0） | 0.7464 | −0.024，仍 PASS |
| 尾段平均（average_start → 1.0） | 0.7708 | 无影响 |
| 三者都去掉 | 0.6166 | ≈ `row_rule` 0.6196 |

**结论**：陷阱的伤害通路是"小 wd → 记住重复拷贝上的噪声标签"。前向噪声校正本来就是这个世界的**正确噪声模型**（众包噪声是均匀的），它把这条通路整个关掉了。于是 wd 这个"答案"在 [0.15, 3.0] 内都能过 T，曲线是平的。

这也说明"把 T 抬高"行不通：T 受参考解约束（s7 参考 0.7762），而这个配方在最优 wd 附近能到 0.829，比参考高得多。

局限：只在 s7、replica 0 上测，每个点一个副本。

### 6.3 教训 A：答案型陷阱被对冲，验证程序型陷阱才咬人

| 陷阱类型 | 例子 | 前沿表现 |
|---|---|---|
| 答案型：击败"wd 该取多少" | `row_rule` | 被对冲衰减、保守改 wd、噪声鲁棒损失、集成中和。只要曲线在通过带内是平的，任何不激进的答案都会过 |
| 验证程序型：击败"作业内随机 holdout" | 泄漏的验证 | Fable 4 个失败全在这里。只改 split 就 4/4 翻转为 PASS |

只要 agent 走了这一步，验证程序型陷阱就一定起作用。但它**不是每条路线都必经的**：不做作业内选择的路线（对冲、保守、噪声鲁棒）绕过了它。L3 要解决的正是这件事（§9）。

### 6.4 教训 B：碰到了证据，又自己否定了

三个失败运行都碰到了"重复"这一证据，然后把它解释掉了。证据强度不同：两个是实测，一个只是预见。

- **su_L2_s0_fcc2**（Fable，FAIL 0.655）：**实测到了**。它把样本平铺成 80,000 行作替身，看到"holdout 里有近重复、记忆赢了"，然后在思考里写：
  > "since the corpus was a leaky duplicate, that 0.03 selection result is meaningless for real data—only useful for timing."

  真实语料恰恰就是重复的。
- **su_L2_s6_gpt6**（GPT-6，FAIL 0.79963）：**实测到了**，而且是在真实样本里。它数出 294 个重复组后，在报告里写：
  > "Repeating sample rows does not add independent examples and is unsuitable for selecting full-corpus regularization."
- **su_L2_s7_fcc**（Fable，FAIL 0.71683）：**只是预见**。它在做任何实验之前的计划里写：
  > "using the latter mainly to check timing and mechanics since the duplicated rows make accuracy less meaningful there."

  之后它只用平铺数据测时间，另造了一份 i.i.d. 合成语料做验证，没有实测到"记忆赢"。

结构都一样：**i.i.d. 先验比 agent 手里的证据更有分量**，重复被归到"我的替身 / 我的工具有问题"。这是一种真实的 AI4AI 失败模式：遇到异常，先怪仪器。它和 v10 已记录的"自证式合成替身"是同一类：agent 的检查与 agent 的假设同源。

出处：`run_evidence/su_L2_s0_fcc2/cc_stream_011.jsonl`；`run_evidence/su_L2_s6_gpt6/app/report.md`；`run_evidence/su_L2_s7_fcc/cc_stream_006.jsonl`（计划），平铺数据只用于计时见同目录 `cc_stream_005.jsonl`。

### 6.5 设计更正：serve_ab 的耐心 θ 可从历史数据识别

**原来的声明**（DESIGN.md §3 和 `serve_ab.py` 文件头）："历史数据和护栏测试都不饱和，θ 不可识别；只能设计夜间 drill 去测。"

**实际情况**：在 M/M/c+M 里，放弃是以速率 θ 作用在等待中的请求上的，所以"放弃率 = θ × 平均等待"（Little 律用于放弃）**在不饱和的小时里也精确成立**。只要历史数据里有放弃和等待，θ 就能识别。drill 是更强的识别路径（信噪比更高），但**不是必需的**。

**证据**：

- GPT-6 在 8 个 serve_ab 运行里有 7 个 0 次 drill（sab_L1_s4 做了 1 次），Q1 区间 8/8 覆盖真值；
- Fable 在 6 个 L1/L2 有效运行里做了 2–4 次 drill。

**影响**：

- 真值和判分都不依赖这条声明，正确性不受影响；
- 但 serve_ab 的难度论证少了一条腿：P3 不再是"必须自己设计实验才能得到的信息"。GPT-6 在 serve_ab 的失败来自 P2 / P4（不外推到护栏之外），不来自 P3。

DESIGN.md 与 `serve_ab.py` 文件头已加更正说明。

### 6.6 其他教训

1. **证书认证率本身是设计信号。** scaleup L2 只有 4/10 认证。未过的种子里，团队 wd 本身已接近最优，同一个算子在这些实例上不起作用。
2. **有限总体 + 金标准可买 + 协变量可见 → 默认卫生必然解出**（judge_audit L1 饱和）。要变难，目标量必须不能由金标准抽样直接得到。
3. **serve_ab 有一个未被证书覆盖的启发式。** 在 sab_L2_s9 上，"利用率目标 0.85"这条策略的 regret 只有 0.00006，能过日程项。证书只把 `rho_0.95` 声明为诱饵，`rho_0.85` / `rho_0.90` 只作报告。它仍需要答对 Q1，所以整题不会因此变成送分，但日程项在这个实例上不需要识别机制。
4. **重复运行必须做。** scaleup L2 的 5 对重复运行里，结果全部相反（见 §4）。单次运行的"卡住"不能当作难度证据。

## 7. pipeline 在本轮实际做到了什么

| 阶段 | 本轮实际产出 | 可自动化程度 |
|---|---|---|
| S0 机制卡 | 三族的文件头 docstring | 人写（本轮由我写）；其中一处声明错了（§6.5），说明机制卡本身需要"识别路径穷举"检查 |
| S1 算子 | H7a/H7b（serve_ab L2）、D1（scaleup L2）、L0 去机制 | 人设计，代码实现 |
| S2 实例条件 | 闭式条件 + 证书 | 全自动 |
| S3 证书 | serve_ab 5 个状态文件，judge_audit 20 个种子，scaleup L1 4 个 + L2 10 个种子 | 全自动、可续跑 |
| S4 实跑 | 41 个有效运行 | 全自动（需要预算和网关） |
| S5 边界核查 | `dup_holdout_cf.py`、`line_cf.py`、`cfg_cf.py`，共 11 个结果文件 | 半自动：要人找出"做决定的那一步" |
| S6 习惯归类 | §5 的表 | 人工 + 轨迹检索 |
| S7 硬化 | L1 前沿解 → L2 诱饵（`l15/tasks/scaleup_l2_decoys/`） | 半自动：诱饵收录全自动，新算子要人设计 |

**S7 的效果**：scaleup 从 L1 的 6/6 到 L2 的 7/13。

- S7 击败了它明确瞄准的两个习惯：`row_rule` 和作业内随机 holdout。s0_gpt6 精确落在前者上，Fable 4 个失败都落在后者上。
- S7 没有击败它明确**放过**的路线：噪声鲁棒 + 对冲，这是开跑前就写下的。

也就是说 pipeline 的**预测是准的**：哪些路线会过、哪些会挂，开跑前都写出来了，实跑结果与之一致。缺的是一个能同时堵住这些已知通过路线的算子。

## 8. 局限

- **样本小**：每个任务 1–2 次运行，通过率的置信区间很宽，例如 Fable L2 4/8 → [0.22, 0.78]。
- **部分反事实只跑了一个副本**：scaleup 的判分是两个副本的平均。以下反事实跑了两个副本：
  - s6_fcc2 的指数与 distinct-N；
  - s6_gpt6 的 distinct-N；
  - s7_fcc2 的去掉二次成员；
  - s7_gpt6 的不衰减。

  以下只跑了 replica 0：4 个按重复组切分的反事实、s7 的 wd 扫描与组件消融。
- **"事先已知"的记录形式**：已知通过路线写在 `scaleup_l2.py` 文件头和证书信息项里，都在开跑前生成，但不是单独的正式预注册文件。
- **Fable 走 CLI 时间片**：Fable 在约 158 s 的 tick 里推进，`MAX_RUN_MIN` = 100，没有运行因此被截断。GPT-6 每个运行有 0–11 次 API 超时，照常计分。
- **数据是合成的**：scaleup 的语料由教师网络产生，但训练代码、判分和资源上限都是真实执行。
- **机制卡错误**：P3 的识别性声明错了（§6.5），是实跑后才发现的。

## 9. 下一步：L3 的设计要求

从本轮的实测里得出 4 条要求，每条都对应上面的证据：

1. **陷阱作用在每条路线都必经的环节上。** 本轮陷阱只作用在"作业内选择"这一步，对冲 / 保守 / 噪声鲁棒路线绕过了它（§6.1）。
2. **伤害通路不能被通用稳健技术关掉。** 本轮均匀标签噪声让"前向噪声校正"成为正确模型，从而关掉了"小 wd 记忆噪声"的通路（§6.2）。
3. **证书把本轮的非洞察通过 repo 原样收为诱饵。** 6 个 repo：s0_fcc、s6_fcc2、s7_fcc2、s0_gpt6b、s5_gpt6、s7_gpt6。它们必须在 L3 上 ≤ T − 0.015；设计的洞察（s5_fcc2 的"去重 + 不同行上 holdout"）必须仍能 ≥ T + 0.015。这正是 S7 的下一轮。
4. **机制卡增加"识别路径穷举"检查。** 对每个声称"只能通过 X 得到"的参数，列出所有能识别它的恒等式（例如 Little 律），并用零洞察策略测一遍（§6.5）。

候选算子（**未实现、未测**，只作为下一步）：

- **scaleup D1 + N2（实例相关噪声）**：把均匀噪声换成依赖特征的噪声。均匀转移矩阵的前向校正就不再是正确模型，"记住重复拷贝上的噪声标签"这条伤害通路也关不掉。证明义务：
  - 上面 6 个 repo 原样失败；
  - s5_fcc2 的路线仍过；
  - 噪声结构能从样本里的重复组识别（同一行的众包标签相同，所以要改成"拷贝间标签独立重抽"，让重复组本身成为噪声率的测量工具）。
- **serve_ab κ 依赖负载**：B 的慢速因子在高 B 比例下因批处理效率变化而改变，30% 的 A/B 测到的 κ 在 100% 下有偏。识别路径是夜间 drill 或非高峰的高比例测试。这属于"廉价测量有偏 + 外推"，是 v2–v9 唯一稳定的难点类型。
- **judge_audit L2**：让 verify 本身在某一类上有偏（Q1），或问反事实 / 外推量而非总体均值（Q2）。
