# v11：MLS 式、只用 CPU、非 QA 的 AI4AI 题（7 道，全部通过正确性证书）

一句话：每道题都是一个**能真跑的小实验室**。agent 只改一个文件（估计器、特征代码、缓存策略……），
由我们在 2 个可见设置和 4 个隐藏设置上**真的运行它**打分。每个设置都过线才算通过。
难度（GPT-6 / Opus 5 的通过率）**还没有测**：本会话调不到模型，命令见 §5。

---

## 1. 思路：从 MLS-Bench 学了什么，改了什么

MLS-Bench 的做法有三点：
1. **固定脚手架、窄编辑面。** agent 只能改一个模块，其余代码（训练循环、评测）固定。
   分数差异只能来自方法本身。
2. **可见设置 + 隐藏设置。** 在隐藏设置上评分，逼改进必须能泛化，靠调 dev 参数刷不上去。
3. **跟基线比。** 分数写成"比标准做法好多少"。

我们照搬了这三点，另外做了三处改动：
- **只用 CPU、几分钟跑完。** 每个"实验"是一个真实的小程序：真的训练梯度提升树、真的回放缓存
  trace、真的做交叉验证。世界由隐藏生成器产生，所以真值能精确算出来（最优缓存 Belady、精确的全量
  上线效应 GTE、信息公平的 oracle 等）。
- **二值通过：每个设置都要过线，不看平均。** "平均变好、某个设置崩掉"判不过。
  这就是 dev 全过、隐藏挂掉的诱饵能被抓住的原因。
- **每道题都有正确性证书**（§2）。MLS-Bench 靠人工审题，我们改成机器能复跑的检查。

## 2. 正确性怎么保证：证书

命令是 `python3 common/certify.py tasks/<题>`。它用题目自己的判分器把三类解各跑一遍：

| 候选 | 放在哪 | 要求 | 说明什么 |
|---|---|---|---|
| 参考解 | `reference/*.py` | 必须**通过** | 题是可解的，线是够得着的 |
| 基线 | `workdir/baselines/*.py` | 必须**不通过** | 教科书做法不够（agent 也能看到这些） |
| 诱饵 | `decoys/*.py` | 必须**不通过** | "看起来合理的聪明做法"也不够 |

结果写进 `certificate.json`。同时记录 `pass_dev_fail_hidden`，即"dev 全过、只挂隐藏"的候选，
用来说明隐藏设置确实在考泛化。

判分时的隔离：
- agent 的代码在**子进程**里跑，拿不到隐藏世界。
- 需要逐步喂数据的题（`cache_policy`、`temporal_leak`）用**锁步管道**：
  主进程发第 t 步，收到回复后才发第 t+1 步。子进程内存里从来没有未来数据，
  即使用 gc / 栈帧翻内存也偷不到。

## 3. 七道题（按考点区分，不按领域）

| 题 | 形式 | agent 交什么 | 常见做法为什么会错（考点） | 证书 |
|---|---|---|---|---|
| `sched_law` | 创新设计 | 从 4 条训练曲线预测**没跑过的** LR 日程的最终 loss | 三条已发表的日程 loss 定律（lr-area、momentum law、multi-power）都外推不到 warmup / 重启 / 更长的训练 | 参考 ≤ 0.034（线 0.10），5 个基线 + 诱饵全挂 |
| `dedup_cv` | 真实实验 | 模型选择规则 `select(X, y)` | 日志管道产生近重复记录，打乱的 K 折 CV 被泄漏，系统性偏向过拟合的配置；只去精确重复没用 | 3 个 CV 基线在全部 6 个设置挂；`always_smooth` dev 过、挂隐藏 |
| `unit_pipeline` | 真实实验 | 数据预处理 `fit_preprocess / transform` | 各医院导出单位不一致且没有文档，新医院没见过；按站点标准化会抹掉真实差异 | `robust_rowwise` dev 过、挂隐藏 |
| `delayed_labels` | 统计建模 | `fit_predict(history, snapshot, new)` | 12 个月违约标签还没成熟（右删失），加上经济环境漂移、销户是竞争风险；只用成熟窗口会过时，把销户当删失会偏 | 基线挂 4–5 个设置，诱饵挂 4–5 个 |
| `ab_interference` | 因果 / 实验设计 | 全量上线效应估计器 | 卖家之间抢份额（干扰），组间差、CUPED、回归调整都估的是"部分处理"的效应，不是全量 | `market_equal_weight`、`market_linear` dev 过、挂隐藏 |
| `cache_policy` | 系统算法设计 | 在线淘汰策略 `Policy` | key 模板里藏着访问模式；只看首个 token 会把热点和扫描混在一起；固定视野的 LHD 对参数敏感 | LRU、LFU-DA、ARC、S3-FIFO 全挂；`first_token_gittins` dev 过、挂隐藏 |
| `temporal_leak` | MLOps / 数据工程 | 特征代码 `features.build(tables, rows)` | 训练特征不是按"当时能看到的数据"构造的：销量会被修订、有门店晚报、闪购当天才决定。离线回测好看，上线变差 | 3 个基线全挂；`final_lags`、`safe_lag3` 挂 4–5 个；另有 2 个不同写法的正确解也通过 |

异质性的依据：7 道题的失败机制两两不同，分别是
- 外推定律选错；
- 验证集泄漏；
- 协变量的来源不一致；
- 删失 + 漂移；
- 干扰（违反 SUTVA，即"各单元的结果互不影响"这一假设）；
- 在线决策的类别粒度；
- 训练与服务时的信息不一致。

它们都不是 QA。按形式分：
- 交估计器 / 规则：`dedup_cv`、`delayed_labels`、`ab_interference`。
- 交数据管道：`unit_pipeline`、`temporal_leak`。
- 交在线策略：`cache_policy`。
- 交预测定律：`sched_law`。

## 4. 一个完整例子：`temporal_leak`

**场景。** 每晚（第 d-1 天结束时）预测明天每个门店的销量。模型固定（`model.py`，梯度提升树），
agent 只能改 `features.py`。数据仓库里每一行都带"写入时间"：
- 销量一天会写好几次。当晚先写一个不完整的初值，之后几天陆续修订到终值。
  有的链初值只有终值的 55%，有的因为退货后扣反而先高后低。
- 有些门店晚 1–2 天才上报。
- 促销有"计划日"，闪购当天早上才决定。
- 天气有"预报"和"实测"两种。

**判分怎么跑。** 先用第 n-1 天的仓库快照训练；再逐日回放 60 个上线日。
第 d 天只给"第 d-1 天结束时仓库的样子"，预测和第 d 天的**终值**比。
过线要同时满足两条：
- WAPE 不超过信息公平 oracle 的 1.55 倍。WAPE 是"总绝对误差 / 总销量"；
  信息公平 oracle 知道第 d-1 天之前的真实需求状态，但只看预报、只看已计划的促销。
- 系统偏差 |bias| ≤ 3%。

**起始代码为什么错。** 它用每天的"最新值"做滚动均值，窗口还包含当天；用了当天的实测天气和当天的缺货标记。
离线看，这些都是完美特征；上线时它们要么不存在，要么还是不完整的初值。
结果 WAPE 是 oracle 的 3.3–6 倍。

**两个"修过"的基线为什么也错。**
- `shift_all`：把所有输入都往前挪一天。但训练时"前一天"用的是终值，上线时是初值，照样错。
- `drop_leaky`：删掉一切可疑特征，只留销量滞后。依然是"终值训练、初值上线"，还丢了促销信号。
  所以它系统性低估 6–19%。

**参考解做了什么。** 对每一个训练行，都按"第 d-1 天结束时仓库的样子"重建特征：
- 第 d-k 天的销量取当时最新的那个版本。
- 只用已计划的促销，只用预报天气。

另外从已经定稿的历史里估出每个门店的修订曲线，把初值"放大回"终值。
这样训练特征和上线特征的含义完全一致。

**证书结果（metric ≤ 1 为过；按 dev_a / dev_b / hid_slow / hid_returns / hid_late / hid_shocky）：**
- 参考解：0.85 / 0.79 / 0.82 / 0.84 / 0.91 / 0.85。
- 另外两种写法（不做修订校正、全链统一修订曲线）也都通过。说明线不是贴着某一种实现画的。
- 诱饵 `final_lags`（其它全对，只是历史销量用终值）：挂 5 个设置，hid_slow 上系统低估 12%。
- 诱饵 `safe_lag3`（跳过最新两天、默认老数据已定稿）：dev_a 刚好过（0.998），其余挂 4 个。
  在修订慢的链上，3 天前的数据其实还没定稿。

**考的能力。** 能不能意识到"训练集也必须按当时的视角重建"，并从数据里自己发现修订和晚报。
task.md 没有明说这两件事，但 dev 数据里带 `recorded_at`，是查得出来的。

  每次运行默认上限 3 小时。

## 6. 已知局限

- **难度未测。** 以上只证明"题对、线够得着、标准做法和聪明诱饵过不去"，不证明前沿模型会走错路。
- **隐藏生成器在同一台机器上。** 如果 agent 能读任务目录以外的文件，就能拿到 `hidden/world.py`。
  harness 只拷 workdir，但没有用系统级沙箱。正式跑之前应放进容器。
- **余量不大的设置：**
  - `cache_policy` 的 hid_zipf：参考 0.415，线 0.35。
  - `temporal_leak` 的 hid_late：metric 0.91。
  - 更强但不同的解有可能挂在这里，需要从实跑结果回头复核。
- `delayed_labels`、`sched_law`、`temporal_leak` 目前没有"dev 过、只挂隐藏"的诱饵。
  隐藏设置在这几道题里的作用是防过拟合 dev，不是额外的考点。

## 7. 没做成的一道：`hpo_prune`（算力受限下选 lr / batch）

原型在会话临时目录，没有进 `tasks/`。世界是对角 NQM（带噪声的二次模型），loss 有闭式解。
试过的四种世界：
- 纯 cosine 到 0：最优 lr 永远卡在稳定性边缘，没有可学的结构。
- 按 token 预算：最小 batch 永远最好。
- 矩阵幂的乘法模型：loss 不是幂律。
- 常数 lr：lr* 随训练长度下降、B* 随长度上升，方向都对。但用短程探针拟合全局定律时，
  L0 和指数 α 分不开，噪声项系数 K 在短程里也识别不出来。参考解本身的后悔是 7–180 倍。

教训：**先证明参考解能从 agent 可见的数据里稳定识别出答案，再谈难度。**
这一步没过，题就不能发。
