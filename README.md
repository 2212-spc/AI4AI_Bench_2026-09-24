## 使用时要注意

1. **不要在本文件夹里直接跑脚本。** 有些脚本会写到 `/tmp/bench2` 或写死的会话输出路径。先把 `v2_2026-09-25/` 复制到临时目录，再在副本上跑。命令见 `实现指南_2026-09-25.md` §3，要改的写死路径见 §5.1。
2. **09-25 修了一个凭证漏洞。** 原来的 `cc_agent.py` 会把真 key 注入 Fable 的沙箱。`v2_2026-09-25/harness/` 里的两个运行器都已修好，现在只有网关读取 key。离线测试已通过，但还没有用真实实跑复测过，下次实跑前请先跑 `gateway.py --selftest`，再做一次“截获启动参数、断言没有真 key”的检查。**09-24 的 `bench_code/harness/cc_agent.py` 没有修，不要原样复用。** 详情见手册 §10 和指南 §5.3。
3. **建议轮换被测模型用的那把 API key。** 它在对话里以明文出现过，而且在 09-24、09-25 的 Fable 实跑中被放进了沙箱的环境变量。核查结果是：任何文件里都没有这把 key，v2 的流日志里也没有读取环境变量的动作；09-24 那批实跑没有存流日志，无法回查。本文件夹里不含 key。以后复跑时，用环境变量 `SEC_DIR` 指向你自己的目录，里面放 `key` 和 `url` 两个文件（见指南 §5.2）。
4. **`v2_2026-09-25/harness/bin/apply_patch` 是 09-25 整理时补上的。** GPT-6 的运行器会把它挂载到沙箱里的 `/opt/tools`，v2 最初的交付里漏掉了它。
5. **v2 的“Harbor 格式”只是目录结构和 `task.toml`。** 这个环境没有 docker，也没有真正运行过 harbor。投 TBS v0.2（截止 2026-10-05）之前，必须先用真的 harbor 跑一遍（见指南 §6.3）。
6. **样本量很小。** 所有“模型在哪里失败”的结论，都只是说这件事发生过、可以重放，不代表统计上站得住。
