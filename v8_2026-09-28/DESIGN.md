# v8 设计：一条"可迭代加难、但正确性不退化"的造题 pipeline

2026-09-29 · 对应代码 `l15/`（世界、闸门、证书驱动）与 `harness/`（前沿实跑）

---

## 0. 结论先行

v8 把一道题的两个性质拆成两张证书，互不推断：

| 证书 | 回答的问题 | 由谁签发 | 能否自动化 |
|---|---|---|---|
| **正确性证书** | 真值对不对、判分器会不会冤枉对的答案 / 放过错的答案、参考解是否只用公开信息就能在预算内通过、每个评分项是否真的在起作用 | 闭式真值 + 实例闸门 + 族闸门（§4），每轮从零重跑 | 全自动，零模型调用 |
| **难度证书** | 顶尖模型会不会在这道题上交出一个自洽但错的答案 | 前沿实跑 + 每个 fail 的边界核查（§2 S6） | 只能半自动：跑是自动的，但必须读轨迹 |

"加难"用的是**轨迹驱动硬化**（§2 S7、§6 的 r_retune → r_crit 实例）。流程是：

1. 读前沿模型的**通过**轨迹，找出它依赖、而世界恰好满足的那个前提。
2. 加入一条有文献依据的机制，让这个前提在新实例上不成立。
3. 上一版的参考解（oracle）降格成新版的诱饵，必须在远离阈值处失败。
4. 新 oracle 仍只用公开事实，在预算内通过。

每一轮都是一个新模块（不改旧模块），正确性证书整套重跑。闸门保证的只是"对"与"反捷径"，"难"只能从实跑中来。

## 1. 目标函数：什么叫"卡住了前沿"

**v8 不变式**：前沿模型失败，只能发生在"它自己的检查，在一个完整、自洽、但错误的答案上判 PASS"的时候。

这句话同时是造题目标和验收标准：

- **陷阱必须让标准实验卫生本身产出错误答案**。要么是控制变量做错，要么是在同一个 dev 集上复评，要么是用短程代理调参，要么是丢掉删失样本。只让"偷懒的做法"失败没有用：v8 的首轮实跑里，Fable 一上来就做了 2×2 析因加单改重训，默认的实验卫生直接打穿了所有"混杂 / 耦合"类陷阱（见 `L15_v8_report.md` §3）。
- **错误答案必须落在远离阈值的地方**。每个声明的陷阱配方，其期望后悔 ≥ `K_TRAP × EPS`（r_crit 取 4×）。这样前沿的失败是"答错了"，而不是"差一点"。实跑时每个 fail 都要记录它距阈值的倍数（§2 S6）。
- **不算数的失败**有三类：
  - 基础设施失败：截断，或 provider 安全分类器拦截；
  - 判分器的浮点边界失败：v8 里修过一个，是 `>` 比较没加 1e-9 松弛造成的误判；
  - 欠规定导致的失败。

  前两类进 `EXCLUDED.md`。api_errors 不是排除理由，v7 曾因此误排除过，已回滚。

## 2. Pipeline 总览

```
 S0 机制卡 ──► S1 闭式世界 ──► S2 构造式实例条件 ──► S3 实例策略闸门 ──► S4 族闸门 ──► S5 覆盖率审计
   ▲                                                                                        │
   │                                                                                        ▼
 S7 轨迹驱动硬化 ◄──────────────────── S6 前沿实跑 + 边界核查 ◄────────────── 证书 OK 的 12 实例池
 （旧 oracle → 新诱饵，新机制 → 新模块，回到 S1，正确性证书从零重跑）
```

| 阶段 | 输入 → 产出 | 保证什么 | **不**保证什么 | 代码 |
|---|---|---|---|---|
| **S0 机制卡** | 一条已发表的 ML 机制 + 一个研究者默认会做的假设 + 该假设导致的捷径 → 陷阱表 P1…Pn | 考点是真实 AI4AI 能力（调参迁移、归因、为不可测目标做优化），不是解谜 | 前沿会上当 | 每个 `tasks/*.py` 的模块文档串 |
| **S1 闭式世界** | 机制 → `E[loss] = F + A(u−μ)² + C(T)(w−ν)²` 这类闭式期望 + 公开噪声模型 | 最优解、每个诱饵的后悔、oracle 的误差模型都**算出来**，不是采样出来 | 机制参数的先验合理（靠文献和人读） | `truth()`、`optimum()`、`penalty()` |
| **S2 构造式实例条件** | 隐藏参数 θ → `_conditions(p)`：一组闭式布尔条件 | 以下六项同时成立：每个陷阱 ≥ K_TRAP·EPS；每条可背诵规则 ≥ K_DECOY·EPS；可解（oracle 自己误差模型下的期望后悔 ≪ EPS）；预算够；可发现（agent 可见数据能以 ≥4σ 否定朴素前提）；廉价代理看不见关键量（T1） | 前沿想不到 oracle 的做法 | `_conditions`、`sample_params`、`instance_gate` |
| **S3 实例策略闸门**（v7 继承） | 实例 × 4 个噪声盐 × 全部脚本策略，走真实 `Session` 和真实噪声 | oracle 在 ≥3/4 盐上通过；每个诱饵、nop、坏 JSON、作弊探针全部失败 | 失败的原因对不对 | `l15/gates.py` |
| **S4 族闸门**（v8 新增 5 个） | 通过 S3 的实例 → 12 实例池 | 见 §4 | 难度 | `l15/v8gates.py`、`l15/v8cert.py` |
| **S5 覆盖率审计** | 在**接受池**上，求任意固定猜测（背诵常数）最多能覆盖多少实例 | 不存在"背一个数就能过一大片"的空隙 | — | `/tmp/rc/cov2.py` 的思路，数字写进 §7 |
| **S6 前沿实跑 + 边界核查** | 池中实例 → Fable / GPT-6 / 对照模型，真实 agent 回路 | 这是难度证书的唯一来源。每个 fail 都要核查三件事：距阈值倍数、最近诱饵（grader 的 `closest_decoy`）、轨迹里的失败机制 | 结果的统计显著性（n 小，见 §10） | `harness/`、`l15/grade.py` 的 `diag` |
| **S7 轨迹驱动硬化** | 前沿**通过**的轨迹 → 它依赖的"世界恰好满足的前提" → 新机制 | 新题的难点针对的是真实前沿行为，不是作者的想象 | 新难点一定能卡住前沿，所以要回到 S6 | §6 |

### 各阶段的要点

**S2 是"构造"，不是"筛选"。** 在 a_span 上，21 个难度条件各自拒绝 20–80% 的实例，拒绝采样 1199 次命中 0 次。改成先找出一个"隐藏、自由、且与所有诱饵答案正交"的实例参数（a_span 里是流量混合 π），再在闭式条件下搜索它，产率从 0 升到 17%。`_conditions` 同时充当提议器和验证器：`instance_gate` 的 identity 模式会拿它和 grader 的 `truth()` 交叉核对。

**S2 的可解性必须用 oracle 自己的误差模型来算。** a_span 的旧 screen 只算了 canary 噪声，漏掉了两件事：设计矩阵本身也是测出来的（EIV），以及 Σπ=1 约束。结果误差低估了 25%。oracle 用拟合残差（约 2 个自由度）定区间，8 个 salt 漏覆盖 5 个。修复后 147/150 覆盖。在 r_crit 里，这条变成三个条件：

- 走步定中心的步数 ≤ MAX_WALK−1；
- 全长括号能覆盖定中心误差；
- 整套协议的成本 ≤ BUDGET。

**S6 的边界核查不是可选项。** v8 有一次实跑 fail，最后查明是判分器的浮点比较（`0.4500000000000002 > 0.45`）。每个 fail 先查它离阈值多远，再查它最像哪个诱饵，最后读轨迹。

## 3. 为什么"加难"不会让题变错

轨迹驱动硬化每一轮都改世界，所以必须说明正确性为什么不会退化。靠的是以下八条不变式，每条都由机器检查：

| # | 不变式 | 怎么检查 | 违反过吗 |
|---|---|---|---|
| I1 | 真值是闭式的，grader 与生成器共用同一个 `truth()`，但 grader 只读 artifacts 和 ledger | `instance_gate` identity 模式、`mutation_test` | 否 |
| I2 | **修复不继承严格性**：新难点写成新模块（`r_crit.py` 引用 `r_retune.py` 的常量和工具函数，但不修改它），证书整套从零重跑 | `v8cert r_crit ...` 独立产出 `v8_reports/r_crit.json` | — |
| I3 | 旧 oracle 降格为新诱饵：必须失败，失败必须落在声明的评分项上，而且离阈值 ≥ K_TRAP·EPS | `_conditions` 的 C1b 条件 + `p_ablation`（P7 `proxy_did`、P8 `short_trend`，均 4/4 盐失败且落在 R1） | 否 |
| I4 | 新 oracle 只调 `Session` 的公共操作、只用题面公开的常量，在 ≥3/4 噪声盐上通过 | S3 闸门；`item_activity` 里 oracle_rate=1.00 | r_crit 初版 C3（oracle 可行）在 batch 变体上失败约 50%，修成走步定中心后降到 3–8% |
| I5 | 答案的中性改写不翻转判定，明显错误的答案必须翻转判定 | `mutation_test`（r_crit 有 5 个变异，其中 `p7_recipe` 专门把陷阱配方写进答案） | v4 曾有两个会误杀正确答案的 grader bug（当时靠单元测试发现），这条闸门把那次教训固化下来 |
| I6 | 没有惰性项（人人都过）和坏项（oracle 过不了） | `item_activity` | a_span_min R2 的 oracle_rate 为 0.83，查明是 2.5σ 区间的自然漏覆盖，不是坏项 |
| I7 | 所有"不超过 X"的比较都带浮点松弛 `> CAP + 1e-9` | 前沿实跑的边界核查 | 违反过一次（bcm5），已修，已重评 |
| I8 | 题面与断言可追溯：instruction 里的数字（预算、容差）由代码替换生成，每次替换都 `assert` 恰好发生一次 | `r_crit.instruction` | r_crit 初版沿用了 r_retune 的题面数字（224 credits / 0.0008），被这条修掉 |

## 4. 闸门：各保证什么、抓到过什么

S3 的 v7 继承闸门（oracle 通过、诱饵失败、nop / 坏 JSON / 作弊失败、沙箱隔离）不再重复。下表是 v8 新增的族闸门：

| 闸门 | 规则 | 为什么需要（实测事件） |
|---|---|---|
| **p_ablation 原则消融** | 每条原则 Pk 绑定一个诱饵策略和它负责的评分项。该诱饵必须从不整体通过，且至少一半的盐失败在声明的项上 | 诱饵也可能因为 JSON 写坏、预算用完而失败，这种失败说明不了它缺的是哪条原则 |
| **item_activity 评分项活性** | 统计每个评分项在全部策略 × 盐上的通过率；另单列 oracle 的通过率 | 人人都过的项是装饰；oracle 过不了的项是 bug |
| **mutation 答案变异** | 从一个真实的通过答案出发，做小改动（中性改写）和大改动（明显错误），前者不得翻转判定，后者必须翻转 | v4 曾有两个 grader bug 会拒收正确答案（缺默认参数崩溃、6 位小数舍入后逐位比较）。这类 bug 靠"诱饵照预期失败"永远发现不了 |
| **search 搜索闸门** | 每族必须声明 `SEARCH`：若干"用最朴素的测量去扫答案空间"的策略，全部必须失败 | a_stack 过了 v7 全部九道闸门、8 个实例条件和原则消融，却被一个零洞察的暴力策略 18/18 打穿：在目标负载上把可行子集各测 1 次，取 argmax |
| **pool 实例池** | 用随机重启贪心构造 12 实例池，满足众数答案上限等池级约束 | 顺序贪心会卡死（b_control 只返回了 3 个实例） |

六个族的证书结果：

| 族 | 候选 → 实例闸门干净 → 池 | 原则消融 | 搜索策略（均 0 通过） | 评分项活性（通过/总数，oracle 通过率） |
|---|---|---|---|---|
| a_span | 240 → 31 → 12 | 5 条全 OK | rank_uniform / borda / minimax | R1 18/54 (1.00)，R2 14/54 (0.83)，R3 34/54 (1.00) |
| a_span_min | 240 → 31 → 12 | 同上 | 同上 | R1 19/54，R2 21/54 (0.83)，R3 38/54 |
| b_control | 60 → 32 → 12 | 4 条全 OK | coupled_loo / rescore_only | R1 30/42，R2 18/42，R3 18/42 |
| b_control_min | 60 → 32 → 12 | 4 条全 OK | coupled_loo / rescore_only / ext_only | R1 30/42，R2 6/42 |
| r_retune | 240 → 32 → 12 | 6 条全 OK | successive_halving / proxy_grid / full_ofat | R1 12/66 (1.00)，R2 60/66 |
| r_crit | 240 → 32 → 12 | 8 条全 OK | 以上 3 个 + full_cross | R1 12/78 (1.00)，R2 66/78 |

r_crit 的 R1 只有 oracle 能过（12/78，正好是 oracle 自己的 12 次运行），说明所有脚本化的"合理做法"都被 R1 拒绝。R2（报告自己配方的损失区间）比较容易，它的作用是防止"配方对了但完全不知道结果"。

## 5. 定律（每条都有 v8 的实测证据）

1. **难度在于廉价测量是否有偏，不在搜索空间多大。** a_stack 的朴素测量是无偏的，所以穷举能赢。b_control 的穷举恰好就是 oracle 的骨架，但朴素测量估错了量，所以穷举照样失败。推论："选最优配置"一类的题天生可以被搜索，只有当目标**不可测**（必须预测、外推或重构）时，难度才立得住。
2. **构造，而不是筛选**（§2 S2）。
3. **可解性要匹配协议本身**：oracle 的误差模型就是可解性条件的误差模型。
4. **闸门证明的是正确性和反捷径，不是难度。** a_span / b_control 通过了全部 v8 闸门，Fable 首轮仍然 4/4 通过。
5. **"披露杠杆"被同实例否证。** 把题面里的世界模型删掉（`*_min` 变体，另配可发现性证书），Fable 仍 4/4 通过。原因是操作接口的 affordance 本身就在泄露世界模型：`score` 暴露了 `harness=` 参数，canary 规定"每窗口至多 1 个改动"。
6. **陷阱必须让标准实验卫生产出错误答案**，而且错误答案要远离阈值（§1）。
7. **背诵抵抗来自"效应量 ≫ 容差"，不能靠条件去挖空隙。** 覆盖率必须在接受池上算（§7）。
8. **轨迹驱动硬化**：前沿通过所依赖的那个前提，就是下一版的陷阱；上一版的 oracle 就是下一版的诱饵（§6）。
9. **判分的一切比较都要加浮点松弛；每个前沿 fail 都要先查边界。**
10. **排除规则**：只排除截断和安全分类器拦截，不排除 api_errors。被拦截的实例不改写题面去绕过，而是换同模板的另一个池实例重跑。

## 6. 完整示例：r_retune → r_crit（一轮轨迹驱动硬化）

**r_retune（第一版）。** 场景是生产配方 (lr0, wd0) 在当前 setup 上是最优的；集群迁移后，batch 或 token 预算被迫变化，要在大约 3 次全长训练的预算内重调 (lr, wd)。陷阱有四个：

- P3：只调 lr；
- P4：背 τ 律指数 1；
- P5：在短代理上直接调；
- P6：在错误的坐标上做 OFAT。

oracle 的做法是三步：锚点校准的代理 DiD（深度 4）定 lr；在 wd 曲率可见的时长上测 β；最后跑 1 次全长确认。

**第一轮实跑。** GPT-6 0/6，全部远失败（阈值的 22–557 倍：背规则、lr 方向反了、只做单侧检查）。Fable 在 4 个有效实例上 2 过 2 挂：rr10 是 2.1×（平坦谬误），rr29 是 2.4×（P4：lr·wd 低了 0.16 octave）。

**读 Fable 的通过轨迹。** 两次通过都从短程 run 取 lr，用的是锚点校准 DiD，或者拟合"lr 最优值随时长的幂律"再外推。在 r_retune 里这两种做法都是**精确**的，因为世界里 μ 对 (log batch, log tokens) 是线性的。所以 Fable 依赖的前提是"全长的 lr 最优值可以从短程读出来"，而这个世界恰好满足它。

**新机制：临界 batch 随训练增长。** 依据是 McCandlish 2018：lr 在临界 batch 以下随 B 增长，以上饱和。Zhang 2024 进一步发现临界 batch 随数据量增长。

```
Bc(T) = c0 + κT                         （log2 临界 batch 随 tokens 增长）
μ(B,T) = u0 − αT + ρ[sm(B, Bc(T)) − sm(0, c0)]      sm = 平滑 min（s=1 时即 McCandlish 形式）
```

在目标时长上，新 batch 位于临界值以下，所以 batch 增益是满额的。到 1/16 时长时，Bc 低了 κ·4 ≈ 2–3.6 octave，增益已经饱和。由此得到两个新陷阱，都是闭式可算、逐实例检查的：

- **P7：代理 DiD 有偏**，测到的是短程饱和后的增益。这正是 r_retune 的 oracle。
- **P8：时长趋势是弯的**，短程拟合再外推就偏。这正是 Fable 的另一种通过路线。

**新 oracle（只用公开事实）。** 分三步：

1. 在 1/8 时长做 1-seed 的"走步" DiD，只用来**定中心**。每条 3 点扫描向更好的一侧走，直到括住最小值。
2. 做 r_retune 的有效衰减扫描。
3. 在全长上做自适应 3 点 lr 括号：先测 c±h/2，再往更好的一侧外延一步。顶点就是 lr，抛物线在顶点处的值就是损失，区间由 Lagrange 权重给出。

**迭代中踩过、又修掉的坑**（都由 S2 条件或 S5 审计暴露，没有一条靠人眼）：

- 定中心深度设为 2 时，batch 变体的预算条件 100% 失败，因为深度 2 每个 run 花费 16。改成深度 3。
- oracle 可行性条件 C3 在 batch 变体上失败约 50%，瓶颈是短程 lr 的散布达 3–5 octave。改为走步定中心，同时改进公开的中心公式，预算改为 384 → C3 失败降到 3–8%。
- 初版背诵覆盖率：原始 23–43%，池上 44–88%。修法见 §7。
- 题面沿用了 r_retune 的数字，由 I8 修掉。

**结果。** 证书一次通过：池 [0,9,10,11,18,19,20,21,22,24,29,30]，陷阱配方的后悔为 10–285 × EPS，oracle 花费 322–376 / 384。

前沿实跑：Fable 2/6（两次通过都在 batch16x 上；4 个 fail 分别为 39.8×、33.5×、3.5×、29.4×），GPT-6 0/4（204–960×）。细节与逐个边界核查见 `L15_v8_report.md` §2–§3。

## 7. 背诵抵抗：覆盖率必须在接受池上算

**测法。** 取"任意一个固定的 lr 偏移猜测（假设 wd 完美）"，看它最多能让多少比例的实例落进 R1 容差。

**教训。** 实例条件在筛选时会把接受池挤进"背诵规则之间的空隙"，所以原始先验上的覆盖率会系统性低估池上的覆盖率。r_crit 初版的原始覆盖率只有 23–43%，池上却达到 44–88%。一个"介于 sqrt 和 linear 之间"的对冲猜测就能过一大半。

**修法**：

- 加大杠杆臂：只保留使 lr 移动 ≥3 octave 的变体（8x/16x），去掉 2x/4x；
- 放宽隐藏参数范围：α ∈ [0.05, 0.70]，ρ ∈ [0.20, 1.00]；
- 收紧容差：EPS 0.0008 → 0.0006。

注意：把 α 收窄到 ≤0.45 反而把池覆盖率推到 0.46–0.47，已回滚。

**定稿数字**（每变体约 1100 个样本）：

| 变体 | 接受率 | 池覆盖率（最佳固定猜测） | 原始覆盖率 |
|---|---|---|---|
| batch8x | 0.18 | 0.27 | 0.13 |
| batch16x | 0.20 | 0.22 | 0.10 |
| tokens8x | 0.14 | 0.22 | 0.16 |
| tokens16x | 0.15 | 0.16 | 0.12 |
| batch2x_tokens8x | 0.08 | 0.31 | 0.14 |

这些覆盖率是**最乐观的上界**：它假设 agent 事先知道该猜哪个固定值、并且 wd 完美，而背诵常数的通过率远低于此。实例条件 C1 还逐实例排除了"任何可背诵规则落在 K_DECOY·EPS 以内"的情况。

## 9. 异质性矩阵（v8 的六个族）

| | a_span | b_control | r_retune | r_crit |
|---|---|---|---|---|
| **AI4AI 场景** | 推理服务：为不可测的生产流量选一组优化改动 | 发版回归归因：某些改动同时动了训练管线和评测 harness | 预训练：批量或 token 预算被迫改变后重调 (lr, wd) | 同 r_retune，但临界 batch 随训练增长 |
| **能力** | 为不可测目标做优化（重构 + 外推） | 因果归因（测量工具被处理污染） | 实验设计 + 迁移 | 实验设计 + 识别"短程不可外推" |
| **难点机制** | Q1 目标不在可测集合里；Q2 廉价测量有偏；Q3 桥是线性的，组合是非线性的 | P3 固定标尺；P4 模型侧改动需要重训 | P3–P6（wd 要动 / τ 指数要测 / 代理有偏 / 坐标） | P7 代理 DiD 饱和；P8 时长趋势弯曲（+ P1–P6） |
| **交付物** | 改动集合 + 生产加速区间 + 集合内最弱成员 | 罪魁 + 效应区间 + 仅动 harness 的集合 | 配方 (lr, wd) + 损失区间 | 同左 |
| **搜索为什么无效** | 目标负载上结构性地不可测 | 朴素测量估错了量 | 全长 OFAT 在错误坐标上；代理扫描有偏 | 同左 + 全长交叉扫描预算不足 |
| **最小披露变体** | a_span_min | b_control_min | — | — |
| **前沿结果** | Fable 4/4，GPT-6 2/4 | Fable 4/4，GPT-6 4/4 | Fable 2/4，GPT-6 0/6 | Fable 2/6，GPT-6 0/4 |

四个族的机制互不相同：

- a_span 是"缺测量"；
- b_control 是"测量被污染"；
- r_retune 是"代理有偏 + 规则不可背"；
- r_crit 是"代理在目标处的行为随时长变化"。

交付物也各不相同。r_crit 和 r_retune 共用场景，这是故意的，用来做"只改一个机制"的对照。

## 10. 局限（诚实说明）

1. **样本很小。** 每族只跑了 2–6 个前沿实例，结论是方向性的，不是统计显著的。两个前沿模型都用单次运行，没有重复。
2. **Fable 的失败离阈值不远**（r_retune 两次都是 2–3×）。r_crit 的目的就是把这种失败推远。这一点做到了：r_crit 上 Fable 的 4 个 fail 中 3 个在 29–40×，1 个在 3.5×。但通过率没有明显下降（2/4 → 2/6），两次通过用的是同一招（见 report §3.2），那一招就是下一轮 S7 要打破的前提。
3. **只有一种正确 oracle。** r2 C4 要求的"替代正确解接受率"没有独立实现，目前靠 mutation 的中性改写近似代替。
4. **没做隐藏 OOD 分割，也没做归一化分。** v8 用二值判定加倍数诊断，更适合"卡住前沿"这个目标，但不利于和 MLS-Bench 横向比较。
5. **轨迹驱动硬化需要人读轨迹。** S7 的"找前提"一步目前由我读轨迹完成，还没自动化。可行的自动化方向：把 grader 的 `closest_decoy` 诊断反过来用，统计通过轨迹里的操作序列与哪个脚本策略最像。
6. **安全分类器。** 有 3 次运行在 provider 侧被拦截（rr11 / rr16 / rc0 的 Fable）。按规则没有改写题面，换实例重跑，记录在 `EXCLUDED.md`。
7. **闭式世界是"L1.5"。** 机制来自文献，常数是反事实的。它考的是研究推理，不是真实 GPU 上的工程能力。CPU-only 的约束下，这是有意为之的取舍。
