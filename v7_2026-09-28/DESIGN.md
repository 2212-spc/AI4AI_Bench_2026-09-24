# L1.5 题库设计（v7，2026-09-28）

## 0. 什么是 L1.5

| 层 | 世界 | 真值来源 | 问题 |
|---|---|---|---|
| L1 现实 | 真跑训练 | 实测 | 贵、不可复现、无法保证可解 |
| **L1.5（本轮）** | **已发表 ML 机制 + 反事实常数 的模拟器** | **模拟器本身即真值，可穷举最优** | 需要自己造机制、防背诵 |
| L2 纯虚构 | 任意合成系统 | 合成 | 与 AI4AI 能力脱钩，沦为解谜 |

L1.5 的三条硬约束：

1. **机制是真的**（数据受限缩放、临界 batch、退火律、验证器可利用性……都来自文献），所以任务考的是研究者真实会用的推理；
2. **常数是反事实的**（每个实例重采样 θ），所以背论文里的数字必拿 0 分；
3. **模拟器是真值**，最优解可穷举 ⇒ 后悔可以机械计算，不需要 LLM judge。

与 v6 的关键差别：v6 是"给定世界，回答问题"（QA / 单次判断）；v7 是"给你一个带预算的实验室 `lab`，自己设计实验、自己决定测什么、交付可执行产物"。

## 1. 交付物形态（针对"目前集中是 QA 我觉得不合理"）

| 形态 | 任务 | 判定方式 |
|---|---|---|
| A. 配置决策 + 预测区间 | K2、K3 | 模拟器算该配置的真值损失 → 后悔 ≤ tol；区间须覆盖真值 |
| B. 提交算法（代码）在隐藏世界上跑 | K4、K6 | 沙箱内跑 agent 的 `.py`，用 3 个新世界的成绩归一化 |
| C. 诊断 + 修复 | K8 | 修复配置在隐藏重跑上达标 + 声明的病因必须通过 grader 的反事实干预检验 |
| D. 估计器（代码）+ 区间 | K1 | 在隐藏评测群体上跑 agent 的估计器，看覆盖率与宽度 |

没有一道是选择题或事实问答。

差异是"机制 × 交付物 × 预算单位 × 失败机制"四维都不同，不是换皮。

## 3. 每题的闸门（TB-Science 风格）

verifier 只看 `task.toml` 里声明的 artifacts + lab ledger，判定全机械。实例接受条件：

1. **可解性证明**：oracle 策略在 ≥3/4 个噪声盐上通过（存在性，不是运气）；
2. **诱饵必死**：所有 `fail` 策略（近视/背诵/nop/cheat/crash/各种半对的中间策略）在每个盐上都不通过；
3. **廉价筛**：`instance_gate` 在无噪声近似下要求 oracle 与最好的简单策略之间有 ≥ 0.07–0.08 的归一化分差距，且 oracle 与基线的绝对差距够大（否则噪声会淹没区分度）；
4. **沙箱**：提交的代码在 bwrap 里跑，`--unshare-all`，看不到 `/app`、`/hidden`、无网络（已实测：`cheat_probe` 只能看到 `/sub` 里自己的文件，socket 连接失败）。

τ（归一化分阈值）写进 instruction，容差是显式数字，不是"尽量好"。

## 4. 自动化 pipeline

    sample_params(seed) → instance_gate(p)   # 秒级无噪声筛，淘汰 ~1/3 种子
        → l15.gates <mod> <seed> --salts 4   # 真 Session、真噪声、12 个策略 × 2-4 盐
        → l15.build <mod> <seed> <out>       # 生成 instruction/docs/starter/hints/hidden
        → harness/launch.py + drive.py       # 多模型并行跑
        → l15.grade <run_dir>                # 同一个 grade() 判定
    
一道新题只需要写一个 `l15/tasks/<name>.py`，提供 `sample_params / World(OPS, grade) / STRATEGIES / instance_gate / instruction / docs / hints [/ starter / instance_truth]`，其余全部复用。难度不是声明的，是 gates 量出来的。

### 4.1 这一轮真正学到的：pipeline 必须自带的五条闸门

下面每一条都不是设计时想到的，都是**被实测打脸之后**加进去的。写在这里是因为"稳定造出新题、难题、正确的题"这个目标，靠的就是把这些教训固化成代码里跑得动的检查，而不是靠作者下次更小心。

**(1) 筛实例，不要调阈值（screen the instance, not the bar）。**
K6 的记忆型诱饵在最幸运的噪声盐上能打到 s≈0.87–0.89，而 τ=0.90。降 τ 等于设计上放它过，升 τ 等于开始误杀正常在线调度器。正确做法是换一个实例：只保留"整个记忆家族在每个噪声盐上都离 τ 有 SCREEN_MARGIN 距离"的种子。K1 同理——24 个种子里只有 5 个同时满足"oracle 覆盖率超 τ 有余量"和"每个诱饵都差 τ 有余量"，**接受率 21%**。筛掉 79% 的种子是划算的：筛一次几秒，跑一次 gate 几分钟，而一道坏题浪费的是整轮模型实跑。

**(2) 诱饵是测出来的分类，不是作者的品味。**
同一个策略在不同实例上会换边。K6 的 `myopic` 原本是必须 fail 的诱饵，实测 s=0.94–0.97，于是改判为第二条存在性证明；`noprior` 在陡 ramp 上是合法解（0.83–0.95），在平 ramp 上塌到 ~0.6，于是改判为诱饵。K1 的 `overshrink` 原本是诱饵，修掉 oracle 的 bug 之后它只把宽度从 0.119 改到 0.113、覆盖率仍是 1.00——它不再因为任何理由失败，于是从 STRATEGIES 里移出。**每一次改判都要在代码注释里留下测量值和理由**，否则下一个人只会看到一个没解释的分类。

**(3) 容差必须从机制自身的精度量出来。**
K3 的 WIDTH_CAP 从 0.40 收到 0.20（oracle 自身预测误差 p90=0.066）；K1 的从 0.10 放到 0.26 再收到 0.17。方向相反，逻辑一样：**凭品味写下的容差要么让题不可解、要么让题不测任何东西**。

**(4) 从坏参照量出来的数不是测量。**
K1 的 WIDTH_CAP=0.26 是"实测"的——测的却是一个有 bug 的 oracle。`point_from` 里 `den` 同时被用作反演分母 `1-fp-fn` 和权重归一化分母，于是每个点估计都除错了数：点偏差 +0.04~+0.19、宽度 0.26。修掉之后偏差 ~0.00、宽度 0.118–0.143，容差落到 0.17。**存在性证明本身必须被验证**，否则整道题会围着 oracle 的 bug 长出来，而且看起来一切正常（覆盖率、宽度、诱饵分离度都有数）。这也正是 K1 这道题要考的东西，讽刺但不意外。

**(5) 评分常量必须和题面一起冻结。**
`l15.grade` import 的是**活模块**，instruction 却是 build 时冻结的。把 K3 的 WIDTH_CAP 从 0.40 调到 0.20 之后重新评分，gpt-6 那次本来合法的 0.38 宽区间被判成 `R0_artifact` 失败——**把 harness 的 bug 报成了模型的失败**。现在 `l15.build` 把模块里所有常量写进 `hidden/grading_consts.json`，`l15.grade` 在评分前比对，不一致直接抛 `StaleTask`。陈旧的题目要响亮地报错，不能悄悄地低分。

### 4.2 增加难度的可用杠杆（实测有效 / 无效）

| 杠杆 | 实测结论 |
|---|---|
| **改变估计目标（estimand）** | **有效**。K1 原本估竞技场均值，代数上可证全局一次性校准恰好无偏——**任何噪声/偏置调参都不可能把它和分层校准分开**。改成"按生产流量配比加权"之后，全局校准立刻有偏而分层无偏。**估计量存在简单无偏解的题，不可能靠调偏置变难。** |
| **让隐藏世界之间的差异变成结构性的** | **有效**。K6 原本的隐藏 run 只是噪声重抽样，于是"背下 dev 副本的曲线"打穿一切（fable s=1.32，7 次 lab 调用）。改成每个 run 重抽切换点、幅度、切换后斜率之后，记忆家族塌到 0.69。 |
| **压平"可离线学到"的那部分信号** | **有效**。K6 的 ramp 太陡（k≈2.7）时，"跟着 ramp 走"就是大部分收益，而 ramp 恰好是离线可学的，记忆策略能拿 0.82–0.89。压平到 k∈[0.35,0.65]、把价值挪到切换检测上之后，区分度才出现。 |
| **加噪声 / 减预算** | **基本无效**，且危险。它同时伤害 oracle 和诱饵，通常只是把题变成运气题。K1 里收紧区间（z 调小）确实能杀掉 hedge，但同时把 oracle 的覆盖率一起杀了。 |
| **提高阈值 τ** | **无效**。见 (1)：τ 只能在"放诱饵过"和"误杀正解"之间选，真正的自由度在实例，不在阈值。 |

### 4.3 生成新题的实际成本（本轮实测）

以 K1 为例，从"机制选定"到"两个实例上线"：探索脚本 12 个（k1a–k1m），推翻过 3 次设计（偏置对称抵消 → 冗长偏置也不行 → 换 estimand），发现 1 个会毁掉整道题的 oracle bug，种子接受率 5/24。这不是可以省掉的开销，**它就是"正确的题"的成本**；pipeline 能做的是让每一次推翻都便宜（秒级 screen）、让每一次错误都留痕（注释里写测量值）、让陈旧产物自己报错（grading_consts）。

### 4.4 pipeline 必须自带的另外三条闸门（第二轮实测补充）

(1)–(5) 是围绕"题目本身是否正确"的。下面三条是围绕"**测量过程是否正确**"的——它们都发生在题目已经造好之后，都不会让任何一次 gate 变红，因此只能靠专门去查。

**(6) 池级性质只能在池上检查（pool gate）。**
K2 每个实例单独看都合格：最优配比可辨识、相对近视解有真实增益、所有诱饵全灭。但把 4 个实例放在一起看，**一个固定配比在 19 个已过闸种子里打穿 18 个**——不调 lab、不做实验，直接交一个"像样的预训练配比"就赢。"答案在实例之间会不会移动"是**池的性质**，per-instance 闸门在结构上看不见它。解法是 `pool_gate()`（检查）+ `diverse_pool()`（选种子时就把最优解拉开）。K8 的 `balanced_pool` 是同一件事的另一个面。

判据要用**清晰性质**而不是容差：`best_fixed` 永远不可能低于 `1/n`（每个实例自己的最优解至少服务自己），所以正确的要求是"**没有任何单一答案能同时服务两个实例**"，即 `best_fixed == 1/n`。写成 `chance + 0.25` 是一个恰好能过的任意数字，而且可以靠缩小 n 来满足。

**(7) 只有旧代码写的标志位，比没有标志位更糟。**
`grade.py` 从来没写过 `truncated`，`analysis.py` 却在按它过滤。于是重新评分一个被截断的 run，会让它带着"缺失即假"的 `truncated` **静默晋升**进正文表格。方向是单向的、无声的。修法是在评分时**推导**这个字段，不信任任何历史产物。

**(8) 排除规则必须锚在"是否被切断"，不能锚在"是否慢"。**
承(7)之后我加了第三条排除规则：`api_errors >= 5` 视为无效 run。这条规则是错的，已删除。`api_errors` 计的是**被重试的瞬时错误**（harness 到 >40 才放弃，并写 `status: api_failed`），所以 `done` + 计数非零意味着重试成功了、模型继续跑到自己停。全库重新评分后实测：129 个 run 带这个字段、15 个 ≥5，其中 **7 个是 PASS**（`k2d99__gemflash__r1`：144 次模型调用、130 次 lab 调用、完整缩放律报告）。而触发我加这条规则的 `k6f2__gpt55__r1`，读 state 才发现它做了 24 次模型调用并交了 py_compile 验证过的 `sched.py`，3 次 lab 调用**全部花在 profile 上**（`profile_seconds` 8.22，该题族最高），交的是真正在线自适应的控制器，只是拟合的 batch-response 形状不对。**这是一次考虑周全的失败，不是一次被切断的实跑。**（我一度把这 3 次调用读成"几乎不 profile 就去调度"——也是错的，且错得很有代表性：调用**次数**低是因为 profile 只需一次调用，不是因为没 profile。把 lab 调用数当努力程度读，和把 api_errors 当切断读是同一个错误。）按"慢"排除，等于按"网关当时对哪个模型友好"给结果加权，正是 `truncated` 这个字段存在的意义所要防止的偏差。

**(9) 诱饵的身份是它失败在哪个条目上，不是它是否失败。**
同一轮用"读失败条目"而不是"读通过/失败"复查全部六个题族，查出两个诱饵在撒谎：

* K8 `partial_fix`（"病因对、修复只做一半"）用暴力法定位病因——每个候选一次 canary、每次 4 次重跑，20 的预算花掉 12——在写出 artifact 之前就因预算不足挂掉，于是**每一个盐都失败在 `R0_report` 上**。gate 显示 `expect=fail pass=0/2 OK`，一片绿，而它**从来没有提交过一次"修一半"的答案**：它要证明的命题一直未被检验。
* K1 `wide`（"点估计对、区间摊到上限"）的代码交的是**原始判官均值**加宽区间，于是失败在 `R1_coverage`（判官偏置）上——那正是 `judge_mean` 已经在测的东西。两个诱饵，一个命题，而宽度这个命题没有任何覆盖。

一个诱饵套件可以看起来完备（每种失败模式一个策略、全红），而其中两个策略其实是同一个实验、有一种模式完全没被测到。**唯一能看见这件事的是 gate 日志里的"失败条目"列**，而在此之前没有人读它。K2/K3/K4/K6 用同样方式复查后是干净的。

### 4.5 增加难度的杠杆（第二轮补充）

| 杠杆 | 实测结论 |
|---|---|
| **把多组耦合隐变量一起放宽** | **有效，且必须一起**。K2 单独放宽任一组都不够（24 个种子里"单一固定配比打穿"的数量：U 20、beta 23、W 23、lam 21），**四组同时放宽才降到 10**。原因是最优解由"哪个域先耗尽独特文本(U)"对"该域的 eval 分量还能改进多快(beta)"决定，再经转移矩阵(W)和权重(lam)路由——收紧任何一组都会通过其余几组把最优解重新钉死。 |
| **先把参照搜索变强，再抬阈值** | **有效，且顺序不能反**。K2 的 τ 卡在 0.80 两轮，因为 oracle 自己只有 0.77–0.93——**阈值测的是参照的搜索质量，不是题目难度**。把 model-free 的响应面搜索换成"拟合机制族本身"（agent 已经知道形状：语料规模 U 是公开的，未知的只有转移行和重复衰减）之后 oracle 到 0.96–0.999，τ 才抬得到 0.94，先验配比的通过率同时从 18/19 掉到 ≤7/19。旧搜索降级为 `oracle_rsm`（expect=fail）而不是删掉：它概念上完全正确、只是拟合了通用曲面，留着可以从下方守住阈值。 |
| **把"选择"和"预测"拆成同一批数据上的两个估计问题** | **有效**。K2 要求同时交配比和损失区间。实测机制拟合**擅长排序、不擅长绝对水平**（用它预测目标损失在 10 对 (seed,salt) 里有 8 对偏 +0.23~+0.60，而独立的外推 sweep 只偏 +0.001~+0.010），因为 W、B、lam 之间可以互相交换——一个拟合可以把所有比较都做对而整个曲面平移。实跑印证：`k2d374__gemflash__r1` 配比分 0.996（近乎最优）而绝对水平差 0.57，栽在 `R2`。 |


### 4.6 交付前独立复核查出来的（第三轮）

报告写完之后交给一个独立 subagent 逐条重算，查出 5 处，其中 3 处是**我在数据上看走眼**而不是笔误。都是同一个形状：**先有一个干净的故事，再去数据里挑支持它的数字**。

**(a) 把众数当成范围。** k8 我写了"只动因果旋钮 → 恢复 0.61–0.66 必败 / 三个旋钮全调 → 0.97–1.01 通过"。实际是 0.1886–0.8176（7 个 run，确实 0/7 通过）和 0.7567–1.0121（9 个 run，只过 6/9）。**"只动一个必败"是真的，"全调必过"是假的**——三个全动仍失败的有 3 次。干净的二分法是靠只引用众数值造出来的。

**(b) 把我以为的机制当成测到的机制。** k6 我写了"通过的 run 少在线探测（n_evaluate 0–1）、失败的多（5–9）"。实测通过是 {0,1,1,4,4,5}、失败是 {0,1,5,6,6,9}——**两个分布重叠，这个签名不存在**。真正的区分点要读提交的 `sched.py`：gpt-6 在 k6f1 上两次 n_evaluate 都是 1、profile 8.56 vs 8.78（预算分配几乎一样），一次 −2.32 一次 1.13，差别是硬编码阈值启发式 vs 对切换点做边缘化的后验。**预算分配是我能一眼看到的量，控制器结构不是**，于是我用前者讲了一个关于后者的故事。

**(c) 同一个词在两张表里指不同的东西。** 分档表里"弱档"= haiku（0/15），分题族表里"弱档"那一列却是 haiku+gemini 合并的——于是每一个"1"都是 gemini 的，而正文同时在说"弱档 0/15 说明没有蒙对通道"。两张表各自都对，合起来自相矛盾。

**(d)(e)** 两处口径/陈旧数：排除规则的计数取自全库重评**之前**（44/9/3 vs 129/15/7）；被持有的 21 个 run 里有 2 个本就落在被排除的任务上，从 76 这个分母里实际扣掉的是 19 个。

固化成流程：**报告里每一个"范围"和"签名"都必须是重算出来的聚合，不能是从几行样本里读出来的印象**；交付前的独立复核要求复核者**自己从 grade.json 重算**，而不是核对我给的数。这一轮它查出的 3 个实质错误，没有一个是我重读自己的表格能发现的。
