## 1. 题目设计：六个题族

### 1.1 L1.5 的定义与三条硬约束

| 层 | 世界 | 真值来源 | 问题 |
|---|---|---|---|
| L1 现实 | 真跑训练 | 实测 | 贵、不可复现、无法保证可解 |
| **L1.5（本轮）** | **已发表 ML 机制 + 反事实常数的模拟器** | **模拟器本身即真值，最优解可穷举** | 需自己造机制、防背诵 |
| L2 纯虚构 | 任意合成系统 | 合成 | 与 AI4AI 能力脱钩，沦为解谜 |

1. **机制是真的**——数据受限缩放、临界 batch、WSD 退火律、验证器可利用性都来自文献，所以考的是研究者真实会用的推理；
2. **常数是反事实的**——每个实例重采样 θ，背论文里的数字必拿 0 分；
3. **模拟器是真值**——最优解可穷举，后悔机械可算，主分不需要 LLM judge。

与 v6 的关键差别：v6 是"给定世界，回答问题"；v7 是"给你一个带预算的实验室 `lab`，自己设计实验、自己决定测什么、交付可执行产物"。

### 1.2 差异矩阵

题与题的区别是**机制 × 交付物 × 预算单位 × 失败机制**四维同时不同，不是换皮。

| | K1 judge-drift | K2 mix | K3 anneal | K4 tts | K6 ramp | K8 postmortem |
|---|---|---|---|---|---|---|
| **背景** | 模型评测方法学 | 预训练数据配比 | 预训练学习率日程 | 推理时采样服务 | 训练吞吐/批量 | 微调线上回归事故 |
| **移植机制** | 判官偏置下的真实胜率估计 | 数据受限缩放+混合律（2305.16264 / 2403.16952） | WSD 退火律（2408.11029） | 验证器可利用性+模板特异错误吸引子 | 临界 batch / 梯度噪声尺度（1812.06162） | 蒸馏容量差 × 数据泄漏（2502.08606） |
| **交付物** | D 估计器代码+区间 | A 配置+区间 | A 配置+区间 | B 策略代码 | B 调度代码 | C 诊断+修复 |
| **预算单位** | 人工标注条数 | FLOPs | FLOPs | credits | GPU-秒 | 重跑次数 |
| **认知难点** | 判官偏置与被评对象相关，且**估计目标是生产流量配比**而非竞技场均值 | 代理实验永远不会触发目标 run 才有的"重复数据"约束 | 可测曲线段与待预测量之间隔着一个相变 | 验证器分数在不同题型上可信度不同 | **切换点每个 run 重抽样，dev 副本只给切换前的 ramp，切换必须在线检测** | 症状同时兼容 3 个原因，只有一个能被干预区分 |
| **主失败机制** | M2 有偏估计当无偏用 | M1 代理不激活机制 | M1′ 外推越过相变 | M5 过信二手信号 | M1‴ 离线记忆代替在线检测 | M4 归因过早收敛 |

### 1.3 判定：TB-Science 风格的 rubric

verifier 只看 `task.toml` 声明的 artifacts + lab ledger，**全机械**。通过 = 所有 `R*` 条目为真。τ 与容差是写进题面的显式数字，不是"尽量好"。提交的代码在 bwrap 沙箱里跑（`--unshare-all`，看不到 `/app`、`/hidden`、无网络；已实测 `cheat_probe` 只能看到自己的文件、socket 连接失败）。

### 2.4 最有信息量的三个失败签名

**(a) 决策对、自我评估错。** `k3v2__gpt55__r1` 配置分 **0.9991**（实际上就是最优配置 n=2048/η=0.0011），却因为预测区间偏了 **0.204** 而整体失败。`k2d374__gemflash__r1` 同型：配比分 **0.996**，绝对损失水平偏 **0.568**。**选一个配置**和**预测它的表现**是同一批数据上的两个不同估计问题，模型普遍擅长前者、不擅长后者。这不是苛求——oracle 在同样预算下偏差只有 0.001–0.010。

**(b) 病因对、修复不对（k8 的设计签名）。** 18 次实跑里 `R2_cause_survives_intervention` 过了 **17 次**（唯一答错病因的是 haiku 的 `k8c2`），`R3_fix_acts_on_cause` 过了 **18/18**——也就是说**几乎所有模型都能定位病因**，但整体通过只有 8 次。

按提交时动了几个旋钮分组（12 个有效 run）：

| 提交的修复 | 恢复率范围 | 通过 |
|---|---|---|
| 只动被归因的那一个旋钮 | 0.1886 – **0.8176** | **0/7** |
| 动 2–3 个旋钮 | 0.7567 – 1.0121 | **6/9** |

**只动一个旋钮的 7 次实跑无一通过**，这一半是干净的。另一半不是：动了多个旋钮也只过 6/9——`k8c2__fable__r1`/`k8c2__gemflash__r1` 三个旋钮全动仍只恢复 0.8984，`k8c3__sonnet5__r1` 三个全动只有 0.7567。**"重新调另外两个"是必要条件，不是充分条件**，还得调对值。`k8c2` 的两次通过用的是 **2 个**旋钮（`{"mixture": 0.76, "capacity": 0.759}`，恢复 0.9992），而 gpt-6 交 `{"mixture": 0.76}` 恢复 0.8176 失败。

题面已写清三个旋钮各自的回退上限、R1 问的是"可达质量的 90%"，所以"另外两个旋钮的最优值发生了移动"是可推导的；陷阱在于**把"病因"和"修复"当成同一个问题**。

**(c) k6 的区分点在控制器结构，不在预算分配。** 我一开始以为签名是"多离线 profile、少在线探测"，**实测不成立**：通过的 run 的 `n_evaluate` 是 {0,1,1,4,4,5}，失败的是 {0,1,5,6,6,9}，两个分布重叠；`profile_seconds` 同样不分（通过 3.59–8.78）。

真正的差别要读提交的 `sched.py`。gpt-6 在 `k6f1` 上两次跑出 s=**−2.32** 和 s=**1.13**，而两次的 `n_evaluate` 都是 1、`profile_seconds` 8.56 vs 8.78——**预算分配几乎一样**。差别在代码：失败那次用的是硬编码阈值的启发式（"`recent[-1] > baseline*1.22` 且 `i>=15` 就切到 512，连续两段回落就切回"），通过那次用的是对切换点、跳幅、后段斜率一起做边缘化的后验估计。同一个模型、同样的探测预算、**差一个数量级的分数**——这也说明 k6 的前沿"失败"更多是方差（见第 4 节），不能当能力差读。

## 3. 难度杠杆：实测有效与无效

这张表是本轮最可复用的产出，每一行都有测量值支撑。

| 杠杆 | 结论 |
|---|---|
| **改变估计目标（estimand）** | **有效**。K1 原本估竞技场均值，代数上可证"全局一次性校准"恰好无偏——**任何噪声/偏置调参都不可能把它与分层校准分开**。改成按生产流量配比加权后，全局校准立刻有偏。**存在简单无偏解的题，不可能靠调偏置变难** |
| **让隐藏世界之间的差异变成结构性的** | **有效**。K6 原本隐藏 run 只是噪声重抽样，"背 dev 副本曲线"打穿一切（fable s=1.32，7 次调用）；改成重抽切换点/幅度/斜率后，记忆家族塌到 0.69 |
| **压平可离线学到的那部分信号** | **有效**。K6 的 ramp 太陡时"跟着 ramp 走"就是大部分收益，而 ramp 恰好离线可学；压平到 k∈[0.35,0.65] 后区分度才出现 |
| **把多组耦合隐变量一起放宽** | **有效，且必须一起**。K2 单独放宽任一组都不够（24 种子里"单一固定配比打穿"数：U 20、beta 23、W 23、lam 21），**四组同时放宽才降到 10** |
| **先把参照搜索变强，再抬阈值** | **有效，顺序不能反**。K2 的 τ 卡在 0.80 两轮，因为 oracle 自己只有 0.77–0.93——**阈值测的是参照的搜索质量**。换成"拟合机制族本身"后 oracle 到 0.96–0.999，τ 才抬到 0.94 |
| **把"选择"与"预测"拆成两个估计问题** | **有效**。见 2.4(a) |
| **加噪声 / 减预算** | **基本无效且危险**。同时伤害 oracle 和诱饵，通常只把题变成运气题 |
| **单纯提高阈值 τ** | **无效**。τ 只能在"放诱饵过"和"误杀正解"之间选，真正的自由度在实例不在阈值 |

## 4. 未达标项：前沿区分度只有 k8 提供

前沿 0.86 的构成：

| 实例 | 前沿通过 | 说明 |
|---|---|---|
| k1-c1/c2、k2-d8/d41/d99/d374、k3-v1/v2、k4-w1/w2、k6-f2 | 全过 | 无前沿区分度 |
| k6-f1 | 3/4 | gpt-6 一次失败一次通过，**方差而非能力差** |
| k8-c1 | 1/2 | gpt-6 败 |
| k8-c3 | 2/2 | 全过 |
| **k8-c2** | **0/2** | **唯一同时打穿两个前沿模型的实例** |

诚实的结论：**本轮只做到"中档以下有强区分度"，前沿区分度只有 k8 一个来源，且样本量小**（前沿每实例 1–2 次）。不把这写成"困住了 GPT-6"。

k8-c2 为什么有效，以及下一轮该往哪走——它同时满足三个条件，而其他五个题族各缺一条：

1. **正确答案需要两步推理且第二步不显眼**：定位病因（17/18 都会）之后，还要意识到回退上限使另外两个旋钮的最优值发生了移动；
2. **看起来完整的答案是错的**：`{"mixture": 0.76}` 是一个自洽、可辩护、且病因正确的答案，它只是不够；
3. **判定同时检验因果与效果**：R2 用反事实干预验病因，R1 用隐藏重跑验效果，**两者不能互相替代**——只对病因不给分，只恢复质量也不给分。

下一轮的具体做法：把 (1)(2)(3) 当作**造题模板**，而不是 k8 的特有性质。K2/K3 最容易改造——它们已经有 R1/R2 双条目，缺的是"正确答案的第二步"：目前 R2 只是对自己 R1 答案的评估，可以改成**必须预测一个 R1 没问、但由同一批实验决定的量**。

## 5. pipeline：稳定造出"新题、难题、正确的题"

### 5.1 结构

    sample_params(seed) → instance_gate(p)   # 秒级无噪声筛，淘汰 2/3 种子
        → l15.gates <mod> <seed> --salts 4   # 真 Session、真噪声、10-13 个策略 × 2-4 盐
        → pool_gate(seeds) / diverse_pool()  # 池级性质，per-instance 闸门看不见
        → l15.build <mod> <seed> <out>       # 生成 instruction/docs/starter/hints/hidden
        → harness/launch.py + drive.py       # 多模型并行跑
        → l15.grade <run_dir>                # 同一个 grade() 判定

一道新题只需写一个 `l15/tasks/<name>.py`（提供 `sample_params / World / STRATEGIES / instance_gate / instruction / docs / hints`），其余全部复用。**难度不是声明的，是 gates 量出来的。**

### 5.2 九条闸门（(6)–(9) 是本轮新加）

| # | 闸门 | 被什么打脸才加的 |
|---|---|---|
| 1 | **筛实例，不要调阈值** | K6 记忆诱饵在幸运盐上打到 0.87–0.89 而 τ=0.90。K1 接受率仅 21% |
| 2 | **诱饵分类是测出来的，不是作者品味** | K6 `myopic` 实测 0.94–0.97 改判为存在性证明；K1 `overshrink` 不再因任何理由失败，移出 |
| 3 | **容差从机制自身精度量出** | K3 从 0.40 收到 0.20；K1 从 0.10 放到 0.26 再收到 0.17 |
| 4 | **从坏参照量出来的数不是测量** | K1 的 WIDTH_CAP=0.26 测的是一个有 bug 的 oracle（`den` 变量被复用），修掉后落到 0.17 |
| 5 | **评分常量必须与题面一起冻结** | 调完 K3 的 WIDTH_CAP 重新评分，把 gpt-6 合法的区间判成失败——**把 harness 的 bug 报成了模型的失败** |
| 6 | **池级性质只能在池上检查** | K2 每个实例都合格，但**一个固定配比打穿 19 个种子里的 18 个** |
| 7 | **只有旧代码写的标志位比没有更糟** | `grade.py` 从不写 `truncated`，`analysis.py` 却按它过滤：重新评分一个被截断的 run 会让它**静默晋升**进正文表格 |
| 8 | **排除规则锚在"是否被切断"，不能锚在"是否慢"** | 我自己加的 `api_errors>=5` 规则会排除 15 个 run，**其中 7 个是 PASS**。已删除，见 5.4(c) |
| 9 | **诱饵的身份是它失败在哪个条目上** | K8 `partial_fix` 从未提交过一次"修一半"的答案；K1 `wide` 与 `judge_mean` 是同一个实验 |

### 5.3 池级闸门的判据要用清晰性质，不要用容差

`best_fixed`（一个固定答案能打穿多少实例）**永远不可能低于 `1/n`**，因为每个实例自己的最优解至少服务自己。所以正确的要求不是"接近随机水平"，而是**"没有任何单一答案能同时服务两个实例"**，即 `best_fixed == 1/n`。

写成 `chance + 0.25` 会是一个恰好能过的任意数字，而且**可以靠缩小 n 来满足**——这正是它必须被替换的原因。最终 K2 出货 {8, 41, 99, 374}：`best_fixed` 0.25（= 1/n 下界）、先验配比菜单 0.25、随机水平 0.025，最优解两两 L1 间距 ≥0.445，跨实例转移 `R1_mixture_quality` 从 **7/9 降到 0/9**。

### 5.4 本轮最贵的一课：闸门只能检验它真正被"玩"过的东西

同一个错误在三个层面各出现一次，全都**不会让任何闸门变红**：

**(a) 诱饵没被玩。** K8 的 `partial_fix` 用暴力法定位病因——每个候选一次 canary、每次 4 次重跑、预算 20 花掉 12——在写出 artifact 前就因预算不足挂掉。gate 显示 `expect=fail pass=0/2 OK`，一片绿，而它**从来没有提交过一次"修一半"的答案**。它要证明的命题一直未被检验。

**(b) 诱饵玩错了。** K1 的 `wide` 文档写"点估计正确、区间摊到上限"，代码交的却是**原始判官均值**，于是失败在 `R1_coverage`（判官偏置）——那是 `judge_mean` 已经在测的东西。两个诱饵、一个命题，而"宽度"这个命题零覆盖。

**(c) 排除规则把"慢"当成"被切断"。** 全部 run 重新评分后，129 个 run 带这个字段、15 个 ≥5，**其中 7 个是 PASS**（含 `k2d99__gemflash__r1`：144 次模型调用、130 次 lab 调用、完整缩放律报告）。`api_errors` 计的是**被重试的瞬时错误**（harness 到 >40 才放弃并写 `status: api_failed`），`done` + 计数非零意味着重试成功、模型跑到自己停。而触发我加这条规则的 `k6f2__gpt55__r1`，读 state 才发现它做了 24 次模型调用并交了 py_compile 验证过的 `sched.py`——而且它的 3 次 lab 调用全部花在 profile 上（`profile_seconds` 8.22，是该题族最高的），交的是一个真正在线自适应的控制器，只是拟合的 batch-response 形状不对（s=−0.30）。**这是一次考虑周全的失败，不是一次被切断的实跑。**按"慢"排除等于按"网关当时对哪个模型友好"给结果加权。

共同的形状：**"expect=fail，得到 fail"不能证明它是因为你想测的原因失败的。** 唯一能看见的地方是 gate 日志里的"失败条目"列，而在此之前没有人读它。K2/K3/K4/K6 用同样方式复查后是干净的。

修复后：`partial_fix` 改用 oracle 的廉价定位法（3 次 decontaminate），现在失败在 `R1_fix_recovers`（0.61–0.77），三个出货实例仍全部 ACCEPT；`wide` 重建为 oracle 估计器 × 12 倍 z，现在只失败在 `R2_width`，两个出货实例仍 ACCEPT。

### 5.5 造一道新题的真实成本

以 K1 为例，从"机制选定"到"两个实例上线"：探索脚本 12 个，推翻过 3 次设计（偏置对称抵消 → 冗长偏置也不行 → 换 estimand），发现 1 个会毁掉整道题的 oracle bug，种子接受率 5/24。

这不是可以省掉的开销，**它就是"正确的题"的成本**。pipeline 能做的是让每一次推翻都便宜（秒级 screen）、让每一次错误都留痕（注释里写测量值）、让陈旧产物自己报错（`grading_consts`）。

## 7. 下一轮建议（按优先级）

1. **把 k8-c2 的三条件当造题模板**（第 4 节），优先改造 K2/K3 的 R2：让它预测一个 R1 没问、但由同一批实验决定的量；
2. **前沿样本量**：当前每实例 1–2 次，区分度结论的置信度不够，前沿模型至少跑到每实例 3 次；
3. **把"读失败条目"变成闸门代码**：`gates.py` 应当断言每个诱饵失败在它声明的条目上（`STRATEGIES` 里补一个 `expect_item` 字段），否则第 5.4 节的错误一定会再犯；
4. **fable 的 k2 拦截**需要一个不改写题面的解法（例如换一个同机制但背景叙述不同的实例），否则这个题族在前沿档永远只有一个模型的数据。
