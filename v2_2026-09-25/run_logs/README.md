# v2 实跑轨迹（09-25 整理时从构建目录补存）

`evidence/` 里只存了每次实跑的交付物，用来重新评分。这里存的是过程：模型每一步做了什么、花了多少。这些文件原本只放在虚拟机的 `/tmp/bench2/runs` 里，虚拟机重置后就会丢失，所以 09-25 整理时把它们复制了过来。

这里一共 29 个实跑目录。18 个是计分的实跑，另外 11 个的结果已被取代：它们答的是后来改过键值或重建过题项的旧版本题目，每个目录作废的原因登记在 `harness/grade_all.py` 的 `STALE` 表里。

| 文件 | 属于哪个运行器 | 内容 |
|---|---|---|
| `cc_stream_NNN.jsonl` | Fable（`cc_*`） | Claude Code 每一拍的 stream-json 输出：消息、工具调用、工具结果、成本 |
| `traj.jsonl` | GPT-6（`gpt_*`） | 每一次 API 调用和工具调用，包括命令、退出码、耗时和截断到 4000 字符的输出 |
| `state.json` | 两者都有 | 续跑状态，包括轮数、成本或 token 用量、effort 是否降过级、最终文本 |
| `tick.log` | 两者都有 | `drive.py` 把运行器的 stdout 和 stderr 重定向到这里。v2 的全部实跑里它都是空文件，说明运行器本身没有报错 |
| `gateway.log` | 网关 | 每个请求一行，记录时间戳、方法、路径、状态码和耗时，不含请求内容和凭证 |

有三类东西没有复制：`app/`（被测模型当时的工作目录，交付物已经在 `evidence/` 里了）、`home/`（Claude Code CLI 的配置目录）和 `sbx_tmp/`（沙箱的临时目录）。

复制前做过凭证扫描：用 key 的全串和三段子串分别做了精确匹配，又用 `sk-` 开头长串和上游域名做了模式匹配，所有文件都是零命中。
