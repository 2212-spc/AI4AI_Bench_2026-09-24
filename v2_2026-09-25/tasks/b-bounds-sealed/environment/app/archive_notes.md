# Archive notes - 2026-06 evaluation sweep

What follows is a file inventory and a units note.  It is not an explanation: nobody reconstructed why
each missing number is missing, and the internal codes in `retention_log.csv` are generated by the
archiver and are not documented anywhere.

## Files

  * `plan.csv` - every run that was scheduled, with its four configuration knobs.
  * `launch_log.csv` - the runs that actually started, and the worker each one ran on.
  * `eval_results.csv` - the `pass_rate` rows the archive still holds.
  * `retention_log.csv` - rows the archive no longer holds: the run id, the instant the row left the
    store, and an internal code in the `reason` column.
  * `retention_policy.json` - the versioned quality floor the archiver is configured with.  Intervals are
    half-open: `[from, to)`.
  * `recovered/*.csv` - values scraped out of the per-worker stdout tails, one file per collection pass.
    The stdout banner prints the score as a percentage, so these carry `pass_rate_pct`; it is the same
    quantity as `pass_rate`, in different units.  The scrape was opportunistic and the shard files were
    assembled from planning tickets, so: a run can appear in several shards and in `eval_results.csv` as
    well, a few rows are duplicated, and a few run ids belong to runs that never launched.  Where a run
    appears more than once the values agree.  Treat the shards as a value source, never as a run list.
  * `runtime.csv` - when each launched run finished.  Kept by the scheduler, on a different host from the
    archive.
  * `daily_digest.csv` - for each UTC day, how many runs finished that day and what their `pass_rate`
    values added up to.  Written at 23:59 from the scores the scheduler received directly from each
    worker, so its totals cover every run that finished that day, whatever the archive did with the row.
    The figure it prints is the exact total, not a rounded summary of one.
  * `suites.json` - for each suite, how the harness scores it.
  * `metric_card.md` - what `pass_rate` means.

## Storage layout

The archive holds result rows in one file per worker per UTC day.

## What is known to be complete

`plan.csv`, `launch_log.csv`, `retention_log.csv`, `runtime.csv` and `daily_digest.csv` are complete for
the whole sweep: nothing was removed from them and no row in them is wrong.  Every file in `/app` is
exactly what it claims to be.

## What is known to be missing

Some launched runs have no row in `eval_results.csv`.  Some of those appear in `retention_log.csv` and
some do not.
