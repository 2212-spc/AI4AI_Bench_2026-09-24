# 目标 2 原型：把真实机制移植进虚拟世界，做开放设计题，评分不以作者答案为天花板

> 2026-09-27。纯 numpy，零模型调用。所有数字都能用 `python3 summarize.py` 从 `results/`、`results2/` 重新生成，自动汇总表见 `SUMMARY.md`。

## 0. 这个原型要回答什么

用户的目标 2 是：先把现实里的机制 transform 到虚拟世界，再给足够的自由度，去考察实验设计、推理和创新设计；创新部分不要以我们的 oracle 为天花板。落到可证伪的问题上，是下面四个：

1. **可移植性**：一条已发表的经验律，能不能直接当虚拟世界的"物理"来用？哪里会出问题？
2. **区分度来源**：在这种世界里，是什么让一个策略失败？这个失败对应的是有意义的能力，还是无意义的点？
3. **不封顶的评分**：不用作者答案作 key，能不能给出一个可信的、可以超过 1 的分数？
4. **公平性**：如果难题上所有策略都挂了，怎么证明题目本身可解，而不是出错了？

为了把"能力需求"和"模型本身强弱"分开，所有策略都是脚本。模型实测留到有 key 的时候再做。

## 1. 世界：Multi-Power Law 学习率世界

**底座**是 Luo et al. 的 Multi-Power Law（MPL，ICLR 2025）。它用"LR 面积的幂律"加上"每次降 LR 带来的饱和型损失下降"来预测任意 LR schedule 的最终 loss：

`L(t) = L0 + A·(s0 + Σu)^(−α) + B·peak(t) − B·Σ_k (η_{k−1} − η_k)·G(η_k^(−γ)·S_k(t))`，其中 `G(x) = 1 − (Cx + 1)^(−β)`。

MPL 本身不含稳定性。为了让"设计"有真实的取舍，加了三处有文献依据的扩展，均为作者设计：

- **稳定边**：θ(t) 会随 warmup 面积从 th0 升到 th_inf，一旦 η ≥ θ 就发散。
- **边附近效率损失**：`u = η·(1 − (η/θ)^p)`。
- **平台噪声项**：`B·peak`。

`world.py` 头部注释列全了公式。

**三类世界**，各 4 个种子：

| 类型 | 改了什么 | 想考的能力 |
|---|---|---|
| F 忠实 | 常数取在文献常见范围 | 基线，看背诵先验够不够用 |
| C 反事实常数 | 文档 LR 正好落在"贴边浪费带"里；退火饱和很慢，所以长衰减最优 | 能不能用测量推翻文档和常识（对应 M6：参照点不是零 / M5：过信二手来源） |
| L 晚发不稳定 | 稳定边在 tc≈0.35–0.5T 之后按幂律收缩（模拟 progressive sharpening），短跑完全看不到 | 有效域外推（M1），以及"主动设计实验去看见看不见的东西" |

**Lab 接口**：策略只能跑 schedule，拿回带噪声的曲线（σ=0.004，每 100 步一个点）和发散步。每次运行的边有 3% 抖动，预算是 2.5T 步。

**评分**：`s = (L_base − L_sub) / (L_base − L_opt)`。

- L_base 是真世界里最好的常数 LR。
- L_opt 是我们的优化器在真世界里找到的最优 schedule。
- 评分取 8 个固定边抖动分位上的平均，所以"只在运气好时不发散"会被惩罚。
- s 不截断。比我们的优化器好就 >1，发散就是很大的负数。

## 2. 策略（全部脚本）

| 策略 | 做法 | 代表的行为 |
|---|---|---|
| P0 const | 文档 LR，常数 | 什么也不做 |
| P1 cosine | 文档 LR + cosine 到 10% | 背诵"标准配方" |
| P2 wsd | 文档 LR + WSD 衰减 20% | 背诵"最新配方" |
| P3 grid | 在 T/10 上对 peak×衰减比例做 18 点网格，再把比例迁移到 T | **作者式参考答案**：这正是出题人会算出来当 key 的东西 |
| P4 model | 3 个 ramp 探边，3 条 2000 步曲线拟合 MPL 族，然后优化自由单调 schedule | 测量→建模→优化（知道正确模型族，是上界） |
| P4v | P4 + 最多 2 次全长 pilot，发散就在发散点前加 cap 再优化 | 加上"验证" |
| P4m | 和 P4 一样，但拟合的是错误的模型族（动量律） | 模型族选错的代价 |
| P6 late-probe | P4 + 两次"晚期探边"：低 LR 跑到 t0=4000/8000，再快速升 LR，看在哪一步发散；取与证据相容的最陡幂律外推边，按 cap=0.85·θ̂(t) 优化 | 主动设计实验去看见晚发现象；不使用世界类型信息 |
| P5 红队 | 在世界最优 schedule 上叠加后峰锯齿，直接在真世界调参 | 找评分漏洞 |
| OPT_strong | 真世界优化，margin 0.95，1000 次迭代 | 检查锚点是否已经接近真最优 |

## 3. 结果

### 3.1 主表（s@T 中位数 [最小]，灾难=s<−1 的次数）

| 策略 | F | C | L | L 在 2T |
|---|---|---|---|---|
| P1 cosine | 0.47 [−0.08] | 0.47 [−0.14] | 0.59 [0.19] | 0.86，灾难 0/4 |
| P2 wsd | 0.80 [0.79] | **−0.83 [−2.00]**，灾难 2/4 | 0.64 [−19.4]，灾难 1/4 | 灾难 4/4 |
| P3 作者式网格 | 0.83 [0.50] | 0.44 [0.20] | **灾难 7/8** | 灾难 8/8 |
| P4 拟合+优化 | 0.95 [0.88] | 0.96 [0.72] | 灾难 4/8 | 灾难 8/8 |
| P4v +pilot 验证 | 0.95 [0.88] | 0.96 [0.72] | 0.90，灾难 1/8 | 灾难 8/8 |
| P4m 错误模型族 | 0.65 [0.32] | 0.68 [−0.04] | 灾难 4/8 | 灾难 8/8 |
| **P6 晚期探边** | 0.95 [0.88] | 0.96 [0.72] | **0.89 [0.81]，灾难 0/8** | **0.86 [0.72]，灾难 0/8** |

补充说明：

- P3/P4/P4v/P4m/P6 每个世界跑 2 个 lab 种子，每类 8 次运行；P0–P2 每类 4 次。
- P6 最多用了 19,384 步预算，上限是 25,000。
- P6 在 L 世界估出的 (tc, ψ) 和真值接近：真 tc 3725–4307，估 3164–4186；真 ψ 0.78–0.95，估 0.73–0.99。
- 在 F/C 世界，P6 误报晚期衰减 1 次（C4），没有造成灾难。

### 3.2 发现

**F1. C 世界把"背诵先验"和"会测量"分开了，而且分得很干净。** P2（背文档 WSD）在 F 里是 0.80，到 C 里掉到 −0.83，下降 1.63 个 gap 单位。P4（测量+建模）在两类世界都是 0.95–0.96。P3（作者式网格）在 C 里只有 0.44：P4 在 C 的 8/8 次、F 的 7/8 次运行里都胜过 P3。反事实常数的作用，就是让"知道答案"失效，同时让"会找答案"保持有效。

**F2. 如果拿 P3 这种作者式最优当 key，天花板会被压低一半以上。** 在 C 世界，作者式网格的中位是 0.44，而 P4 的中位是 0.96。若评分以作者答案归一化，P4 的真实优势会被截断，或者被判成"偏离答案"。所以锚点必须是真世界里的数值最优，不能是出题人某个流程的输出。这正是用户说的"不要以 oracle 为天花板"在工程上的含义。

**F3. 但在单调设计域里，"不封顶"只是形式上的。** OPT_strong 最多比锚点高 0.0001。可见我们的锚点已经基本就是这个域的物理最优，s>1 的空间几乎为零。想要实质上的开放性，设计空间里必须有锚点搜不到的结构，比如多旋钮耦合（LR × batch × 数据配比）或组合式设计。可这些恰好又是被移植的律没有验证过的区域，见 F4。

**F4. 已发表的公式在它的验证域之外会给出荒谬的奖励，这是移植世界最大的风险。**

- 在世界最优上叠加后峰锯齿（幅度 0.4、周期 2 步），MPL 在全部 12 个世界都给出 s=38–443，loss 低于不可约损失 L0。原因是 G 的不对称：同一幅度下，"降"得到的权重大于"升"。
- 这种大漏洞会被 0.25 的兄弟律门全部拦下（12/12），物理下界 L≥L0 也能拦下。
- **物理上看不出问题的锯齿**：sweep 覆盖幅度 0.5%–10%、周期 2–200 步（12 个世界共 300 个点）。其中 s>1.05 且 L≥L0 的点有 120 个，兄弟门只拦下 75 个，**45 个漏过**（s=1.05–1.23，中位 1.10；幅度 ≤2% 的 27 个，5–10% 的 18 个）。（2026-09-27 核查更正：原文把 120 个点都写成"幅度 0.5%–2%、s=1.05–1.09"。）原因是兄弟律在验证域内和主律本来就有 5–12%（中位）、最多约 49% gap 的分歧，门阈值不能低于这个噪声，所以小于阈值的漏洞无法检测。
- 模型只凭黑箱实验就能发现这种漏洞：7% gap ≈ 0.007 nats，约为单次观测噪声的 1.75σ，重复几次就能看见。

**F5. 两种修法及其代价（实测）。**

- (a) **悲观集成评分** `s_pess = min(s, s_sib)`：只给所有可接受律都同意的改进记分。sweep 里 s_pess>1.05 的点变成 0 个，最大 1.000。代价是诚实的单调策略也会被兄弟律分歧拖低：P2/P3/P4 中位 0，最大 0.06/0.16/0.09；cosine 类 schedule 中位 0.16、最大 0.31，因为两条律恰好在 cosine 形状上分歧最大。
- (b) **把设计空间限制在验证域内**（峰后单调不增）：对诚实策略零代价，也按构造杜绝了锯齿，但等于承认"开放性以律的有效域为界"。
- 推荐做法：评分用 (b)，审计用 (a)，也就是用悲观分数给 s>1 的提交打标记，再人工或红队复核。

**F6. 植入的 builder bug 在验证域里完全不可见。** 把退火项的有符号下降写成绝对值 `|drop|`，在单调 schedule 上数值完全不变：兄弟律拟合结果逐位相同（4/4 个 F 世界）。只有红队的非单调输入会暴露它（s=6453–8903，全被门和物理界拦下）。结论：**移植世界的正确性检查不能只在验证域里做**，必须有一个会主动走出验证域的红队。

**F7. L 世界的失败机制是有意义的能力，而且"失败链"很清楚。**

- 短程网格（P3）根本看不见晚发不稳定，灾难 7/8。
- 只拟合不验证（P4）灾难 4/8。
- 做一次全长 pilot（P4v）降到 1/8。剩下那次是 **pilot 刚好碰上边抖动的好运气而没发散**（L4 lab 种子 7），但在评分的 8 个抖动分位下仍会发散，s=−15.0。这对应 M3 误差预算：一次成功的 run 并不等于稳健。
- 到 2T，所有适应策略都是 8/8 灾难，因为预算根本不允许在 2T 上验证。只有"背诵"的 cosine 活下来，它是靠早衰减碰巧躲开的。
- P6 证明这道题**在预算内可解**：它主动设计两次晚期探边实验，用与证据相容的最陡衰减外推，T 和 2T 都 0 灾难，中位 0.89/0.86。
- 这正是目标 2 想考的"设计实验"：答案不在任何文档里，也不能靠多跑几次碰到，必须先想到"有些现象只在我没观测过的区域出现"，再花预算去看。

**F8. 模型族选择本身就是能力需求。** 同样的数据和优化器，改拟合动量律族（P4m），F/C 中位从 0.95/0.96 掉到 0.65/0.68，最差 −0.04。P4 的 0.95 是"知道真族"的上界。对真实 agent 来说，"用什么模型、怎么检验模型对不对"是题目的一部分。不应该把 MPL 公式写进题面，否则就退化成一道拟合题。

### 3.3 兄弟律（集成门）的保真度

兄弟律是 Tissue et al. 的动量律，做了 ε 修正。它只在单调 schedule 上拟合主世界的无噪声曲线。

- 拟合 RMSE 为 0.003–0.006 nats。
- 留出单调 schedule 上的分歧：中位 5–12% gap，最大 16–49% gap。

所以兄弟门**只能抓大于约 0.25–0.5 gap 的漏洞**。这是 F4 小幅漏洞漏过的根本原因，不是参数没调好。

## 4. 诚实的局限

1. **全是脚本策略**。结论是"某种策略结构会在哪里失败"，不是"某个模型会失败"。P0–P6 恰好对应"背诵 / 作者式 / 测量建模 / 验证 / 主动探测"这条能力阶梯，但真实模型会落在哪一级需要实测：用前沿 2 个（gpt-6-astra、claude-fable-5-1）加中档 4 个（gpt-5.5、claude-sonnet-5、claude-haiku-4-5、gemini-3.x-flash）模型，每格 ≥3 次运行。
2. **世界扩展（稳定边、效率、晚发收缩）是作者设计的**，没有被同一篇论文验证。它们的"真实性"只有定性依据（edge-of-stability、progressive sharpening），没有定量依据。这正是 L1.5 级别的定位：机制是真的，常数和组合是虚拟的，不宣称预测真实训练。
3. **P4/P6 知道 MPL 族**，所以是上界；P4m 给出了模型族错误时的下降幅度。
4. **世界类型数量少**：只有 3 类 × 4 种子。C/L 的"反事实"是手选的方向，还没有用自动方法去搜"哪些常数组合能最大化背诵先验与测量的分歧"。目标 3 的出题 loop 应当做这件事。
5. 评分用 8 个抖动分位取平均，所以"发散"表现为很大的负分。用于正式 bench 时建议截断到 [−1, ∞)，另外单独报告灾难率，避免均值被少数发散主导。

## 5. 对正式 bench 的设计规则（从本原型直接推出）

| 规则 | 依据 |
|---|---|
| R1 锚点=真世界数值最优，不是出题人流程的输出 | F2：作者式网格只有 0.44 |
| R2 每个移植世界声明验证域；评分限制在域内，域外只审计 | F4、F5 |
| R3 红队优化器是必备闸门，并且必须能走出验证域 | F4、F6 |
| R4 同域一致的律集合 + 悲观分数，用于给 s>1 提交打标记 | F5 |
| R5 物理下界（L≥L0）是廉价的第二道闸门，但只能抓大漏洞 | F4 |
| R6 难题必须附一个预算内可解的存在证明策略（这里是 P6） | F7：否则无法区分"难"和"错" |
| R7 题面不暴露律的函数形式 | F8：否则退化成拟合题 |
| R8 反事实常数要让背诵先验失效、测量仍然有效：用 F→C 背诵策略的下降量作为世界的合格指标 | F1：下降 1.63 gap |
