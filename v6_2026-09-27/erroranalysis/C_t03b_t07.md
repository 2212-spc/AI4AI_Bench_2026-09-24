## 0. 结论先行

1. **T03b 两个模型的崩法毫无共同点，都不是"信息不够"。**
   - 我拿 oracle 自己的拟合器，在每个模型**自己买的 12 次 run 加 notebook** 上重拟合，6 题全过：
     - fable：q2 0.07T，q5 0.05T。
     - GPT-6：q2 0.04T，q5 0.04T。
   - 这些 12-run 数据足以答对，失败出在拿数据的**过程**上。
2. **GPT-6 的 q1 差 116T，是因为答案写在分析之前，而且再也没改。**
   - 它在最后一次 run 返回后的下一步就写了 `answers.json`，这时还没做任何拟合；0.68 这个数在前面任何输出里都不存在。
   - 两步之后，它自己的完整模型算出 q1 = 0.02223，6 题全对，但它没有回写。
   - 这属于过程断裂（提前落笔、未核对），和预算、和 C6/C7 机制都无关。
3. **fable T03b 的 q2、q5、q6 是同一个错：噪声标定错误 → 追噪声 → 外推出假结构。**
   - 它从 notebook 里 3 对"异常一致"的种子对，把噪声估成 0.003–0.004。真值 σ = 0.0074，notebook 正文自己写着 "Seed-to-seed spread is about 0.01 nats"。
   - 于是它把一个约 2σ 的噪声模式（"过滤收益随 D 衰减得更快"）当成真结构，加了一个惩罚项去外推，最后又在两个模型之间折中。
   - 在 T03（40 次 run）里它看到了**完全相同的噪声点**：两题共享噪声盐，而 T03 的 L0、L1、L3、L12 与 T03b 的 L0、L1、L2、L6 配置和观测值逐位相同。区别是那次它做了重复 run，发现噪声约 0.01–0.015，幻觉被稀释了。
   - 即便如此，T03 的 q2 也只是 0.97T 勉强过；换成 T03b 的容差，就是 1.77T 失败。
4. **T03 与 T03b 之间有容差混杂，所以报告里"预算是开关"说过头了。**
   - q2 容差：T03b 是 0.00297，只有 T03（0.00539）的 0.55 倍。
   - q1 容差方向相反：T03b 是 T03 的 1.6 倍。
5. **T07 六个失败项，按性质分四类：**

   | 类别 | 项 | 说明 |
   |---|---|---|
   | 真实概念错误 | GPT-6 ws3 q4 | 把"训完的 cosine run"当成零惩罚参照，漏掉 ca·rmin^ζ = 0.0130 的残余地板。误差 0.0106，几乎全由这一项解释 |
   | 模型选择失误 | fable ws1 q3 | 自己的 F≈44 已经支持幂律惩罚，它仍取线性，再往中间折中 |
   | 读符号错误 | fable ws3 q5 | 数值算对是 −0.0237，结论读反 |
   | 容差边缘 PRECISION | fable ws3 q2、fable ws4 q2、GPT-6 ws4 q3 | 在各自数据上用 oracle 拟合器，前两项能过（0.74T、0.68T）；ws4 q3 连 oracle 拟合器都过不了（1.07T；fable 数据上 1.02T），是数据极限 |

6. **T07 的 q2 容差确实偏松（ws1、ws3），并且被设计的"cosine 终点残余被 E 吸收"陷阱在 q2 上低于 T，测不到：**
   - ws1：0.69T。
   - ws3：0.35T。

   同一陷阱在 q4 上是 2.46T，这正是 GPT-6 ws3 q4 被抓的地方。

## 1. 方法与证据约定

### 路径与索引

- `v3/` 指 `AI4AI_Bench_2026-09-24/v3_2026-09-25/`；`v4/` 指 `AI4AI_Bench_2026-09-24/v4_2026-09-26/`。
- GPT-6 轨迹：`v3/runs/<run>/traj.jsonl` 的 0 基行号，记作 `[k]`。
- fable 轨迹：`v3/runs/<run>/cc_stream_00X.jsonl:行号`，0 基。
- ledger 引用记作 `L#`，指 `lab_ledger.jsonl` 的 0 基行号。

### 真值与容差

- 真值：`v3/tasks/<task>/tests/key.json`；隐藏参数：`hidden/world.json`。
- 容差来自 `cert.json` 的 calibration：T = max(floor, 2.25 × p90)，p90 取 10 次 oracle 重复误差的 90 分位。
- decision 题：r_tol = 次小 regret / 3。

### 复拟合

- 把 `v3/scalelab`（blueprint 包）拷到 /tmp。
- 对每次运行，取 notebook 行加该运行 `lab_ledger.jsonl` 的全部结果，调用蓝图自带的 `fit_rows`（两阶段，n_starts=4）和 `answers_from`，再用 key 评分。
- seed 0 与 seed 1 结果完全一致。

### 噪声 z 值

用 `world.core_loss` 算无噪均值，σ = `world.sigma(P, N)`，z = (obs − mean) / σ。

### 归因规则

沿用 `v3/docs/attribution.txt`：
- 与某个 rival 的距离 < 1T 视为匹配；该 rival 自身误差 ≥ 2T 记为 strong。
- 没有 rival 匹配且误差 < 2T，记为 precision。

## 3. T07（checkpoint ≠ 训完的 run）

### 3.1 cert.json 容差核查（报告第 456 行说 "q2 容差偏松"）

0.0139、0.0166、0.0131、0.0088、0.0026、0.0091、0.0047、0.0045、0.0173、0.0069

p90 = 0.0166，所以 T = 2.25 × 0.0166 = 0.0374。

松的原因是 **oracle 自己的外推方差**：lab 里 N ≤ 3e8，生产是 N = 3e9，要外推 10 倍，E/A 之间又退化。这不是 floor 设置的问题。

**被设计的陷阱在各题上的可测性**（陷阱：cosine 终点残余 ca·rmin^ζ 被 E 吸收；蓝图第 8 行、第 41 行 `OFFSET_MIN = 0.012`，"the offset trap must bite"）：

| world | q2 T | ca·rmin^ζ | 占 q2 T | q4 T | 占 q4 T | cert 里的 q2 击杀 |
|---|---|---|---|---|---|---|
| ws1 | 0.02905 | 0.0199 | **0.69T，测不到** | 0.003 | 6.6T | — |
| ws3 | 0.03735 | 0.0130 | **0.35T，测不到** | 0.00529 | 2.46T | 只有 `widen_points`（3.11T）；`B2_cosine_finals_no_schedule` 过 q2（0.73T），`drop:C11:ca` 1.01T |
| ws4 | 0.01333 | 0.0190 | 1.42T，能测到 | 0.00354 | 5.4T | — |

**结论：**
- ws1 和 ws3 的 q2 只在测"拟合一条律并外推"，陷阱只能靠 q4 抓。
- 在 ws3 上 q4 的余量只有 2.46T，非常薄（见 3.2.4）。
- 所以 q2 上 1.0–1.1T 的失败一律按 PRECISION 处理。attribution 给出的 `drop:C11:ca` "weak" 匹配是巧合。

## 4. 综合

1. **失败的主要来源不是缺信息，而是"算出来的东西没有决定结论"。** 共 8 个失败簇（T03b 两个，T07 六个），其中非 PRECISION 的 5 个全都在轨迹中留有正确或近乎正确的中间量：

   | 失败 | 手里已有的对的东西 |
   |---|---|
   | GPT-6 T03b | 全对的分析 |
   | fable ws1 | F≈44 |
   | fable ws3 q5 | −0.0237 |
   | GPT-6 ws3 | 0.0174 的残余 |
   | fable T03b | 文档写着 0.01 |

   这可以叫"计算–结论脱节"（COMPUTE–CONCLUDE DISCONNECT）。
2. **fable 特有 HEDGE_AVERAGING。** 它在 T03b、T03、T07 ws1 三处都在互斥模型之间取中值或折中，这会把一个正确模型的答案拖出容差。
3. **噪声标定是 T03 簇的真正考点。** 从少量种子对估噪声，把 2σ 模式当成结构，再加项外推。
4. **T07 里有 3/6 是 PRECISION**，其中 ws4 q3 连 oracle 拟合器都过不了。T07 的 6 个失败里只有 3 个反映真实的能力差异。
5. **预算紧度作为难度杠杆（T03 对 T03b）。**
   - 紧预算没有让题目不可辨识：两个模型自己的 12 次数据复拟合都是 6/6。
   - 它起作用的唯一通道是**挤掉了能暴露噪声的重复 run**：oracle 的正确设计是 6 对种子重复，两个模型都是 0 对。
   - 所以它考的是"有限预算下先标定噪声再选模型"。这种难度依赖一次噪声实现（两题共享盐，n = 1），并且和容差混杂：q2 的 T 从 0.00539 变成 0.00297，fable 的 T03 答案在 T03b 容差下同样失败。
   - GPT-6 的 T03b 崩溃是过程断裂，与预算无因果证据。
   - 报告里"预算是开关"（第 437 行）应降级为："紧预算 + 该噪声实现 + 更紧的 q2 容差下，fable 的噪声追逐未被纠正；GPT-6 的失败与预算无关"。
6. **与 v4 调和。**
   - v4 e05 把 caps 从参考解用量的 2.58× 收到 1.37×，仍然全对（`v4/ScaleLab_v4_报告_2026-09-26.md` 第 21、173、194 行）。那里的关键观测**无噪声**（第 192 行："关键观测无噪声"，q1/q5 误差是精确的 0.00T），少买几次不会少任何信息。
   - T03b 里预算之所以"咬"到，是因为观测噪声（σ_diff = 0.0105）与竞争模型形式在可测点上的差异（0.01–0.02）同量级，**而**模型必须在这些形式之间做选择。
   - 合在一起的预测：**只有当"区分候选结构所需的重复次数 × 覆盖所需的配置数"超过 caps 时，预算才是杠杆。** 即便如此，它测的是噪声纪律，不是信息极限，而且难度随噪声实现波动，必须多个 world_seed 验证。
7. v4 的"唯一有效杠杆 = 带噪估计量 + 外推"与本分析相容：T03b 里真正起作用的也是带噪估计量上的模型选择。

## 5. 可做出题模板的机制

### 模板 A：噪声诱导的结构幻觉（来自 fable T03/T03b）

- **世界**：真律 k 个参数。存在一个"看起来合理"的额外结构项（例如效应随 D 衰减、常数惩罚），在世界里严格为零。噪声 σ 与"有、无该项两种形式在可测点上的差"同量级（约 1–2σ_diff）。在被问的外推点上，两种形式的差 ≥ 4T。
- **观测**：
  - notebook 给出**真实抽样但偏小**的少量种子对（可以按选择性报告的方式合法挑选，比如团队只报了"看起来稳定"的对）。
  - 同时在文字里正确给出噪声量级，形成可发现的矛盾。
  - caps 要求在"覆盖"与"重复"之间取舍：caps ÷ oracle ≈ 1.0–1.2，oracle 设计里一半是重复。
- **问题**：外推点上的效应量，再加一个依赖其符号的 verdict（像 q2、q5、q6）。
- **正确过程**：在关键配置上买种子对标定 σ（或采信文档里的 σ），在正确的 σ 下对嵌套模型做显著性检验，选简约形式再外推。
- **诱人的错误过程**：用 notebook 的小种子差估 σ，看到 2σ 模式，加项拟合，外推；或者在互斥模型之间折中。
- **必需的闸门**：
  - oracle 在 ≥ 20 个噪声实现上通过。
  - "追噪声" rival 在 ≥ 80% 的实现上失败且 ≥ 3T。
  - 难度必须跨 world_seed 验证，不能再 n = 1。

### 模板 B：参照点不是零点（来自 GPT-6 ws3 q4）

- **世界**：处理组终点仍带残余偏差（如 cosine 的 rmin 地板），残余 ≥ 4T（ws3 只有 2.46T，太薄）。
- **观测**：处理组 finals 与对照组 finals 在相同 (N, D) 上的配对，能直接看到残余。
- **问题**：只问**相对处理组自身终点**的增量。不要同时问绝对量，否则 q2 类题会把残余吸收进 E 而测不到。
- **正确过程**：给惩罚建带地板的模型，增量减去终点惩罚。
- **诱人的错误过程**：用在终点归零的 phase 变量，或者把处理组 finals 当成干净点。

### 过程指标（不是出题模板）

COMPUTE–CONCLUDE DISCONNECT 可以机械检测：要求 answers.json 的每个数都能追溯到某个 tool 输出（容差内匹配），再报告"未追溯答案"的比例。GPT-6 T03b 的 q1 = 0.68 就会被这一条直接标出。

## 6. 未能确定或证据不足之处

- GPT-6 T03b 的 0.68、−0.04、D 是怎么来的：推理加密，无法确定。"占位后忘记覆盖"只是假设。
- 紧预算是否**引起**了 GPT-6 的提前落笔：n = 1，与 `runs_left: 0` 同时出现，但无法建立因果。
- fable T03b 的噪声幻觉在其他噪声实现下是否复现：没有做多种子仿真，只报告本次实现的 z 值。
- T07 各世界都只有 1 次运行（每个模型、每个世界 H0 一次），不能区分"模型稳定会犯的错"和"单次抽样"。
