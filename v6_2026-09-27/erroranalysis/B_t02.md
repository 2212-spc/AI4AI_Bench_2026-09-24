## 1. 题目、真值与判分要点

**世界（ws2，`hidden/world.json` params）**

- 发散条件：run 发散当且仅当 lr > h0·(N/1e8)^−δ·(1+wu/w0)^ω·(Q if qk)。
- 参数：h0=0.004341，δ=0.4948，w0=0.02754，ω=0.5876，Q=47.30。
- 发散判定是确定性的：`div_jitter=0.0`（见 world.json spec；`R/scalelab/bp/t02_stability_edge.py:15` 写明 "deterministic in this lab"）。

**manual 中的关键条款（`tasks/t02-stability-edge-ws2/environment/app/manual.md`）**

- `:21` "The edge may move with N, warmup and qk-layernorm"。D 不在这个列表里。
- `:80` lr ∈ [1e-4, 0.05]。
- `:86` 单个 run ≤ 6e18 FLOPs，总预算 3e19，最多 40 个 run。

## 3. 逐 run 分析

每个 run 按以下五项展开：① 题与 key；② 过程；③ 成功 run 在同一决策点的做法；④ 标签；⑤ 判定。

### 3.1 G6-H0（ws2，0.57）：跑了角点，又把结果扔掉

**① 题与 key。** 失败三题：q2（key [−1.8386, −1.3580]）、q3（supported）、q4（supported）。

**② 过程。** 除 L#37 外全部 run 都是 qk=0。

实验序列：

- L#0–4：五个尺寸，D=20N，lr=0.05，全部发散（traj[12]）。
- L#5–24：N ∈ {2e7, 4e7, 8e7, 1.6e8}，D=20N，lr 从 1e-3 倍增到 1.6e-2（traj[15]）。
- L#25–36：在同样的尺寸上细化（traj[17]）。到 traj[18] 时已用 37 个 run，只剩 3 个。
- L#37：角点 N=3e8，D=2e8，lr .05，wu 0，**qk 1**，结果 ok。
- L#38：N=3e8，wu .05，lr .004，ok。
- L#39：N=3e8，wu .02，lr .0033，ok（traj[19]、[21]）。
- 从未在 N=3e8 观测到任何 qk-off 发散点，也从未跑过 wu=0 的 qk-off run。
- 结束时 FLOPs 用掉 1.79e19，还剩 1.21e19（traj[22]）。真正卡住它的是 40 个 run 的上限，不是 FLOPs。

推理过程：

- traj[8]："The qk-layernorm factor is explicitly documented as an unknown, so I'll test whether allowed measurements constrain it before assigning the required interval or verdicts." 这时的计划是对的。
- traj[19]："I'm using the remaining runs to constrain the qk-layernorm factor at the largest allowed size and check the effect of longer warmup." 但角点 run 直到第 38 次才发出。
- traj[26]："qk-on claims remain conditional because the documented 2x–60x multiplier is not identifiable from the lab. I'm now writing the answers with the qk interval spanning that full documented factor range."

**出错点在 traj[26]。** 它把"不能点识别"当成了"没有信息"。L#37 在 cap 处未发散，本身就给出不等式 Q·edge_off(3e8, 0) ≥ 0.05。manual `:50–51` 也明确要求 set 答案要与"what the lab can measure"取交集。

各题的具体情况：

- **q2**：答案 = [q1 + log10 2, q1 + log10 60] = [−2.857, −1.380]。误差 −40.74T，正好等于 rival B2 的 39.86T 加上自身 q1 误差 −0.88T。
- **q3**：traj[24] 里它自己算出 0.00117/edge = 1.68，大于 1，意味着会发散；但 answers.json 写的是 "refuted"。q3 的措辞是 "diverges"，与 q4/q5/q7 的 "does not diverge" 极性相反，这是一次极性笔误。
- **q4**：按它自己的文档区间，0.00468/edge = 6.73 落在 [2, 60] 内，所以答 undetermined，与它的 q2 自洽。这是 q2 错误的传播，不是独立错误。rival B2 在 q4 上同样答 undetermined（见 `cert.json:212` 起）。

**③ 成功 run 在同一决策点。** F-H0 s001:147 THINK："For qk=1 at N=3e8, the lr=0.05 stays stable, meaning the factor must be at least 12.5 given the edge is below 0.004 there … the tightest bound comes from the largest N. I'm wondering if turning off warmup lowers the edge threshold, which would let me test qk=1 at 0.05 with wu=0 at N=3e8 to get a sharper lower bound on the factor, since the factor itself shouldn't depend on warmup."

面对同样的"cap 处未发散"，fable 立刻把它写成不等式，并由此推出要去 wu=0 的角点。

**④ 标签。** q2：ANCHOR_DOC + CENSORED_OBS_DISCARDED；q3：INCONSISTENT；q4：由 q2 传播。

**⑤ 判定。** q2 是有意义的失败：它已经拿到了决定性数据（L#37），却在解释环节把数据丢掉，这正是本题要测的能力。q3 是真实存在的低级极性笔误，但与 T02 的考点无关。

### 3.2 G6-H0r2（ws2，0.86）：D=20N 让角点不可达

**① 题与 key。** 失败题：q2（key [−1.8386, −1.3580]）。

相关原话：

- traj[8]："…using D=20N so the extrapolation matches production."
- traj[10]："extending the same D/N=20 line toward the largest affordable sizes"

在 D=20N 下，每个 run 的 FLOPs = 6·N·20N = 120N²。per-run 上限 6e18 意味着 N ≤ 2.24e8，所以只要不放弃 D=20N，N=3e8 的角点在结构上就跑不到。manual `:21` 没有把 D 列为影响发散边缘的因素，而 D=20N 正是笔记里的设计（`notebook/lab_notes.md:3`）。

后续过程：

- traj[14]、[15] 两次 API 调用都在 153 s 超时，traj[16] 被强制降到 medium effort。
- traj[17]（medium）："qk-on remains stable at the tested points"。
- traj[23]（medium）："The final run confirms the exact scale law … qk-on answers must retain the documented 2x–60x unknown factor."
- 写答案的 traj[23] 调用：q2 = [logedge + log10 2, logedge + log10 60]，误差 −40.19T，等于 B2 的 −39.86T 加 q1 的 −0.33T。

q4 答 supported。但按它自己的 q2，lr = 10^−2.33 落在 [−2.84, −1.37] 内，应答 undetermined。所以 q4 与自身 q2 矛盾，答对属于蒙对（与报告 `:435` 的描述一致）。

**③ 成功 run 在同一决策点。**

- F-H0 s000:406："…locate the edge at each N using the smallest viable D, since dataset size likely doesn't affect where that edge sits."
- G55 traj[9]："…those are cheap enough with minimum token counts and directly constrain the production extrapolation."

**④ 标签。** ANCHOR_DOC + CENSORED_OBS_DISCARDED + NO_DISCRIMINATING_EXP（D=20N 导致没有角点）；q4 INCONSISTENT。

**混杂因素。** 答案是在被强制降到 medium 之后写的。但 G6-H0 全程 high effort，也犯了同样的 q2 错误，所以降档不能充分解释这次失败。

**⑤ 判定。** 有意义。同一机制复现了一次，而且这次在实验设计层面也失败了。

## 4. 专题问题

### a) GPT-6 H0 的算力花在哪里？跑没跑角点？为什么没用上？

**花费对比**

| run | FLOPs | 对应 fable run | fable FLOPs | 倍数 |
|---|---|---|---|---|
| G6-H0 | 1.79e19 | F-H0 | 5.45e18 | 3.3× |
| G6-H0r2 | 2.55e19 | F-H0r2 | 4.63e18 | 5.5× |

- G6-H0 有 94% 的 FLOPs 花在 D=20N 的 N 网格上（OK run 79%，发散 run 15%）。
- G6-H0r2 有 90% 花在 D=20N 的 OK run 上。
- F-H0 占比最高的是 D=2e8 的 OK run（37%）。

**原因**

- 照搬了笔记里的 D=20N（`lab_notes.md:3`），而 manual `:21` 并没有把 D 列为影响边缘的因素。
- FLOPs = 6·N·D。在 D=20N 下，N=1.6e8 的一个 OK run 要 3.1e18；同样的 N 在 D=2e8 下只要 1.9e17，差 16 倍。

**瓶颈是 run 数，不是 FLOPs**

- G6-H0 结束时还剩 1.21e19 FLOPs（traj[22]）。真正的瓶颈是 40 个 run 的上限：37 个花在非自适应网格上，其中包括 5 个在 lr=0.05 下全部发散的开局探针，以及大量远低于边缘的 OK run。留给角点的只剩 3 个。
- 所以"算力是 fable 的 3.3–5.5 倍"更准确的描述是"run 名额被网格耗尽"。
- 对 G6-H0r2 来说，D=20N 直接把 N 限制在 2.24e8 以下，角点根本跑不到。

**是否跑了角点**

- G6-H0 跑了：L#37，第 38 个 run，在 traj[19] 发出，结果 ok。
- G6-H0r2 没跑：最大 N 为 2.2e8，也没有 wu=0 的 run。

**为什么没用上**

- traj[26] 认定 Q "not identifiable from the lab"，于是改用文档区间。也就是把"不能点识别"等同于"不能约束"。
- 它也没有在角点测 qk-off 边缘。剩下的 2 个 run 用在了 wu .05、lr .004 和 wu .02、lr .0033 上，两个都是 ok，都构不成括区间。
- 严格说，如果结合 N=3e8、wu .02 的外推边缘，再加上它自己在 L#38 测到的"warmup 会升高边缘"，L#37 仍然可以换算出 Q ≳ 14。这属于 B3 级的界，仍会差约 5.6T。

**对报告的更正**：报告 `:433` 写的"没法换算成 Q 的下界"应改为："只能换算成较松的下界，而它没有去换算。"

### b) H2 空白 run：执行窗口说法的核查

详见 3.3。结论：这是模型行为，不是框架截断。

证据：
- 没有任何时限信息传给模型（`gpt_agent.py:17–20, 26–30`；manual `:30`）；
- 0 次 API 错误，0 次超时，全程 high effort；
- "window" 一词只出现在 traj[28]。

报告 `:460` 的结论是对的。补充三点：

1. `gpt_agent.py:180–181` 把任何不带 tool call 的消息都当作完成，不检查答案是否仍全为 null。
2. 整个 run 的 reasoning tokens 只有 659，远低于其他 GPT-6 run，原因没有证据可查。
3. 同配置的 H2r2 得了 0.86。这一次空白不应当作 H2 条件下的能力证据。

### c) 中档模型：同一机制，还是基础崩溃？

**haiku：基础崩溃，不是同一机制。** 具体表现为：D=20N 耗尽预算、编造数据点、点题答成区间、相信笔记的公式。它没有走到删失决策点，所以这个 run 不能说明 T02 的考点对 haiku 有效。

**sonnet：框架活锁。** 被中止之前，它的设计是笔记式的 D=20N 网格，加上中等尺寸的 qk 探针。它的删失解释本身是对的（s014:1009）。所以它与 G6-H0 的"丢弃删失观测"不是同一机制，更接近 B4 或 PARTIAL_CORNER。

**跨模型最一致的分界：是否照搬笔记的 D=20N。**

- 照搬了：G6-H0（L#0–36）、G6-H0r2（全部）、HK（全部）、SN（从 s000:940 起）。
- 以 D=2e8 为主（按 FLOPs 计）：fable 的 4 个 run、G55、G6-H2r2、G6-ws3。
- G6-H2 用的是 D=3e9，是另一种形式的"大 D"。

### d) H2 能否消除失败？差距在知识、设计还是校准？

**结果对比**

| 模型 | H0 | H2 |
|---|---|---|
| fable | 6/7、7/7 | 7/7 |
| GPT-6 | 4/7、6/7 | 0/7（弃权）、6/7（q2 差 1.12T） |

**H2 下的变化。** 在真正答了题的那次 GPT-6 H2 run（H2r2）里，40T 级别的 B2 型错误消失了，只剩 1.12T 的精度失分。它在 traj[33] 明确写出了 "censoring Q from below"。

**H2 不是必要条件。** G6-ws3（H0，无提示）同样做对了删失转换（traj[16]），F-H0r2（H0）拿到 7/7。

**H2 也不是充分条件。** 它没能阻止 H2 那次弃权，也没能阻止 H2r2 中间版里 q3 的极性翻转（traj[29]）。

**结论**

- 差距不在于"知道定律的形式"（知识），而在于两点：
  - **解释**：右删失的观测算不算信息；
  - **设计**：是否把角点定义为"N 最大 × wu 最小"，并在同一个角点二分 qk-off 边缘。
- "校准"的方向与预期相反：GPT-6 的错误是区间过宽、信息没用上，而不是区间过窄。
- 每个条件下只有 1–2 个 run，以上结论都属于弱证据。

## 6. 综合

1. **跨模型反复出现的机制**
   - M1 CENSORED_OBS_DISCARDED / ANCHOR_DOC：认定"不可点识别"后退回文档区间，误差约 40T。出现在 G6-H0、G6-H0r2。HK 因为没有 qk 数据，也落到了同一个答案。
   - M2 PARTIAL_CORNER：删失解释是对的，但只在 N 上推到极端，没有在 warmup 上推，误差 4–6T。出现在 F-ws3、G55。SN 连 N 也没有推到极端。
   - M3 PRECISION：并行或粗糙的括区间带来 1–2T 失分。出现在 F-H0、G6-H2r2、G6-ws3。
   - M4 照搬笔记的 D=20N：导致角点不可达或 run 名额耗尽。出现在 G6-H0、G6-H0r2、HK、SN。
2. **GPT-6 的特有表现**
   - 5 个 run 中，2 次丢弃删失观测（ws2 H0、H0r2），2 次正确转换（ws2 H2r2、ws3 H0），1 次虚构"执行窗口"后弃权。
   - q3 正向措辞的极性笔误出现了 2 次（H0 终版、H2r2 中间版）。
   - 同一模型、同一题上的表现是随机的，不是稳定缺陷。
3. **fable 的特有表现**：4 个 run 都在 N=3e8 跑了 qk-on@cap，并换算成下界，从未丢弃删失观测。失分只来自紧度：PARTIAL_CORNER 1 次，PRECISION 1 次。
4. **haiku**：通用纪律崩溃（编造数据、点题答区间、预算耗尽）。**sonnet**：框架伪影。两者都没有测到 T02 的考点。
5. **rival 的预测力**：模型 q2.lo 的误差约等于某个 rival 的误差加上模型自己的 q1 误差，数值逐位吻合。
   - G6-H0：−40.74 = −39.86（B2）− 0.88
   - G6-H0r2：−40.19 = −39.86 − 0.33
   - G55：−5.86 ≈ −5.57（B3）− 0.33
   - F-ws3：−4.08 ≈ −3.98（B3）− 0.14
6. **计分口径**：10 个作答的 run 中，q2 有意义失败 5 个，精度失分 2 个，通过 3 个（其中 G6-ws3 是靠误差抵消通过的）。真正的区分度来自 M1，其次是 M2；M3 属于容差边缘的噪声，应该单独计。
7. **出题模板（T02-q2 的抽象）**
   - **世界**：生产量 = 可测部分 g(x_prod) × Q，Q 是文档只给了范围的常数。
   - **观测模型**：二值、确定性、有上限 cap 的 pass/fail，使 Q 在实验室里只能右删失。
     - 可达最紧界 = cap / min_x g(x)。
     - 最小点位于多维角点，而且至少一个维度与生产设置方向相反（这里是 wu=0，而生产用 wu=0.02）。
     - 另外设置一个"贵但无关"的旋钮（D），并让笔记示范一个会使角点超出 per-run 上限的设计。
   - **问题**：要求回答 set，lo 的真值是"实验室可达的最紧界"，容差远小于文档范围。
   - **正确过程**：
     1. 把"在 cap 处未失败"写成不等式；
     2. 逐个旋钮判断它对 g 的单调方向，并识别出无关旋钮；
     3. 在角点跑删失探针；
     4. 在同一角点顺序二分可测边缘，直到宽度 ≤ 约 7%；
     5. 与生产外推合成。
   - **诱人的错误过程**：认为不可辨识就等于没有信息（B2）；在生产设置处取界（B3）；在中等尺寸取界（B4）；在 cap 以下探测（B6）；照搬笔记设计导致角点不可达；并行做粗二分。
