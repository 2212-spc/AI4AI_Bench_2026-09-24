## 1. 主会话独立复核

### 1.1 v2 D 族：key 错了，GPT-6 的"失败"是对的（已确认）

**方法**
- 把 `d-design-sealed`、`d-design-open` 的 `solution/` 和 `environment/app/` 拷到 /tmp。
- 自写 `full.py`：继承 `truth_b.Truth`，只加一件事——`recovery_log.csv` 的行按原意变成约束：
  - `value` 行：固定该 run 的值，并从当日 digest 余量里扣掉；
  - `range` 行：与该 run 的 box 支撑取交。
- 用原 `design_d.Design` 重算全部 31 项。脚本另外断言：不加日志时逐项复现 key.json。

**依据**
- 题面原文："Nothing in `/app` is a decoy: every file is exactly what it claims to be"。
- consistent 的定义是 "contradicts nothing in `/app`"。
- `recovery_service.md` 写明："that range is a genuine constraint on the run's pass_rate"。
- 所以日志约束必须计入。`truth_b.py` 全文不读 `recovery_log.csv`（grep 为 0）。

**结果**

| 任务 | 日志行（value/range/no_bundle） | 落在被问 contrast 人群里的日志行 | 真值会变的项 | GPT-6 | Fable |
|---|---|---|---|---|---|
| d-design-sealed | 4 / 22 / 14 | 4 | k01, k02, k03, w01（4/31） | 4 项全部逐位等于"加日志真值" | 4 项全部等于旧 key |
| d-design-open | 4 / 34 / 0 | 3 | k02, k03（2/31） | 2 项全部等于"加日志真值" | 2 项全部等于旧 key |

- 在修正后的真值下，GPT-6 两题都是 31/31，Fable 分别错 4 项和 2 项。
- Fable 在 `cc_stream_017` [540] 原话："the recovery log itself also constrains runs it names (its ranges and values are true), so I'll fold those into the bounds"。
- 但它交的数与不含日志的旧 key 逐位相同，也就是**宣布了、没执行**（INTENT_DROPPED）。
- 这是一个被错 key **奖励**了的真实失败。

### 1.2 v2 S 族：估计对象有歧义，而且字面读法支持 Fable（已确认）

- 题面问："what fraction of the runs launched there were removed *by the divergence guard specifically*"。
- `launcher.md` 写明，抢占在 run 产生 loss 之前决定。所以被守卫删掉的 run 数 = n·(1−p)·q，占**发射数**的比例就是 (1−p)·q。
- key（`estimator_s.py`，`counts_with_preemption` 分支）给出的是 1−(nobs/n)/(1−p) = q，即守卫的条件触发率。
- Fable 与 key 的比值：
  - batch=512 的 r1/r2/r3/r6：0.912 / 0.892 / 0.894 / 0.901；
  - batch=256 的 r5：0.839。
  - 它自拟合的 1−p̂₅₁₂ = 0.901，与上面吻合。
  - r4 的比值 0.65 不说明问题，因为两个数都约等于 0。
- 轨迹 `cc_stream_000` [215] 与 `cc_stream_001` [385] 明确推导了 (1−p)(1−Φ)，并写道："I'm weighing whether that's really the intended definition"。
- 结论：这是 ESTIMAND_AMBIGUITY，而且字面读法更支持 Fable。v2 报告 L58 的说法"把两者的合计当成了其中之一"方向正好反了：Fable 的数**小于** key。

### 1.3 抽查（证实）

- **v4 e03 a1**：答案 `[0.389, 0.392]` 的宽度是 0.0030000000000000027，大于 `max_width` 0.003；区间与允许带有交集。这是浮点伪影。v4 报告 L135 "越出允许带"的说法不对。
- **v3 T02 G6-H0**：ledger 第 38 条（run_id 38，零基第 37 条）在 N=3e8、wu=0、qk=1、lr=0.05 的角点 `status ok`。随后它写道："the documented 2x–60x multiplier is not identifiable from the lab"，并用了全文档区间。与 B 报告一致。
- **v3 T03b**：用 oracle 拟合器在 GPT-6 **自己的** 12 次 run 加 notebook 上重拟合，6 项全过（q2 0.04T，q5 0.04T）。Fable 那一份也是 6 项全过（q2 0.07T，q5 0.05T），由子代理先算、主会话读了输出。结论：失败不在数据，在分析和落笔。

### 1.4 由此推翻的旧结论

- **旧结论**："唯一有效杠杆是逼迫精确陈述无知"。
  - 出处：v2 报告 L188/L238，以及记忆 `ai4ai_bench_v2_delivery`。

## 3. 机制归并：六个有意义的能力需求

判定是否"有意义"的标准：
- 该错误在真实 AI 研究里会导致错误结论；
- 它有一个可以明文写出的**被违背的假设**；
- 正确做法在预算内可以执行。

| 代号 | 能力需求（正向表述） | 被违背的假设 | 前沿证据（单元） | 跨模型？ |
|---|---|---|---|---|
| **M1** | 知道测量的**有效域**：局部斜率、局部形式、局部上下文、单维极端都不能外推到全局 | "在我测到的范围里成立 ⇒ 在被问的地方也成立" | #1 #2 #4 #8 + E1 | 是（GPT-6 偏函数形式，Fable 偏维度或组合） |
| **M2** | 把**部分信息**（删失、区间、不等式）当信息用 | "不能点识别 ⇒ 没有信息" | #6 #7 + v2 Fable（隐） | 是（GPT-6 在 T02，Fable 在 v2 D） |
| **M3** | **误差预算**：分清噪声与结构、方差与偏差，先标定噪声再选模型 | "残差小 / 重复多 ⇒ 对"；"看到模式 ⇒ 有结构" | #2 #4 #5 #10 #11 | 是（Fable 为主） |
| **M4** | **结论可追溯**：答案来自自己最新的分析，宣布的方法被执行 | "我说了要做 ⇒ 我做了" | #5 #9 + v2 Fable（隐） | 是 |
| **M5** | 对**二手信息**（文档、notebook、提示）校准信任，测量优先 | "文档或前人设计是对的 / 够用" | #3 #6 #7 + haiku×2 | 是 |
| **M6** | **参照点不是零点**：对照条件本身也带残余 | "基线在渐近线上" | #12 | 仅 1 例 |

### 两点观察

1. **M1、M2、M3、M5、M6 都是"一个被违背的假设 × 一个诱人的捷径路线"。** 这正是 v5 `routes.py` 的 B 证书能度量的结构：捷径的偏差除以 oracle 的精度。于是它们可以编译成题。M4 不一样，它是过程属性，只能当过程指标度量（答案对 tool 输出的可追溯率），不能直接出成考点。
2. **同一模型、同一题的表现是倾向而不是确定行为。** GPT-6 在 T02 共 5 个 run（ws2 4 个、ws3 1 个）：无提示的 ws2 两次都丢弃删失观测；换种子到 ws3 无提示没丢；ws2 加 H2 提示后一次正确转换、一次虚构"执行窗口"后弃权。n 太小，分不开种子效应与随机性，所以难度只能写成**失败率**，每格至少要 3 次运行。（2026-09-27 核查更正：原文误写为"ws2 的 5 个 run"。）

## 5. 对题目生产的直接含义

1. **先把伪影率降下来，再谈难度。** 25 个失败单元里有 6 个是伪影，另有 1–2 个真实失败被错 key 掩盖。必须新增的闸门：
   - **规范一致性**：key 生成器必须读取 `/app` 中每个声明为真的文件。机械检查办法是逐个文件做消融，看 key 是否变化；文件不影响 key 却被声明为"约束"，就报警。
   - **估计对象歧义**：每个问句至少写出两种字面读法，分别算值；差值 > T 就必须改写题面。
   - **浮点边界**：宽度或区间比较一律加 1e-12 的相对余量。
   - **harness 终止**：答案全空时拒绝结束。
2. **机制卡 × 被违背假设（AV 模板）才是考点单位**，而不是"机制卡 × 障碍"。v3/v4 的障碍模板 O1–O17 多数描述的是作者打算走的推导，而实测会咬人的都是某个被违背的假设。
3. **M4 做成过程指标**：`answers.json` 中每个数字都要能在某个 tool 输出里以容差匹配到。未追溯比例当作报告字段，不计入正确率。
4. **每格至少 3 次运行，报失败率**，并把真实机制、精度边缘、伪影分三栏报告。
