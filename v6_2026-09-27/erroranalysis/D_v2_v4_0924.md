### 2.1 D 族：GPT 的"过窄区间"其实是 key 漏证据

**题面语义**（`tasks/d-design-sealed/instruction.md`）
- L9–12："recovery_log.csv is the record of every recovery request… Nothing in /app is a decoy… no file is wrong"。
- L21–23：答案 "consistent if it contradicts nothing in /app"。
- L31–35："…recovery_log.csv is a sample of what it actually did, on runs that are not the ones you are asked about… Whatever it is, it is true, it never contradicts /app"。
- `environment/app/recovery_service.md` L12–23、L25–27：返回的 range "is a genuine constraint on the run's pass_rate"。

**参考解**
- `solution/truth_b.py` 的 `Truth` 只用 eval_results 和 recovered shards 构造取值，**完全不读 recovery_log.csv**。
- `support()`（L89 起）给出的支撑：
  - below_retention_floor：[base, floor(dropped_at)−0.0001]
  - shard_file_lost：[max(floor(fin), base), 1]
  - never_written：[base, 1]
- `diff()`（L152 起）用闭式计算。
- 生成器 `factory/fam_d/gen_ds.py` L39（G10）只保证被问的 run 不出现在 log 里。它**没有**保证 log 对被问区间不构成约束：log 里其他 run 的值会通过每日 digest 的等式约束传播过来。

**复算**（副本，monkeypatch `Truth`，把 log 的 value/range 也加为约束；dsv2 的 log 有 40 行，其中 4 行 value、22 行 range；dov2 有 38 行，其中 4 行 value、34 行 range）

| dsv2 k02 | [−0.033084, 0.158623] | [−0.029038, 0.152887] | 相同 |
| dsv2 k03 | [−0.056069, 0.162797] | [−0.052986, 0.147275] | 相同 |

### 2.2 S 族：Fable r2/r3/r6 是 estimand 读法之争，不是"合计当分解"

**题面与 key**
- `tasks/s-censored-a/instruction.md` L10–11："what fraction of the runs launched there were removed *by the divergence guard specifically*"。分母是 launched。
- `environment/app/launcher.md` L20–21：缺失 "for exactly one of two reasons"；L36–37：调度器 "decides before the run produces one"。
- key（`tests/key.json`）：r1 9.9e-05、r2 0.390591、r3 0.638913、r4 5.8e-05、r5 0.02275、r6 1.0；容差 0.04（r3 为 0.048）。
- 参考实现 `solution/estimator_s.py` L258–278 的 `_censor` 默认分支 `counts_with_preemption` 算的是 `1 - (nobs/n)/(1-p)`，也就是 **P(loss>guard | 未被抢占)**，是条件概率。
- 同一函数里的 rival 有 `zero`、`raw_missing`（两种机制的合计）、`model_phi`，**没有**"占全部 launched 的比例"= (1−p)·P(tail) 这一种读法。作者考虑过"合计"，但没考虑字面读法。

**Fable 做了什么**（`run_logs/cc_s2/`，证据 B）
- cc_stream_000 [215] THINK："since preemption happens before a run produces a loss, the fraction of runs removed specifically by the divergence guard should only apply to the subset that actually completes, giving something like (1-p_preempt) times the tail probability… rather than that probability alone"。
- cc_stream_001 [385] THINK："though I'm weighing whether that's really the intended definition given the ambiguity in how the question frames 'runs removed by the guard.'"
- cc_stream_001 [452]："using 1-p_b=0.90"。
- cc_stream_001 [477] 终答："Each guard fraction is the non-preempted share times the probability the cell's loss exceeds the threshold… r6 is the zero-survivor cell, so every non-preempted run there was removed by the guard, giving 0.90."

**数值核对**

| 项 | Fable 答案 | (1−p)·key | key | 原始缺失比例（"合计"读法） |
|---|---|---|---|---|
| r2 | 0.3485 | 0.3527 | 0.3906 | 0.4455 |
| r3 | 0.5709 | 0.5766 | 0.6389 | 0.6685 |
| r6 | 0.9008 = 1−p | — | 1.0 | 1.0 |

**(b) 两个模型的"性格"**（n 小，只是倾向）
- **GPT-6**，真失败 5 次运行（e05×2、w14 r3、w14 r1 边界、wA-b40h）：
  - 全局实验设计强：w14 的 3 次通过和 r1 都用了全因子或锚定筛选；D 族里读全了证据。
  - 但函数形式或短名单一旦选定，就不再检验形式，转而追求精度（3 次）；另有执行层失误 2 次。

**(c) 抽象模板**
- **M1 LOCAL_VALIDITY_EXTRAPOLATED**
  - 世界：效应或函数形式依赖背景 Z（交互或曲率），证据只覆盖 Z∈R，被问的量在 Z∉R；R 内信号干净且有叙事，目标区的单次探针噪声大，而且"看起来更差"。
  - 正确过程：先列出证据覆盖了哪些背景，再往目标区放区分性探针；做不到就把结论标为不可识别。
  - 诱惑过程：把 R 内的斜率或效应直接搬过去。
  - 类型：**estimand 识别**（支撑 / positivity 问题）；不是知识问题，因为模型自己陈述了"交互存在"的原则，却只用了一次。
- **M2 PRECISION_OVER_COVERAGE**
  - 世界：预算有限；复制能看得见地降低 SE，偏差却看不见；被问量的误差由偏差或未覆盖的格主导。
  - 正确过程：先覆盖、先检验形式（残差结构、留一），最后才复制。
  - 诱惑过程：复制现任，报告一个很小的 SE。
  - 类型：**设计**（预算分配）加**校准**（把 SE 当作总误差）。
- **M3 THEORY_OVER_MEASUREMENT**（仅 1 例，还不成模板）：决策量可以直接测但成本高，提示给出带共享常数的公式。正确做法是为决策量预留直接测量；诱惑是用公式加额外假设来代替测量。类型：设计加识别。
