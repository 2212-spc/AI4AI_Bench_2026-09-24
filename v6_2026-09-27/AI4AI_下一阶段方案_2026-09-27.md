# AI4AI Bench 下一阶段方案：失败机制、L1.5 移植世界与自动出题 loop

> 2026-09-27。本文回答用户提出的三个目标：应该怎么做、为什么这样做。每个建议都给出支撑证据，这些证据来自三组本次新做的材料：
> - `erroranalysis/`：v2–v4 和 09-24 全部失败项的轨迹级错误分析；
> - `proto_goal2/`：目标 2 原型，把真实机制移植进虚拟世界，并测试不封顶评分；
> - `proto_goal3/`：目标 3 原型，把失败机制自动编译成可认证的题。
>
> 两个原型都**零模型调用**（本次会话没有 key），所有数字都可以用各自 README 的命令重算。凡是需要模型数据才能下结论的地方，本文都明确标为**假说**，并给出检验它的实验。

## 0. 一页结论

**目标 1：难度机制。**
- 前沿模型的真实失败可以归并成 6 个有意义的能力需求（M1–M6）。其中 M1/M2/M3/M5/M6 有共同结构："**一个被违背的假设 × 一条诱人的捷径**"。M4（结论不可追溯）是过程属性。
- 但 v2–v4 的 25 个失败单元里只有 12 个（48%）是真实机制。其余是伪影（6 个）、精度边缘（6 个）和笔误（1 个）。另有 1–2 个真实失败被错误的 key 掩盖了。
- 所以"找机制"的第一步不是想新杠杆，而是先把伪影剔掉；否则量产出来的是伪影。
- 这项分析推翻了一条旧结论："唯一有效杠杆是逼迫模型精确陈述无知"。它的两条证据，一条是 key 错了，一条是估计对象有歧义（§2.1）。
- 中档模型的证据只有 4 个 run。据此形成的"L0 执行纪律 → L1 统计卫生 → L2 有效域推理 → L3 设计"分层只是假说，本文给出检验它的实验设计（§2.5）。

**目标 2：从 L1 走向真实领域。**
- 建议在 L1 与 L2 之间插一层 **L1.5**：用真实发表的机制（本原型用的是 Multi-Power Law）当世界的物理，常数取反事实值，并声明验证域。
- 这样做的好处是：正确性仍由模拟器按构造保证，不需要 domain expert；而考察的能力（测量、建模、设计实验、验证）是真实领域里的能力。
- 原型证明了三件事：
  - 反事实常数能把"背诵"与"会测量"干净地分开：背 WSD 配方的策略从 0.80 掉到 −0.83，测量建模策略保持 0.95–0.96。
  - 以出题人流程的输出当 key，会把天花板压低一半以上：作者式网格 0.44，对比测量建模 0.96。
  - "晚发不稳定"世界里存在一个必须**主动设计实验**才能解的题。
- 同时暴露了最大风险：已发表的律在验证域外会给出荒谬奖励。物理上看不出问题的漏洞（s>1.05 且 L≥L0）共 120 个，其中 45 个（s=1.05–1.23）能躲过所有廉价闸门。
- 所以"创新不以 oracle 为天花板"在**评分**上可以做到，但**有效天花板是律的验证域**。超出验证域的创新，律已经无法判分，只能交给 L2 审计（§3）。

**目标 3：agent 自动出题 loop。**
- 原型把 M1/M2/M3/M6 编译成 4 个模板，在 5 张机制卡上实例化。搜索式 proposer 在 864 个世界里找到 316 个能出 T2 认证题的世界，18 格中有 15 格出了题。
- 更重要的发现是 loop 自身的错误：
  - 修复规则写错；
  - 数值捷径其实是合法插值；
  - 捷径在 lab 里不可执行；
  - 题面泄漏答案：20% 的认证题被渲染审计抓出；
  - 世界不同步。
- 不计红队时认证的题（oneshot + loop 共 173 道），62% 会被红队杀掉。
- 另一方面，在 search T1 的 376 道被杀题里，53% 的红队路由其实落在 T 内，也就是走这条路的 agent 会被判对。红队路由本身也需要检验。
- 多样性有一半是换皮：M2/M3 的认证题 86–88% 由统计常数驱动，换卡不换考点。
- 结论是：**LLM 应当放在"提出新假设"那一层**，也就是新模板、新红队路由、新机制卡；**门、真值、世界搜索保持代码**。并且每个角色都必须有一个能证伪它的检查（§4）。

**合起来的 pipeline**（§5）：
1. 模型实跑；
2. 轨迹错误分析，分成真实 / 精度边缘 / 伪影三栏；
3. 可归因性分流：已知路由 / 路由库盲区 / 新机制；
4. LLM 提议新模板或新路由；
5. 代码编译并搜索世界；
6. 门 + 红队 + 渲染审计；
7. 按签名策展；
8. 回到模型实跑。

第一轮实跑是整个方案里最关键的未知数，§6 给出五周计划和每一步的停止条件。

## 1. 对三个目标的理解

用户的原话可以拆成下面三组可证伪的问题。拆的目的是避免"做了很多但不知道算不算达到"。

| 目标 | 用户要的 | 我理解的可证伪版本 | 判定"达到"的标准 |
|---|---|---|---|
| 1 难度机制 | 顶尖和中等模型在 ai4ai 为什么失败；机制要有意义；最好能量产 | (a) 失败能否归到少数几个**有明文被违背假设**的机制上？(b) 这些机制是否跨模型、跨题复现？(c) 能否把机制编译成新题，而且新题上的失败率可以预测？ | 在新编译的题上，模型的失败能被归因到预先登记的路由上，而不是出现新的无法解释的错答 |
| 2 L2 真实领域 | 考真实领域的设计实验、推理、创新；正确性不依赖专家；创新不以 oracle 为天花板 | (a) 能否把真实机制移植进虚拟世界，同时保证真值正确？(b) 在这种世界里，失败是否对应真实能力？(c) 评分能否超过作者答案，而又不被律的漏洞利用？ | 存在一道题：背诵策略失败、测量策略成功、有预算内的存在证明；并且 s>1 的提交都能被审计 |
| 3 自动化 loop | agent 系统通过 loop 迭代、比较自动地产出新题 | (a) 哪个角色适合 LLM，哪个必须是代码？(b) loop 自身会犯什么错？能否被 loop 自己的证据抓到？(c) 产出的多样性是真是假？ | 每个角色都有一个能证伪它的机械检查；产出按"考点签名"计数而不是按题数计数 |

有两个约束贯穿全文。
- **正确性来自构造。** 这是 09-26 讲解文档的核心结论：在前沿分数区间，坏题决定分数。所以任何方案都不能引入"需要专家判断真值"的环节。
- **难度要测，不能靠作者声明。** v4 已经否证过四个作者声明的杠杆（反先验常数、推理链深度、干扰机制数、不可达配置），全部 0.00T。

## 2. 目标 1：难度机制

### 2.1 做了什么，发现了什么

对 v2、v3、v4 和 09-24 MiniLab 的全部失败项做了轨迹级分析。报告见 `erroranalysis/` 下的 A–E 五份，汇总在 `E_synthesis.md`。方法上有两条要求：
- 每个失败单元都要回到 tool 输出和原话，不能只看分数；
- 影响最大的两个判断（v2 D 族、S 族）由主会话在源目录之外的副本上**独立重算**。

**结果一：一半的"失败"不是能力问题。**

| 类别 | 单元数 | 例子 |
|---|---|---|
| 伪影（key 错、估计对象歧义、浮点、harness） | 6 | v2 D 族 key 没读 recovery_log；v2 S 族分母有两种读法；v4 e03 区间宽度 0.0030000000000000027 > 0.003 |
| 精度边缘（< 约 2T，没有 rival 可归因） | 6 | T07 ws4 q3 连 oracle 拟合器都过不了 |
| 笔误（符号或极性） | 1 | T07 F-ws3 q5 |
| **真实机制** | **12** | 见 §2.2 |
| 被错 key 掩盖的真实失败 | 1–2 | v2 Fable d-design：宣布了要用日志约束，但交的数与不含日志的旧 key 逐位相同 |

**结果二：v2 的两处"区分度"都不成立。**
- D 族的 key 没有使用题面声明为真的 recovery_log。在修正后的真值下，GPT-6 两题都是 31/31，反而是 Fable 错了 4 项和 2 项。
- S 族的问句有两种字面读法，而且字面读法更支持 Fable 的答案（Fable/key ≈ 0.9 ≈ 1−p）。
- 所以旧结论"唯一有效杠杆 = 逼迫精确陈述无知"失去了全部证据。这条结论出现在 v2 报告、经验手册、讲解文档、汇报稿和记忆里，更正清单见 §8。

**结果三：同一模型、同一题，表现是倾向而不是确定行为。** GPT-6 在 T02 共有 5 个 run（ws2 4 个、ws3 1 个）：
- 无提示的 ws2 两次都丢弃了删失观测；
- 换种子到 ws3，无提示也没丢；
- ws2 加 H2 提示后，一次正确转换，一次虚构"执行窗口"后弃权。

n 太小，分不开种子效应和随机性。所以难度只能写成**失败率**，每格至少 3 次运行。

### 2.2 六个能力需求

判定"有意义"用三条标准：
1. 该错误在真实 AI 研究里会导致错误结论；
2. 它有一个可以明文写出的**被违背的假设**；
3. 正确做法在预算内可以执行。

| 代号 | 能力需求 | 被违背的假设 | 证据 | 能否编译成题 |
|---|---|---|---|---|
| M1 | 知道测量的**有效域**（局部斜率、局部形式、局部上下文、单维极端都不能外推） | "在我测到的范围成立 ⇒ 在被问的地方也成立" | 4 个单元 + MiniLab E1；GPT-6 偏函数形式，Fable 偏维度或组合 | ✓ 模板 M1 |
| M2 | 把**部分信息**（删失、区间、不等式）当信息用 | "不能点识别 ⇒ 没有信息" | GPT-6 T02 两次 40T | ✓ 模板 M2 |
| M3 | **误差预算**：先标定噪声，再选模型；分清方差与偏差 | "残差小 / 重复多 ⇒ 对" | 5 个单元，Fable 为主 | ✓ 模板 M3（赢家诅咒是其中一种） |
| M4 | **结论可追溯**：答案来自自己最新的分析，宣布的方法被执行 | "我说了要做 ⇒ 我做了" | GPT-6 T03b 116T；Fable 2 例（其中 1 例被错 key 掩盖） | ✗ 做成过程指标 |
| M5 | 对**二手信息**校准信任，测量优先 | "文档或前人设计是对的" | 3 个单元 + haiku ×2 | 以 `B_prior` 路由出现在 M1、M6 |
| M6 | **参照点不是零点** | "基线在渐近线上 / 下限是出版常数" | 仅 1 例 | ✓ 模板 M6 |

**为什么 M4 不出成题。** M4 是过程属性：同一个错误答案可以来自"没做"或"做错"。把它做成考点，判分就要读轨迹，这就需要人或者 LLM 来判，违背了"正确性来自构造"。可行的做法是把它当成报告字段：`answers.json` 里每个数字都必须能在某个 tool 输出里以容差匹配到，未追溯比例单独报告，不计入正确率。

**为什么"被违背的假设 × 捷径"是正确的考点单位。** v3/v4 的障碍模板 O1–O17 描述的是作者打算走的推导，实测不咬人。实测会咬人的，大多数（M4 除外）是模型走了一条**在另一个世界里成立**的捷径。这个结构正好能被 v5 的 B 证书度量：捷径离真值的距离除以参考方法的精度。

### 2.3 从"有意义"到"可机械判定"

"不能是无意义的点"是用户的明确要求。上面三条标准需要人判断，所以要把它们尽量落成可重复的检查。下表列出四道检查，但目前只有一道是通用代码：

| 检查 | 排除的是哪种"无意义" | 证据 | 目前状态 |
|---|---|---|---|
| 三栏分类（真实 / 精度边缘 / 伪影） | 精度边缘：在 2T 内、没有 rival 可归因的失分，只是在考"运气好不好" | 本次错误分析：25 个单元里剔掉 13 个 | 人工读轨迹；计划交给 LLM 分类、代码做可归因性（§4.4） |
| 路由阶数检验：把括号减半，看偏差缩小倍数 p | 捷径其实是另一种合法插值（与参考同阶），分不开 | M1 第一版几乎全部卡在 B≈1；改后局部二次和割线移到 `valid` | 代码，但只用于 M1 |
| 可执行性检查 | agent 根本走不到的捷径（lab 不卖那个点） | `R7:plugin` 被删 | 人读后手工删除；需要通用化 |
| 红队路由有效性检验 | 红队路由在该世界近似成立：此时"做了未检验的假设"和"做对了"分不开 | search T1 被杀题里 53% 的红队路由落在 T 内 | **尚未实现** |

### 2.4 能不能量产：能，但要按签名计数

原型的具体结果见 §4。这里只说对目标 1 的含义。
- **M1、M6 的难度由卡的物理常数驱动**（驱动常数 100% 是机制常数），不是换皮。但两者各有局限：
  - M1 在 T2 下只出了 9 题，量还不够；
  - M6 的 98 题里有 72 题绑定在"背出版常数当下限"（B_prior）上，驱动集中在 K3、K1 的下限 E 上。这是真考点，但很单一。
- **M2、M3 的难度主要由统计常数驱动**（86%、88%），比如噪声和配方离散。换卡只换了故事，考的是同一个统计点：跨卡坍缩覆盖 M2 的 82/99 题、M3 的 97/110 题。
- 因此量产配额应当按**考点签名**分配：(卡, 模板, 绑定对手族, 驱动类或机制常数, ⌊log2 B⌋)。M2/M3 各留少量代表题；增量应当来自新的 mechanism-driven 模板，而不是在现有 M6 上加量。

### 2.5 中档模型：怎么测"因为什么失败"

**现有证据很薄。** 只有 4 个 run：
- haiku-4.5 两次，分别得 0.12 和 0.43，出现编造数据点、扫描没越过最优点就下结论、文档锚定；
- gpt-5.5 一次，得 0.86，失败在 PARTIAL_CORNER，与 Fable ws3 同机制、同 rival；
- sonnet-4.6 一次，harness 活锁，中止。

由此形成的**假说**是：中档模型大多断在 L0（执行纪律：不编造、先括住再下结论、能收尾），前沿模型断在 L1（统计卫生，M3）到 L2（有效域推理，M1/M2/M6）。

**建议的实验设计**（6 个模型：前沿 gpt-6-astra、claude-fable-5-1；中档 gpt-5.5、claude-sonnet-5、claude-haiku-4-5、gemini-3.x-flash）：

1. **同一机制的两层题**：M1 的 T1 题只考"是否意识到上下文变了"，T2 题还考"是否意识到斜率也变了"。两层来自同一个模板、同一张卡，只差红队路由是否计分。
2. **提示阶梯**，沿用 v3 的 H0/H1/H2 约定，但改成按被违背的假设来写：
   - H0：原题；
   - H1：点名有风险的假设（例如"笔记本的上下文与生产不同"），不说怎么处理；
   - H2：给出参考方法（例如"在生产上下文里买两点做括号插值"）。
   这样可以把失败分成三种：H0 错、H1 对，说明是"没意识到"（M 类机制）；H1 错、H2 对，说明是"意识到但不会做"；H2 也错，说明是执行纪律问题（L0）。
3. **每格 ≥ 3 次运行**，报失败率及其区间。
4. **L0 过程指标单独计量**：编造数据点（答案或报告里的数不在任何 tool 输出里）、提前收尾、预算崩溃。它们不计入题目难度，否则中档模型的失败会全被 L0 吃掉，看不到 L1/L2 的差别。

**为什么这样设计。** 用户想知道"因为什么失败"，而单看 H0 的分数，"不会"和"没想到"混在一起。09-24 反馈里"提示后仍失败，所以不是缺知识"的结论只有 n=1，正是因为没有这个对照。两层题加提示阶梯是一个 2×3 的因子设计，它能直接回答"中档和前沿的差距是在 L0、L1 还是 L2"。

**要检验的预测**（写在实验之前，便于证伪）：
- P1：中档模型在 H0 的 T1 题上失败率明显高于前沿，并且主要在 H1 被救回（没意识到）或 H2 也救不回（L0）；
- P2：前沿模型在 T1 上接近全对、在 T2 上有可观的失败率，并且在 H1 被救回；
- P3：M2/M3 的失败率在同一签名的不同卡之间没有显著差别，这是换皮假说的直接检验。

如果 P2 不成立，也就是前沿在 T2 上也全对，就说明红队路由只是作者想象中的捷径，模型根本不走。这时应当降低 M1 的配额，而不是继续加难。

## 3. 目标 2：从 L1 到真实领域

### 3.1 为什么需要 L1.5

用户的判断是对的：L2（真实领域）需要 domain knowledge 来保证题目正确，而这恰恰是"脱离专家"要避免的。但只做 L1（纯虚拟世界）又有两个问题：
- 考察的能力可能与真实研究脱节；
- 模型可以把虚拟世界当成一道编程题：v2 形式化估计量 27/27 被打穿，就是这个原因。

L1.5 的定义是：**机制是真的，常数和组合是虚拟的，不宣称预测真实训练。**
- **世界的物理**取自已发表、有验证域的经验律，本原型用的是 Multi-Power Law。
- **常数**取反事实值，让"背出来的先验"失效，同时让"会测量"仍然有效。
- **真值**由模拟器按构造给出，所以不需要专家。
- **需要的领域知识是真的**：知道退火重要、知道稳定边、知道 progressive sharpening。但知道这些只能帮模型选对实验，不能直接给出答案。

| 层级 | 世界 | 真值来源 | 考什么 | 主要风险 |
|---|---|---|---|---|
| L1 | 纯虚拟（ScaleLab v3–v5） | 构造 | 具体统计与推理能力 | 退化成编程题；与真实研究脱节 |
| **L1.5** | 真实机制 + 反事实常数 + 声明验证域 | 构造 | 测量、建模、设计实验、验证 | 律在验证域外的漏洞；作者扩展的真实性 |
| L2 | 真实训练 | 真实运行（贵、噪声大） | 全部 | 真值需要专家或大量算力 |

### 3.2 原型结果（`proto_goal2/`）

世界是 MPL 加三处作者设计的扩展：稳定边、边附近效率损失、平台噪声项。设三类世界：
- F：忠实，常数取在文献常见范围；
- C：反事实常数，文档 LR 正好落在浪费带里，而且长衰减最优；
- L：晚发不稳定，稳定边在 0.35–0.5T 之后收缩，短跑看不到。

评分 s = (L_base − L_sub)/(L_base − L_opt)，不截断，所以比锚点好就 >1。

| 发现 | 数字 | 对目标 2 的含义 |
|---|---|---|
| F1 反事实常数分开了"背诵"与"测量" | 背 WSD 策略 F 0.80 → C −0.83；测量建模策略 0.95 → 0.96 | L1.5 的核心杠杆成立；可以用"背诵策略 F→C 的下降"作为世界的合格指标 |
| F2 作者式 key 会压低天花板 | C 世界作者式网格中位 0.44，测量建模 0.96 | 锚点必须是真世界里的数值最优，不能是出题人某个流程的输出 |
| F3 单调域里"不封顶"只是形式上的 | OPT_strong 最多比锚点高 0.0001 | 低维单调设计空间里，锚点就是物理最优，s>1 的空间几乎为零 |
| F4 律在验证域外给出荒谬奖励 | 叠加锯齿后 12/12 个世界 s=38–443。幅度 0.5%–10% 的锯齿扫描中，有 120 个点 s>1.05 且 L≥L0，其中 45 个（s=1.05–1.23，幅度 ≤2% 的 27 个、5–10% 的 18 个）漏过兄弟门 | 最大风险。兄弟律在域内本身就有中位 5–12%、最多约 49% gap 的分歧，门阈值不能低于这个噪声 |
| F5 两种修法 | 悲观评分 s_pess=min(s, s_sib) 让漏洞归零，但 cosine 类诚实策略中位被扣 0.16。限制在验证域内按构造没有这个代价（未单独实测） | 评分限制在验证域内，悲观评分只用于审计 |
| F6 植入的 builder bug 在域内完全不可见 | `|drop|` bug 在单调 schedule 上数值不变，兄弟律拟合逐位相同（4/4） | 正确性检查不能只在验证域里做，必须有会走出验证域的红队 |
| F7 L 世界的失败链很清楚 | 短程网格灾难 7/8；拟合不验证 4/8；加全长 pilot 验证（P4v，最多 2 次）1/8；主动晚期探边（P6）0/8，中位 0.89 | 存在一道必须**主动设计实验**才能解的题，并且有预算内的存在证明 |
| F8 模型族选择本身是能力 | 拟合错误的模型族，F/C 中位从 0.95/0.96 掉到 0.65/0.68 | 题面不能暴露律的函数形式，否则退化成拟合题 |

### 3.3 "创新不以 oracle 为天花板"：能做到什么，做不到什么

这是用户明确提出的要求，也是原型里最需要说清楚的地方。

**评分层面可以做到。** 按真世界结果评分、不和作者答案比对、s 不截断，就没有人为天花板。F2 说明这一点很重要：如果以作者流程的输出当 key，测量建模策略的真实优势会被截断一半以上。

**但有效天花板是律的验证域。** 天花板有两层。
- 第一层：在低维、单调的设计空间里，数值最优就是物理最优（F3），s>1 的空间本来就不存在。
- 第二层：想要实质性的开放，设计空间里必须有锚点搜不到的结构，比如多旋钮耦合（LR × batch × 数据配比）或组合式设计。但这些恰好是被移植的律**没有验证过**的区域。在那里，律给出的高分可能是律的漏洞，而不是真创新（F4）。

所以建议的规则是：
1. **评分只在验证域内做**；
2. **s>1 的提交一律打标记**，用悲观集成评分做第一道审计；
3. **超出验证域、又声称有改进的设计，交给 L2 审计**，也就是在真实的小规模训练上复现。

这就是 L1.5 与 L2 的接口：L2 不负责给每道题判分，只负责审计"律无法判断的创新"。审计量很小，因为只有 s>1 且被标记的提交才需要。

**为什么这样做。** 另一种做法是扩大律的适用范围，比如用多个律拼接。但 F6 说明，即使在一个律内部，作者自己植入的 bug 在验证域内都完全不可见。再加复杂度，正确性就无法保证。宁可承认"开放性以律的有效域为界"，把超出部分交给真实运行。

### 3.4 L1.5 世界的设计规则（从原型直接推出）

| 规则 | 依据 |
|---|---|
| R1 锚点 = 真世界的数值最优，不是出题人流程的输出 | F2 |
| R2 每个移植世界都声明验证域；评分限制在域内，域外只审计 | F4、F5 |
| R3 红队优化器是必备闸门，并且必须能走出验证域 | F4、F6 |
| R4 用同域一致的律集合加悲观分数，给 s>1 的提交打标记 | F5 |
| R5 物理下界（L ≥ L0）是廉价的第二道闸门，但只能抓大漏洞 | F4 |
| R6 难题必须附一个预算内可解的存在证明策略 | F7：否则无法区分"难"和"错" |
| R7 题面不暴露律的函数形式 | F8 |
| R8 反事实常数要让背诵失效、测量有效；用背诵策略 F→C 的下降量作为合格指标 | F1 |

### 3.5 下一批 L1.5 机制的选择标准

不建议立刻铺开很多律。每个新律都要满足三点：
- 有一个兄弟律可以做集成门（MPL 的兄弟是 Tissue 等人的退火律）；
- 有明确的验证域；
- 至少有一个"只在没观测过的区域出现"的现象，这是 L 世界那类设计实验题的来源。

目标 3 原型里的 5 张机制卡（计算量饱和幂律、LR 盆地、数据重复衰减、pass@k、临界 batch）都是 L1 版本。把它们升级到 L1.5 时，应当按这三条逐个检查，而不是全部升级。

## 4. 目标 3：自动出题 loop

### 4.1 原型做了什么（`proto_goal3/`）

把目标 1 的机制编译成 4 个"被违背假设"（AV）模板：M1 上下文迁移、M2 删失单元、M3 赢家诅咒、M6 下限比例。在 5 张机制卡上实例化，得到 18 个有效格（两张没有下限的卡不做 M6）。每道题都要过 v5 证书的 10 道门（G0–G9），其中 G9 是红队。

三种 proposer 对比：
- **oneshot**：每次独立从先验抽世界和设计；
- **loop**：读首个失败门的诊断，按规则改设计；
- **search**：把门当廉价 oracle，在每个世界里爬山。

| proposer | 认证 | 有 ≥1 题的格 /18 | 每 100 次评估的认证数 |
|---|---|---|---|
| oneshot | 28/720 | 7 | 3.9 |
| loop | 37/720 | 10 | 5.1 |
| search T2 | 316/864 世界（clean 257） | 15 | 0.9；首次认证所需探针中位 18 |
| search T1（不计红队） | 547/864 世界 | 18 | — |

按单位评估算，search 效率最低，因为它找到认证后还继续找更好的设计。它的价值在于两点：
- **覆盖面**：15/18 格，oneshot 只有 7/18；
- **不育判断可以检验**：search 失败的世界，其不育主要由世界常数决定。在 9/18 格里，AUC 能指出一个强预测常数；其余 4 格没有单一强预测常数，5 格因少数类太少没有计算。

### 4.2 loop 自身的错误：本原型最重要的产出

出题 loop 的每个角色都会犯错，而只有一部分能被 loop 自身的证据暴露。

| 错误 | 怎么暴露的 | 规模 | 修法 |
|---|---|---|---|
| 修复规则写错 | 统计每条规则"下一步是否推进到更靠后的门" | M1 买运行 45 次推进 7%；M2 让配置更旧 49 次推进 8%，另有 13 次空操作；M6 调低起点 4 次推进 0% | 规则是作者对"难度从哪来"的假设，必须像门一样实测。最常见的误诊是把世界受限当成噪声受限 |
| 数值捷径其实是合法插值 | M1 第一版几乎全部 B≈1 | M1 整个模板 | 路由阶数检验 |
| 捷径在 lab 里不可执行 | 人读路由定义 | 1 条路由 | 可执行性检查 |
| **题面泄漏答案** | **把认证题渲染成 agent 看到的样子** | 此前认证的 192 道 T2 题里 39 道（20%），10 道门全部漏掉 | `shown` 登记 + G7 要求每个**已登记**的题面数字 ≥ 1T。未登记的数字查不到，例如 M6 目前一个都没登记。下一步做数字登记完备性门 |
| 两层证书的世界不同步 | 配对比较出现不可能的结果 | 所有 T1/T2 比较 | 世界流与提议流分开；断言配对 |

几点说明：
- **泄漏是最值得警惕的一类。** 门只能检查作者登记过的东西。M3 在笔记本恰好选中在位配方时，题面公布的在位值就是答案；M2 的删失阈值 c 可能紧挨中位数。这两类都是"一眼就能看到"，但 10 道门都看不到。
- **修复规则写错不会报错**，只会表现为 loop 效率低。如果不看推进率，就会误以为是世界不育。loop 只比 oneshot 好一点（5.1 对 3.9），规则写错是一个说得通的原因，但本原型没有做"修好规则后重跑"的对照。

### 4.3 红队、两层证书与可归因性

**只对作者想到的对手认证，假阳性率很高。**
- oneshot + loop 里不计红队即可认证的 173 题中，62% 会被红队杀掉。
- 按模板看，T1 最优设计的红队杀伤率：M1 98%、M2 90%、M3 57%、M6 20%。

**但红队路由本身也需要检验。** 模拟一个用红队路由作答的 agent，看它的错答能否被基础路由库解释。376 道被杀题分成三类：
- 198 道（53%）判对，也就是红队路由在该世界落在 T 内；
- 177 道（47%）只有红队库能归因；
- 1 道基础库就能归因。

这有两层含义：
1. **隐藏路由不只会造成假认证，还会造成"无法解释的错答"。** 所以路由库必须覆盖模型实际会走的路，这只能靠模型实跑后的错误分析来补。
2. **超过一半的"杀伤"本身可能是合法捷径。** 例如 M2 的 unit_slope（假设各单元平移相同）在平移几乎相同的世界里近似成立。正确做法类似路由阶数检验：对每条红队路由，判断它在该世界是合法捷径（移到 valid）还是错误假设（计分）。这一步还没实现。

**两层证书本身是有用的难度梯度。** M1 在 T1 下 5 张卡都能出题；在 T2 下基本只有 K2 能出（8/48 个世界），K4 只出 1/48，其余三张卡为 0。
- T1 题考"是否意识到上下文变了"；
- T2 题考"是否意识到连斜率也变了"。

这正是 §2.5 实验设计里的两层题。

### 4.4 LLM 应该放在哪里

| 角色 | 本原型 | 接入模型后 | 理由 |
|---|---|---|---|
| proposer（设计） | 代码搜索 | **保持代码** | 门评估约 5–6 ms，搜索在大多数世界里就能给出答案（配对检验漏检约 5%）；LLM 在这一层没有增量 |
| proposer（新模板、新卡、新红队路由） | 人写 | **LLM** | 真正的创造性工作；输入是模型实跑的错误分析 |
| 门 / 真值 | 代码 | **必须保持代码** | 真值外包给世界模拟器，这是无专家正确性的来源 |
| 红队 | 手写路由库 | LLM 提议，代码执行并做有效性检验 | 手写库有盲区；LLM 提议的路由必须先过阶数、可执行性、有效性三道检验才能计分 |
| 错误分析 | 人（主会话 + 子代理） | LLM 做三栏分类，代码做可归因性 | 可归因性是机械的（错答离哪条路由 < T）；三栏分类需要读轨迹 |
| 渲染审计 | `render.py` + 人读 | LLM 读题面列出每个数字，代码核对登记 | 只有这个角色能看到作者没登记的东西 |
| 策展 | 代码 | 保持代码 | 签名、驱动分析、跨卡坍缩都是机械的 |

**为什么不让 LLM 当设计层的 proposer。** 用户说的"agent 系统通过 loop 完善迭代"，最直觉的实现是让 LLM 读门的反馈、改设计。原型说明这一层用代码搜索更好：门很便宜，搜索能穷尽，而且搜索失败本身就是"世界不育"的证据。LLM 在这一层只会重复 v1 规则的错误，例如把世界受限误判成噪声受限，而且更难审计。LLM 的比较优势在**提出新假设**：新的被违背假设、新的捷径、新的机制卡。这一层的产出没有廉价 oracle 可以替代，但每个产出都能被代码检验。

### 4.5 让 loop 自己可审计

原型最大的教训是：出题人（包括我）会犯错，而且这些错误都不是事先想到的，而是在看 loop 的输出（推进率统计、渲染出来的题面、配对比较）时才发现的。其中泄漏和不可执行两类是人读输出才看到的，门没有报。所以正式 pipeline 里，每个角色都需要一个能证伪它的检查，并且要把"人读输出"这一步也变成固定环节：

| 角色 | 它可能犯的错 | 机械检查 |
|---|---|---|
| 门 | 门本身有 bug，放过坏题 | 变异测试：故意植入缺陷，断言门必须失败（v4 的 `test_g17.py` 模式） |
| 修复规则 / proposer | 规则误诊 | 推进率统计；空操作检测（同一设计不重复评估） |
| 路由库 | 路由其实是合法方法 / 不可执行 / 在该世界恰好成立 | 阶数检验、可执行性检查、有效性检验 |
| 题面 | 泄漏答案 | 数字登记完备性：题面上每个数字都必须已登记，未登记即拒收 |
| 世界采样 | T1/T2 世界不同步 | 独立随机流 + 配对断言 |
| 策展 | 换皮当多样性 | 按签名计数；跨卡坍缩统计 |
| key 生成器 | 没读声明为真的文件（v2 D 族） | 逐个文件消融：文件不影响 key 却被声明为"约束"，就报警 |
| 问句 | 估计对象有歧义（v2 S 族） | 每个问句至少写两种字面读法，分别算值；差 > T 就必须改写 |

## 5. 三个目标如何合成一个 pipeline

```
                   ┌────────────────────────────────────────────────────────────────┐
                   ▼                                                                │
  ① 模型实跑（6 模型 × ≥3 次 × 两层题 × 提示阶梯）                                         │
                   │                                                                │
  ② 轨迹错误分析：真实机制 / 精度边缘 / 伪影 三栏      ──伪影──▶ 修门（§4.5 表）           │
                   │真实机制                                                         │
  ③ 可归因性分流（错答离哪条已登记路由 < T）                                              │
       ├─ 能归因 ──▶ 已知考点，计入失败率                                                  │
       ├─ 是已知假设的变体 ──▶ LLM 提议新红队路由 ──阶数/可执行/有效性检验──▶ 路由库            │
       └─ 新机制 ──▶ LLM 提议新 AV 模板（被违背假设 + 捷径 + 参考方法）                        │
                   │                                                                │
  ④ 编译：卡 × 模板 × 世界搜索（代码，门当 oracle）                                          │
                   │                                                                │
  ⑤ 门 G0–G9 + 红队 + 渲染审计（数字登记完备性）                                            │
                   │                                                                │
  ⑥ 策展：按签名配额；跨卡坍缩只留代表；现实性标记                                              │
                   │                                                                │
  ⑦ L1.5 世界：同一套模板在移植世界上实例化；s>1 标记并审计；域外创新交 L2                         │
                   └────────────────────────────────────────────────────────────────┘
```

**"不可归因错答率"本身就是路由库完备性的度量。** 这个比例下降，说明 pipeline 在收敛；比例持续不降，说明模型在走我们没想到的路，而这正是新机制的来源。

这个闭环回答了用户目标 1 里的"能否通过错误分析抽象出一个机制去量产题目"。答案是能，但有两个前提：
- 错误分析必须先剔除伪影；
- 量产必须按签名计数，否则一半是换皮。

## 9. 风险与局限

- **零模型数据。** 本文所有关于难度的结论都只相对于脚本化捷径成立。最大的风险是模型根本不走我们登记的捷径（v4 的教训）。§6 把实跑放在第一位，就是为了尽早暴露这个风险。
- **红队库是手写的**，有两个方向相反的偏差：
  - 模型实际会走但没登记的捷径不会计入 B，所以 T2 认证数偏乐观；
  - 53% 的被杀题上，红队路由落在 T 内。有效性检验实现后，其中一部分路由会移到 `valid`，被杀题会恢复认证。
- **现实性。** 19% 的认证题要靠夸张的笔记本噪声（≥ 4 倍）或预算（n ≥ 300）才能出题。正式集应当只用 clean 题。
- **可育性是下界。** 搜索是启发式的，配对检验测得漏检率约 5%。
- **目标 2 的世界扩展是作者设计的**：稳定边、效率损失、晚发收缩都只有定性依据（edge-of-stability、progressive sharpening），没有被同一篇论文定量验证。这正是 L1.5 的定位，不宣称预测真实训练。
- **L2 审计还没有设计。** "域外创新交给真实运行复现"需要算力和一个小规模训练框架，本文只给出接口，没有给出实现。
- **中档模型的分层是假说，n=4。**
- **错误分析的覆盖面。** 12 个真实单元来自两个前沿模型的几十次运行，M6 只有 1 例。新的实跑很可能会发现不在 M1–M6 里的机制，这是 §5 闭环要处理的。
